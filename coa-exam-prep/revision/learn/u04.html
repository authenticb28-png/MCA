Unit 4 · Number Systems & Two's Complement

Is unit ki kahani: Unit 3 mein humne adder banaya jo bits jodta hai. Par bits ka matlab kya hai? 1011 ek number hai, par kaunsa: 11 ya −5? Ye unit sikhata hai ki numbers binary aur hex mein kaise likhte hain, negative numbers kaise likhte hain (sign-magnitude, 1's complement, 2's complement), chhote number ko bade register mein kaise daalte hain (sign extension), add/subtract kaise hota hai, aur kab answer box mein fit nahi hota (overflow). Agla unit (5) batayega ki ye bits yaad kaise rakhe jaate hain (latches, flip-flops).

4.1 Number systems: binary, decimal, hex conversions

Pehle socho: Tum roz decimal use karte ho kyunki insaan ke 10 ungliyan hain: digits 0 se 9. Computer ke andar har wire pe sirf do haalat hain: current hai (1) ya nahi hai (0), jaise switch ON/OFF. Isliye computer base 2 (binary) mein ginta hai. Lambi binary strings padhna mushkil hai (1011 0101 1100 0011), isliye insaan unhe chhota karke hex (base 16) mein likhte hain. Teeno systems ek hi idea pe chalte hain: har position ki ek "keemat" (weight) hoti hai.
Definition: A positional number system with base (radix) r represents a value as the sum of each digit multiplied by r raised to the power of its position, positions being numbered 0, 1, 2 from the right. Binary uses base 2 (digits 0, 1), decimal base 10 (0 to 9) and hexadecimal base 16 (0 to 9, A to F).
Mushkil shabd, aasaan matlab:
base / radix
Kitne alag digits hain, aur har position pichhli se kitni guna keemti hai. Decimal: base 10. Binary: base 2. Hex: base 16.
place value / weight
Kisi position ki keemat. Decimal mein right se: 1, 10, 100, 1000. Binary mein: 1, 2, 4, 8, 16, 32 (har baar ×2).
bit
Ek binary digit, 0 ya 1. "101" mein 3 bits hain.
nibble / byte
4 bits = nibble (ek hex digit). 8 bits = byte (do hex digits). 1011 0101 ek byte hai.
MSB / LSB
Most Significant Bit = sabse left wala bit (sabse bada weight). Least Significant Bit = sabse right wala (weight 1). 101101 mein MSB ka weight 32, LSB ka 1.
subscript ₂ ₁₀ ₁₆, prefix 0x
Number kis base mein hai ye batata hai. 101₂ = five, 101₁₀ = one hundred one. 0x2A ka matlab hex 2A.
remainder
Divide karne ke baad jo bachta hai. 45 ÷ 2 = 22, remainder 1 (kyunki 22 × 2 = 44, 45 − 44 = 1).
Kaise kaam karta hai:
  1. Decimal se shuru (place value): 237 ka matlab hai 2 sau + 3 das + 7 ek = 2×100 + 3×10 + 7×1 = 200 + 30 + 7 = 237. Har position pichhli se 10 guna keemti hai.
  2. Binary mein bilkul wahi, bas ×2: weights right se 1, 2, 4, 8, 16, 32, 64, 128. 101101₂ = 1×32 + 0×16 + 1×8 + 1×4 + 0×2 + 1×1 = 32 + 8 + 4 + 1 = 45. Rule: jahan bit 1 hai, us position ka weight jodo; 0 wali positions chhod do.
  3. Decimal → binary, method 1 (baar baar 2 se divide): number ko 2 se divide karo, remainder (0 ya 1) likho, quotient ko phir 2 se divide karo, jab tak quotient 0 na ho jaaye. Phir remainders ko neeche se upar padho. 45 ke liye:
    DivisionQuotientRemainder
    45 ÷ 2221 (LSB)
    22 ÷ 2110
    11 ÷ 251
    5 ÷ 221
    2 ÷ 210
    1 ÷ 201 (MSB)
    Neeche se upar: 1 0 1 1 0 1 → 101101. Check: 32 + 8 + 4 + 1 = 45. Ye kyun kaam karta hai: 237 ÷ 10 karo to remainder 7 aata hai, jo 237 ka last digit hai. Waise hi ÷ 2 ka remainder binary ka last bit (LSB) hai. Isliye pehla remainder sabse right mein jaata hai.
  4. Decimal → binary, method 2 (powers of 2 ghatao): sabse bada power of 2 dhoondo jo number se chhota ya barabar ho, use ghatao, us position pe 1 likho; baaki se phir yahi karo. 45: 32 ≤ 45 → 45 − 32 = 13; 16 > 13 → 0; 8 ≤ 13 → 13 − 8 = 5; 4 ≤ 5 → 5 − 4 = 1; 2 > 1 → 0; 1 ≤ 1 → 1 − 1 = 0. Positions 32, 16, 8, 4, 2, 1 → 1 0 1 1 0 1 = 101101. Same answer.
  5. Binary → hex (4 ke group): 16 = 2⁴, isliye ek hex digit = exactly 4 bits. Bits ko right se 4-4 ke group mein todo, har group ko hex digit mein badlo. 10110101 → 1011 | 0101 → B | 5 → 0xB5. Agar bits 4 ke multiple nahi hain to left mein 0 jodo: 1101101 (7 bits) → 0110 | 1101 → 0x6D.
  6. Hex → binary: ulta karo, har hex digit ko 4 bits mein likho. 0x2A → 2 = 0010, A = 1010 → 0010 1010.
  7. Hex → decimal: hex weights right se 1, 16, 256, 4096. 0xB5 = 11×16 + 5×1 = 176 + 5 = 181. 0x3E8 = 3×256 + 14×16 + 8×1 = 768 + 224 + 8 = 1000. 0x3C = 3×16 + 12 = 48 + 12 = 60.
  8. Decimal → hex: 16 se divide karo, remainders neeche se upar. 181 ÷ 16 = 11 remainder 5 (11 × 16 = 176); 11 ÷ 16 = 0 remainder 11 = B → B5.
  9. Octal (base 8): 8 = 2³, isliye ek octal digit = 3 bits. (1217)₈ → 001 010 001 111 → ab 4 ke group banao right se: 0010 1000 1111 → 0x28F = 2×256 + 8×16 + 15 = 512 + 128 + 15 = 655.
  10. Fraction (binary point ke baad): weights 1/2, 1/4, 1/8 (0.5, 0.25, 0.125). 0.101₂ = 0.5 + 0 + 0.125 = 0.625. Ulta (0.625 → binary): ×2 karte jao, integer part likho: 0.625×2 = 1.25 → 1; 0.25×2 = 0.5 → 0; 0.5×2 = 1.0 → 1 → 0.101 (yahan upar se neeche padho).
  11. n bits mein kitna aata hai (unsigned): 0 se 2ⁿ − 1. 4 bits: 0 se 15. 8 bits: 0 se 255. 1000 tak ke liye kitne bits? 2⁹ = 512 (kam), 2¹⁰ = 1024 (kaafi) → 10 bits.

Powers of 2 ratt lo: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024. 2¹⁰ = 1024 ≈ 1 K, 2²⁰ ≈ 1 M, 2³⁰ ≈ 1 G.

Diagram kaise padhein: Upar wali row mein bits 1 0 1 1 0 1 hain. Beech wali row mein har bit ka weight (32, 16, 8, 4, 2, 1). Neeche wali row "contribution" hai: bit 1 hai to weight aata hai, bit 0 hai to 0. Highlighted columns (32, 8, 4, 1) jodo: 32 + 8 + 4 + 1 = 45.

Formula: Value = Σ (digit × baseposition), position 0 = rightmost.
Unsigned n bits: 0 to 2ⁿ − 1. Bits needed for value N: smallest n with 2ⁿ − 1 ≥ N.
1 hex digit = 4 bits, 1 octal digit = 3 bits.
Solved example 1 (exam favourite, 5 marks):

Convert (a) 157₁₀ to binary, octal and hex, (b) 0x3E8 to decimal, (c) 10110.011₂ to decimal. Show working.

  1. (a) Repeated ÷2: 157 ÷ 2 = 78 r 1; 78 ÷ 2 = 39 r 0; 39 ÷ 2 = 19 r 1; 19 ÷ 2 = 9 r 1; 9 ÷ 2 = 4 r 1; 4 ÷ 2 = 2 r 0; 2 ÷ 2 = 1 r 0; 1 ÷ 2 = 0 r 1.
  2. Remainders neeche se upar: 1 0 0 1 1 1 0 1 → 157₁₀ = 1001 1101₂. Check: 128 + 16 + 8 + 4 + 1 = 157.
  3. Octal: right se 3 ke group: 10 | 011 | 101 → 010 | 011 | 101 → 2 | 3 | 5 → 235₈. Check: 2×64 + 3×8 + 5 = 128 + 24 + 5 = 157.
  4. Hex: right se 4 ke group: 1001 | 1101 → 9 | D → 0x9D. Check: 9×16 + 13 = 144 + 13 = 157.
  5. (b) 0x3E8 = 3×256 + 14×16 + 8×1 = 768 + 224 + 8 = 1000.
  6. (c) 10110.011: left part 16 + 0 + 4 + 2 + 0 = 22; right part 0×0.5 + 1×0.25 + 1×0.125 = 0.375 → 22.375.

Answer: 157 = 1001 1101₂ = 235₈ = 0x9D; 0x3E8 = 1000; 10110.011₂ = 22.375.

Solved example 2 (MCQ / NAT type):

(i) Convert 181₁₀ to hex. (ii) How many bits are needed to store unsigned numbers up to 1000?

  1. (i) 181 ÷ 16 = 11 remainder 5 (16 × 11 = 176, 181 − 176 = 5). 11 ÷ 16 = 0 remainder 11 = B.
  2. Neeche se upar: B, 5 → 0xB5. Check via binary: 1011 0101 = 128 + 32 + 16 + 4 + 1 = 181.
  3. (ii) 9 bits max = 2⁹ − 1 = 511 < 1000 (kam). 10 bits max = 2¹⁰ − 1 = 1023 ≥ 1000 (kaafi).

Answer: (i) 0xB5 (ii) 10 bits.

Galti mat karna: (1) Remainders upar se neeche padhna: 42 ke remainders upar se neeche 0 1 0 1 0 1 hain; aise padhoge to 010101 = 21 aayega (galat). Sahi: neeche se upar = 101010 = 42. (2) Hex group left se banana: 1101101 ko 1101 | 101 karna galat hai, group hamesha right se. (3) 0x10 ko "das" samajhna: 0x10 = 1×16 + 0 = 16.

Trick: 4 bits ke weights "8 4 2 1" ratt lo. Koi bhi nibble 2 second mein: 1011 = 8 + 2 + 1 = 11 = B.

Ek line mein: Har position ka weight base ki power hai; binary → decimal = 1 wale weights jodo, decimal → binary = ÷2 aur remainders neeche se upar, binary ↔ hex = right se 4-4 bits ka group.

4.2 Signed representations overview

Pehle socho: Kaagaz pe −5 likhne ke liye hum "−" sign lagate hain. Par computer ke paas sirf 0 aur 1 hain, koi "−" nahi. To negative number kaise likhein? Teen ideas try kiye gaye: (1) ek bit ko sign bana do (sign-magnitude), (2) saare bits ulat do (1's complement), (3) ulat ke 1 jodo (2's complement). Pehle do mein problems hain, teesra jeet gaya. Teeno ko ek hi number pe dekhenge.
Definition: A signed number representation encodes both positive and negative integers using bits. In sign-magnitude the MSB is the sign (0 = +, 1 = −) and the remaining bits give the magnitude; in one's complement a negative number is formed by inverting every bit of the positive number; in two's complement it is formed by inverting every bit and adding 1.
Mushkil shabd, aasaan matlab:
sign bit
Sabse left wala bit (MSB). 0 = positive, 1 = negative. Teeno systems mein yahi rule hai.
magnitude
Sign ke bina size. −5 ka magnitude 5.
invert / complement
Har bit ulta karo: 0 → 1, 1 → 0. 0101 ka invert = 1010.
two zeros
Zero ke do alag patterns hona (+0 aur −0). Bekaar hai: ek pattern waste, aur "kya ye zero hai?" check karne ke liye do comparisons.
end-around carry
1's complement addition mein jo carry left se bahar nikle, use wapas right wale bit mein jodna padta hai. Extra kaam.
range
Sabse chhota se sabse bada number jo n bits mein likh sakte ho.
Kaise kaam karta hai (same number, teeno tarike, 4 bits):
  1. Pehle +5 likho: 0101 (teeno systems mein positive number same hota hai).
  2. Sign-magnitude −5: sirf sign bit 1 kar do, magnitude 101 waisa hi → 1101.
  3. 1's complement −5: 0101 ke saare bits ulto → 1010.
  4. 2's complement −5: 1010 mein 1 jodo → 1011.
  5. 8-bit mein ±18 (class slide): +18 = 0001 0010. Sign-magnitude −18 = 1001 0010. 1's complement −18 = 1110 1101. 2's complement −18 = 1110 1110.
  6. Two zeros problem: sign-magnitude mein 0000 (+0) aur 1000 (−0). 1's complement mein 0000 (+0) aur 1111 (−0). 2's complement mein sirf 0000 (1111 ka matlab −1 hai).
  7. Addition problem (sign-magnitude): 5 + (−3) seedha jodo: 0101 + 1011 = 1 0000 → 0000 = 0. Galat (answer 2 hona chahiye). Isliye sign-magnitude ko jodne se pehle signs compare karne wala alag circuit chahiye.
  8. Addition (1's complement): 5 + (−3) = 0101 + 1100 = 1 0001. Bahar nikla carry wapas jodo: 0001 + 1 = 0010 = 2. Sahi, par extra "end-around" step lagta hai.
  9. Addition (2's complement): 5 + (−3) = 0101 + 1101 = 1 0010 → carry chhod do → 0010 = 2. Seedha sahi. Isliye har CPU 2's complement use karta hai.

Formula: Sign-magnitude and 1's complement range: −(2ⁿ⁻¹ − 1) to +(2ⁿ⁻¹ − 1) (two zeros). 2's complement range: −2ⁿ⁻¹ to +(2ⁿ⁻¹ − 1) (one zero).
1's complement of x = (2ⁿ − 1) − x; 2's complement of x = 2ⁿ − x.
4 bits: S-M and 1's: −7 to +7; 2's: −8 to +7. 8 bits: S-M and 1's: −127 to +127; 2's: −128 to +127.
Solved example (exam 5 marks):

Represent −23 in 8-bit sign-magnitude, one's complement and two's complement. Compare the three representations.

  1. +23 binary: 23 = 16 + 4 + 2 + 1 → 0001 0111.
  2. Sign-magnitude: MSB 1, baaki magnitude 001 0111 → 1001 0111.
  3. One's complement: 0001 0111 ka har bit ulto → 1110 1000.
  4. Two's complement: 1110 1000 + 1 = 1110 1001. Check: −128 + 64 + 32 + 8 + 1 = −23.
  5. Comparison (likhne ka tareeka): "Sign-magnitude and one's complement both have two zeros (+0 and −0) and a symmetric range −127 to +127 in 8 bits. Sign-magnitude addition needs sign-comparison logic; one's complement needs an end-around carry. Two's complement has a single zero, range −128 to +127, and the same adder performs both addition and subtraction, so it is used in all modern CPUs. Sign-magnitude survives only as the sign bit of floating-point numbers."

Answer: S-M 1001 0111; 1's 1110 1000; 2's 1110 1001.

Galti mat karna: 1000 0000 ko 2's complement mein "−0" mat bolo. 2's complement mein ye −128 hai. "−0" sirf sign-magnitude (1000 0000) aur 1's complement (1111 1111) mein hota hai.

Trick: "S-M: sign flip. 1's: sab flip. 2's: sab flip + 1."

Ek line mein: Negative likhne ke teen tarike hain; sign-magnitude aur 1's complement mein do zero aur addition ki pareshani hai, 2's complement mein ek zero aur seedha addition, isliye wahi use hota hai.

4.3 Two's complement deep dive: negation and range

Pehle socho: Gaadi ka purana 3-digit odometer (km meter) socho, jo 000 pe hai. Use ek km peeche chalao to wo 999 dikhayega. To 3 digit ki duniya mein "999" ka matlab hi "−1" ho gaya: kyunki 999 + 1 = 1000, aur 3 digit mein 1000 ka "1" gir jaata hai, bachta hai 000. 2's complement bilkul yahi hai, binary odometer pe: 4-bit 0000 se ek peeche = 1111 = −1. Isliye addition apne aap sahi aata hai.
Definition: In n-bit two's complement, the MSB has weight −2ⁿ⁻¹ and every other bit has its normal positive weight. The negative of x is 2ⁿ − x, which is obtained by inverting all bits of x and adding 1. The range is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1.
Mushkil shabd, aasaan matlab:
wrap-around
Sabse bade pattern ke baad wapas sabse chhote pe aa jaana. 4-bit mein 1111 + 1 = 0000 (carry bahar gir jaata hai).
2ⁿ (modulus)
n bits mein total patterns. 4 bits: 2⁴ = 16 patterns (0000 se 1111). Wheel pe 16 jagah hain; 16 kadam chalo to wapas wahin.
negate
Number ka ulta sign wala version banana: +18 → −18, ya −18 → +18.
MSB ka negative weight
8-bit mein MSB ka weight +128 nahi, −128 hai. 1000 0001 = −128 + 1 = −127.
asymmetric range
Negative side ek number zyada: 4-bit mein −8 hai par +8 nahi.
Kaise kaam karta hai:
  1. Wheel idea: 4 bits ke 16 patterns ek ghadi ki tarah gol ghere mein lagao: 0000 upar, clockwise 0001, 0010 se 1111 tak. 1111 ke baad phir 0000. Har kadam = +1.
  2. 0000 se ek kadam ulta (anticlockwise) = 1111. To 1111 = −1. Do kadam ulta = 1110 = −2. Teen ulta = 1101 = −3. Negative numbers bas "zero se peeche" wale positions hain.
  3. Formula kyun −x = 2ⁿ − x: 16 kadam chalo to wapas wahin aate ho, isliye "3 kadam peeche" = "16 − 3 = 13 kadam aage". 13 = 1101. Dekho, upar humne −3 = 1101 hi paaya. To −x ka pattern = (2ⁿ − x) ka binary.
  4. Invert + 1 kyun kaam karta hai: x aur uska invert x' jodo to har column mein 1 + 0 = 1 aata hai: 0101 + 1010 = 1111 = 2ⁿ − 1 (koi carry nahi). Matlab x' = (2ⁿ − 1) − x. Ab 1 jodo: x' + 1 = 2ⁿ − x = −x. Bas, isliye invert karo, 1 jodo.
  5. Negation steps (8-bit, +18 → −18): (a) +18 = 0001 0010. (b) Invert: 1110 1101. (c) 1 jodo: 1110 1101 + 1 → right bit 1 + 1 = 10, likho 0 carry 1; agla bit 0 + 1 = 1, carry khatam → 1110 1110.
  6. Shortcut (copy till first 1): right se chalo, bits copy karte jao jab tak pehla 1 na mile (us 1 ko bhi copy karo), uske baad baaki saare bits ulto. +18 = 0001 0010: right ka 0 copy → 0; agla 1 (pehla 1) copy → 1; baaki 0001 00 ulto → 1110 11. Joda: 1110 1110. Same answer, addition ki zarurat nahi. Ek aur: +40 = 0010 1000 → right ke 000 copy, phir pehla 1 copy → "1000"; baaki 0010 ulto → 1101 → 1101 1000 = −40.
  7. Negative pattern ko padhna (method 1, weights): 1110 1110 = −128 + 64 + 32 + 0 + 8 + 4 + 2 + 0 = −128 + 110 = −18.
  8. Method 2 (wapas negate): MSB 1 hai to negative hai. Invert + 1 karo magnitude milega: 1110 1110 → 0001 0001 → +1 → 0001 0010 = 18. To value −18. (Negate dono taraf kaam karta hai.)
  9. Range nikalna, n = 4: 16 patterns. MSB = 0 wale 8 patterns: 0000 se 0111 = 0 se +7 (zero ne ek jagah le li, isliye positive sirf 7 tak). MSB = 1 wale 8 patterns: 1000 se 1111 = −8 se −1. Range −8 to +7. Formula: −2³ = −8 to 2³ − 1 = 7.
  10. Range, n = 8: −2⁷ = −128 to 2⁷ − 1 = +127. Sabse negative 1000 0000 = −128, sabse positive 0111 1111 = +127, −1 = 1111 1111. (16-bit: −32768 to +32767.)
  11. Sabse negative ka koi jodidaar nahi: −8 = 1000 ko negate karo: invert 0111, +1 → 1000. Wapas −8! Kyunki +8 4 bits mein fit hi nahi hota.

Diagram kaise padhein: Teen ghere hain. Beech wali ring mein bit pattern, andar ki taraf (halka) unsigned value, bahar signed (2's complement) value. 0000 sabse upar hai, clockwise chalo to +1 hota hai. 0111 (+7) ke baad 1000 (−8) aata hai; ye highlighted line signed overflow ki deewar hai. 1111 (−1) se ek aage 0000 (0): ye unsigned ka carry-out point hai (15 → 0). Trace: 1101 dhoondo, bahar likha hai −3, andar 13; 13 + 3 = 16 = 2⁴.

Formula: −x = x' + 1 = 2ⁿ − x  ·  Range = −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1  ·  MSB weight = −2ⁿ⁻¹
n = 4: −8 to 7 · n = 6: −32 to 31 · n = 8: −128 to 127 · n = 16: −32768 to 32767. All ones = −1.
Solved example 1 (class exit ticket):

Write −45 in 8-bit two's complement and verify.

  1. +45: 45 = 32 + 8 + 4 + 1 → 0010 1101.
  2. Invert: 1101 0010.
  3. +1: right bit 0 + 1 = 1, koi carry nahi → 1101 0011.
  4. Shortcut se check: 0010 1101 ka right bit hi pehla 1 hai, use copy karo; baaki 0010 110 ulto → 1101 001 → 1101 0011. Same.
  5. Verify weights se: −128 + 64 + 16 + 2 + 1 = −128 + 83 = −45.

Answer: −45 = 1101 0011.

Solved example 2 (MCQ/NAT type):

(i) 0xB7 as an 8-bit signed integer? (ii) Decimal value of 1011 0100 (8-bit two's complement)? (iii) Range of a 6-bit two's complement number? (iv) Show +18 + (−18) = 0.

  1. (i) 0xB7 = 1011 0111. MSB 1 → negative. Weights: −128 + 32 + 16 + 4 + 2 + 1 = −128 + 55 = −73. (Unsigned padho to 183.)
  2. (ii) 1011 0100 = −128 + 32 + 16 + 4 = −128 + 52 = −76.
  3. (iii) n = 6: −2⁵ = −32 to 2⁵ − 1 = 31 → −32 to +31.
  4. (iv) 0001 0010 + 1110 1110: bit 0: 0 + 0 = 0. Bit 1: 1 + 1 = 10 → 0, carry 1. Bits 2 se 7: har column mein ek 1 hai, plus aaya hua carry 1 = 10 → 0, carry 1. Result 1 0000 0000. 9th bit (carry) 8-bit box mein fit nahi, gir jaata hai → 0000 0000 = 0.

Answer: −73; −76; −32 to +31; sum = 0 (carry discarded).

Galti mat karna: (1) "+1" bhool jaana: sirf invert karoge to 1's complement banega, 2's nahi (−45 = 1101 0010 galat). (2) Range ko symmetric likhna (−127 to +127): ye sign-magnitude ka hai; 2's complement mein −128 to +127. (3) Shortcut mein left se copy shuru karna: copy hamesha right se.

Trick: "Odometer peeche chalao." −1 hamesha all ones (1111 1111). Range: "negative side pe ek extra, kyunki zero positive side pe baitha hai."

Ek line mein: 2's complement mein −x = invert + 1 = 2ⁿ − x, MSB ka weight −2ⁿ⁻¹ hai, aur range −2ⁿ⁻¹ se 2ⁿ⁻¹ − 1.

4.4 Sign extension

Pehle socho: Odometer wapas lo. 3-digit meter pe −1 = 999. Ab gaadi mein 6-digit meter lag gaya. −1 ab kya dikhega? 999999, na ki 000999 (wo to 999 km hai, positive!). Matlab chhote number ko bade box mein daalte waqt naye khaali digits ko "sign wale digit" se bharna padta hai. Binary mein bhi: 4-bit ya 16-bit number ko 8-bit ya 32-bit register mein daalna ho (MIPS mein 16-bit immediate ko 32-bit ALU tak), to naye upar wale bits mein MSB copy karo.
Definition: Sign extension increases the number of bits of a two's complement number without changing its value, by copying the sign bit (MSB) into every new higher-order bit. Zero extension fills the new bits with 0 and is correct only for unsigned numbers.
Mushkil shabd, aasaan matlab:
extend (widen)
Bits badhana: 4-bit → 8-bit, 16-bit → 32-bit.
sign bit
MSB. 1 = negative, 0 = positive (2's complement mein).
immediate
Instruction ke andar likha constant number. MIPS mein 16 bits ka hota hai, jaise addi $t0, $t0, −1 mein −1.
lb / lbu
MIPS "load byte" (signed, sign-extend karta hai) aur "load byte unsigned" (zero-extend karta hai).
Kaise kaam karta hai:
  1. Purane number ka MSB dekho.
  2. Naye jitne bits chahiye, sab mein wahi MSB likho, purane bits ko right mein waise hi rakho.
  3. +5 (4-bit) = 0101, MSB 0 → 0000 0101 (8-bit). Value 5 hi.
  4. −5 (4-bit) = 1011, MSB 1 → 1111 1011. Check: −128 + 64 + 32 + 16 + 8 + 2 + 1 = −128 + 123 = −5. Value same.
  5. Agar galti se 0 bhar diye: 0000 1011 = 8 + 2 + 1 = +11. Bilkul galat.
  6. Kyun copy karne se value nahi badalti: 4-bit mein MSB ka weight −8 tha. 8-bit mein bits 7 se 3 ab 1 1 1 1 1 hain: −128 + 64 + 32 + 16 + 8 = −8. Yaani naye saare 1s milke wahi −8 dete hain jo pehle akela MSB deta tha. Baaki bits (2 + 1 = 3) same → total −8 + 3 = −5.
  7. MIPS mein: addi, lw, sw, slti aur branch offsets ka 16-bit immediate sign-extend hota hai. 0xFFFB (−5) → 0xFFFFFFFB. 0x0004 → 0x00000004. Logical ones (andi, ori, xori) zero-extend karte hain. lb byte 0xF0 → 0xFFFFFFF0; lbu 0xF0 → 0x000000F0.

Diagram kaise padhein: Upar 4 input bits a3 a2 a1 a0, neeche 8 output bits y7 se y0. Neeche ke right 4 bits seedhe wire se upar wale se jude hain (y3 = a3, y2 = a2, y1 = a1, y0 = a0). Highlighted wire a3 (sign bit) se nikal ke y7, y6, y5, y4 sab mein jaata hai. Trace: a = 1011 → a3 = 1 → y7 se y4 = 1111 → y = 1111 1011.

Formula: sign-extend n → m bits: new bits = copies of the MSB. Verilog: y = {{4{a[3]}}, a}; (a[3] ko 4 baar repeat karo, phir a)
Solved example 1:

Sign-extend the 4-bit value 1010 to 8 bits and give its decimal value.

  1. MSB = 1.
  2. Naye 4 bits mein 1 bharo: 1111 1010.
  3. Value: 4-bit 1010 = −8 + 2 = −6. 8-bit 1111 1010 = −128 + 64 + 32 + 16 + 8 + 2 = −128 + 122 = −6. Same.

Answer: 1111 1010 = −6.

Solved example 2 (MCQ + 4 marks):

(i) Sign-extend the 8-bit value 0xF4 to 16 bits. (ii) What is sign extension and why does the MIPS datapath need it? Give a positive and a negative 16-bit example.

  1. (i) 0xF4 = 1111 0100, MSB 1 → upper 8 bits all 1 = 0xFF → 0xFFF4 (= −12).
  2. (ii) Model answer: "Sign extension widens a two's complement number by copying its sign bit into the new upper bits, so the value is unchanged. The MIPS ALU and registers are 32 bits wide but the immediate field of I-format instructions is only 16 bits, so offsets of lw/sw, constants of addi and branch offsets are sign-extended before use. Example: 0x0004 (+4) → 0x00000004; 0xFFFC (−4) → 0xFFFFFFFC."

Answer: 0xFFF4; definition + need + two examples as above.

Galti mat karna: Negative number mein 0 bharna (zero-padding) value badal deta hai. Aur ulta: unsigned data (lbu, andi, ori) ko sign-extend nahi karte, wahan 0 bharte hain.

Trick: "Signed → MSB copy. Unsigned → zero copy."

Ek line mein: 2's complement number ko chauda karte waqt naye bits mein MSB copy karo, value same rehti hai (−5: 1011 → 1111 1011).

4.5 Binary addition and subtraction

Pehle socho: School mein 47 + 38 aise karte the: 7 + 8 = 15, likho 5, 1 carry upar. Binary mein bhi bilkul wahi, bas 2 hote hi carry lagta hai (10 pe nahi). Aur subtraction ke liye alag circuit nahi chahiye: A − B = A + (−B), aur −B to invert + 1 se ban jaata hai. Ek hi adder dono kaam karta hai.
Definition: Binary addition adds column by column from the LSB, producing a sum bit and a carry into the next column. In two's complement, subtraction A − B is performed as A + B' + 1. An adder-subtractor uses one XOR gate per bit of B and a control input K (or M) that also feeds the carry-in, so that K = 0 gives A + B and K = 1 gives A − B.
Mushkil shabd, aasaan matlab:
carry
Column ka sum 2 ya 3 ho to agle column mein jaane wala 1. 1 + 1 = 10₂: likho 0, carry 1.
carry-in (Cin) / carry-out (Cout)
Kisi column mein aane wala carry / usse nikalne wala carry. 4-bit adder ka final carry-out C4 kehlata hai.
discard the carry
Signed answer mein 4 bits se bahar nikla 5th bit (C4) phenk do. Wo answer ka hissa nahi.
borrow
Unsigned subtraction mein "udhaar". A + B' + 1 method mein C4 = 0 ka matlab borrow hua (A < B), C4 = 1 ka matlab borrow nahi (A ≥ B).
XOR as controlled inverter
B ⊕ 0 = B (waisa hi), B ⊕ 1 = B' (ulta). Isliye ek control K se B ko ulta ya seedha kar sakte hain.
Kaise kaam karta hai:
  1. Chaar rules: 0 + 0 = 0 (carry 0); 0 + 1 = 1 (carry 0); 1 + 1 = 10 (likho 0, carry 1); 1 + 1 + 1 = 11 (likho 1, carry 1).
  2. Hamesha right column (bit 0) se shuru karo, har column mein A bit + B bit + aaya hua carry.
  3. Full example A (unsigned, 13 + 11 = 24): 1101 + 1011.

Result 1 1000 = 16 + 8 = 24. 4-bit box mein sirf 1000 = 8 bachta hai; C4 = 1 batata hai ki unsigned answer 15 se bada ho gaya.

Formula: A − B = A + B' + 1  ·  adder-subtractor: input to FA = Bᵢ ⊕ K, Cin = K.
Signed result: C4 phenko. Unsigned subtraction: C4 = 0 → borrow (A < B).
Solved example (5 marks):

Draw a 4-bit adder-subtractor and explain how one control input selects addition or subtraction. Trace 0101 − 0011.

  1. Circuit: draw D4.5a (4 FAs in a chain, XOR on every B input, K to all XORs and to Cin of FA0).
  2. K = 0: Bᵢ ⊕ 0 = Bᵢ and Cin = 0 → S = A + B.
  3. K = 1: Bᵢ ⊕ 1 = Bᵢ' and Cin = 1 → S = A + B' + 1 = A + (−B) = A − B.
  4. Trace: K = 1. B = 0011 → XOR outputs 1100. 0101 + 1100 + 1: bit 0: 1 + 0 + 1 = 10 → 0 c1; bit 1: 0 + 0 + 1 = 1 → 1 c0; bit 2: 1 + 1 + 0 = 10 → 0 c1; bit 3: 0 + 1 + 1 = 10 → 0 c1.
  5. S = 0010 (+2), C4 = 1 (no borrow, kyunki 5 ≥ 3).

Answer: 0101 − 0011 = 0010 (+2), C4 = 1.

Galti mat karna: (1) Subtract karte waqt sirf invert karna aur Cin = 1 bhool jaana (5 − 3 ka answer 0001 aayega, galat). (2) Signed answer mein C4 ko 5th bit bana ke likhna (1 0010 ko 18 padhna). (3) C4 = 1 ko "overflow" samajhna: signed overflow alag cheez hai (next topic).

Trick: "Minus = ulta + ek." Ek K wire do kaam karti hai: B ko ulta karti hai aur wahi +1 deti hai.

Ek line mein: Binary addition school wala column addition hai (2 pe carry), aur A − B = A + B' + 1, jo ek XOR-wale adder (K = 1) se ho jaata hai.

4.6 Overflow detection rules

Pehle socho: 2-litre ki bottle mein 3 litre paani daalo, 1 litre bahar gir jaata hai aur bottle mein galat maatra dikhti hai. 4-bit signed box sirf −8 se +7 tak hold kar sakta hai. 5 + 4 = 9 is box mein fit nahi hota, to adder ek galat pattern deta hai (1001 = −7). Ise overflow kehte hain. Aur ye chupchaap hota hai, koi alarm nahi bajta (odometer 999 se 000 pe chala jaata hai bina beep ke). Isliye CPU ek flag bit set karta hai taaki software check kar sake.
Definition: Overflow occurs when the true result of an arithmetic operation lies outside the range representable with the available bits. For two's complement (signed) addition it is indicated by the overflow flag V (OF) = Cin,MSB ⊕ Cout,MSB; for unsigned addition by the carry flag CF = Cout,MSB.
Mushkil shabd, aasaan matlab:
overflow
Sahi answer box ki range se bahar. 4-bit signed: answer +9 ya −9 aaye to overflow.
C3 / C4 (4-bit)
C3 = MSB column (bit 3) mein aane wala carry. C4 = MSB column se bahar jaane wala carry.
V / OF (overflow flag)
Signed overflow ka flag. V = C3 ⊕ C4 (dono alag hon to 1).
CF (carry flag)
Unsigned overflow ka flag = C4.
flag
Ek bit jo CPU result ke baare mein set karta hai, jaise "overflow hua" ya "result zero hai".
trap
Error pe program ka ruk jaana. MIPS add/addi signed overflow pe trap karte hain; addu/addiu nahi.
Kaise kaam karta hai:
  1. Seedha matlab: answer ko decimal mein socho. 4-bit signed range −8 to +7. Agar sahi answer is range ke bahar hai to overflow.
  2. Rule 1: positive + positive = negative aaya → overflow. (Do positive ka sum kabhi negative nahi ho sakta; MSB 1 aaya matlab number bahut bada ho gaya.)
  3. Rule 2: negative + negative = positive aaya → overflow.
  4. Opposite signs kabhi overflow nahi karte: +5 + (−3) ka answer hamesha dono ke beech mein aata hai (−3 aur +5 ke beech), aur dono already range mein hain, to answer bhi range mein.
  5. Rule 3 (hardware): C3 ≠ C4 → overflow. MSB column mein aane wala carry aur jaane wala carry alag hon to V = 1. Circuit mein bas ek XOR: V = C3 ⊕ C4.
  6. Rule 3 kyun sahi hai (MSB column dekho): (a) Dono MSB 0 (dono positive): C4 = 0 hi hoga; sum bit = C3. C3 = 1 aaya to answer ka MSB 1 (negative) → overflow, aur tab C3 = 1 ≠ C4 = 0. (b) Dono MSB 1 (dono negative): C4 = 1 hi hoga; sum bit = C3. C3 = 0 aaya to answer positive → overflow, aur tab C3 = 0 ≠ C4 = 1. (c) MSB alag: column mein 0 + 1 + C3, isliye C4 = C3 hamesha → V = 0. Teeno cases rule se match.
  7. Carry-out ≠ signed overflow (bahut important): −1 + 1 = 1111 + 0001 = 1 0000. C4 = 1 aaya, par signed answer 0000 = 0 bilkul sahi hai! C3 = 1, C4 = 1 → V = 0. Ulta, 7 + 1 = 0111 + 0001 = 1000: C4 = 0 par signed answer −8 galat (V = 1). Matlab C4 unsigned ka flag hai, signed ke liye C3 ⊕ C4 dekho.
  8. ALU dono flags hamesha banata hai; instruction decide karti hai kaunsa matter karta hai.

Formula: V = C3 ⊕ C4 (n-bit: Cn−1 ⊕ Cn)  ·  CF = C4
Sign form: V = A3'B3'S3 + A3B3S3' (dono 0 aur sum 1, ya dono 1 aur sum 0).
Solved example 1 (overflow hota hai):

In 4-bit two's complement compute 0101 + 0100. Is there overflow?

  1. Bit 0: 1 + 0 + 0 = 1 → likho 1, carry 0.
  2. Bit 1: 0 + 0 + 0 = 0 → likho 0, carry 0.
  3. Bit 2: 1 + 1 + 0 = 10 → likho 0, carry 1 (ye C3 hai, MSB mein jaayega).
  4. Bit 3 (MSB): 0 + 0 + 1 = 1 → likho 1, carry 0 (C4 = 0).
  5. Result 1001. Rule 1: +5 + +4 = negative (MSB 1) → overflow. Rule 3: C3 = 1, C4 = 0 → V = 1. Decimal: 9 > 7, fit nahi.

Answer: 1001 (reads as −7), V = 1 → signed overflow; CF = 0.

Solved example 2 (overflow nahi hota):

Compute 0101 + 1101 (+5 + −3) and state V and CF.

  1. Bit 0: 1 + 1 = 10 → 0, carry 1.
  2. Bit 1: 0 + 0 + 1 = 1 → 1, carry 0.
  3. Bit 2: 1 + 1 + 0 = 10 → 0, carry 1 (C3 = 1).
  4. Bit 3: 0 + 1 + 1 = 10 → 0, carry 1 (C4 = 1).
  5. Result 0010 = +2 (sahi). Signs opposite the → overflow possible hi nahi. C3 = 1 = C4 → V = 0. CF = 1 (par signed mein ignore).

Answer: 0010 = +2, V = 0, CF = 1 (no signed overflow).

Solved example 3 (mock 6 marks):

Compute 0110 − 1101 (two's complement) on the adder-subtractor and state the overflow flag.

  1. K = 1 → B' = 0010, Cin = 1.
  2. 0110 + 0010 + 1: bit 0: 0 + 0 + 1 = 1 → 1, c0; bit 1: 1 + 1 + 0 = 10 → 0, c1; bit 2: 1 + 0 + 1 = 10 → 0, c1 (C3 = 1); bit 3: 0 + 0 + 1 = 1 → 1, c0 (C4 = 0).
  3. Result 1001. Decimal check: 6 − (−3) = +9, jo 4-bit range (max +7) se bahar hai; 1001 ko −7 padha jaayega.
  4. C3 = 1, C4 = 0 → V = 1.

Answer: 1001, V = 1 (overflow).

Galti mat karna: (1) Carry-out C4 ko signed overflow flag bolna (1111 + 0001 mein C4 = 1 par V = 0). (2) "Positive + negative bhi overflow kar sakta hai" likhna: kabhi nahi. (3) Ye maanna ki overflow pe CPU khud error dega: by default chupchaap galat answer aata hai, flag check karna padta hai.

Trick: "Same sign andar, ulta sign bahar = overflow." Hardware ke liye: "MSB mein carry aaya aur gaya alag = overflow."

Ek line mein: Signed overflow tab hai jab do same-sign numbers ka sum ulta sign deta hai, hardware mein V = C3 ⊕ C4; unsigned overflow sirf CF = C4.
