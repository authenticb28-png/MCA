Unit 15 · Pipeline Hazards

Is unit ki kahani: Unit 14 mein pipeline ideal tha: har cycle ek naya instruction, koi rukawat nahi. Asli programs mein instructions ek doosre pe depend karte hain (add ka result sub use karta hai), hardware share hota hai, aur branch ke baad pata nahi agla instruction kaunsa. In situations ko hazards kehte hain. Is unit mein: hazards ke types, stall (rukna), forwarding (result jaldi pahunchana), load-use ka 1 stall, compiler scheduling (order badalna), branch handling, aur CPI = 1 + stalls wala formula. Saari cycle tables site ke pipeline tool (PIPE.schedule) ke convention se bani hain: register file pehle aadhe cycle mein likhta hai, doosre aadhe mein padhta hai; instruction aur data memory alag. (Class slides nahi thi; content Patterson & Hennessy se.)

15.1a Hazard Taxonomy and the Structural Hazard

Pehle socho: Flat mein 4 log, ek hi bathroom. Subah 8 baje do log ek saath ready: ek ko rukna padega. Ye hardware (resource) ki kami hai = structural hazard. Agar tumhe dost ki notes chahiye jo usne abhi likhi hi nahi = data hazard. Agar pata hi nahi aaj college jaana hai ya nahi jab tak notice na aaye = control hazard. Teeno mein result ek hi: kaam apne time pe shuru nahi ho sakta.
Definition: A hazard is a situation in which the next instruction cannot execute in its planned clock cycle. A structural hazard occurs when two instructions need the same hardware resource in the same cycle; a data hazard occurs when an instruction needs an operand that an earlier instruction has not yet produced; a control hazard occurs when the address of the next instruction depends on a branch that has not yet been resolved.
Mushkil shabd, aasaan matlab:
resource
Koi hardware hissa: memory, ALU, register file port.
stall (bubble)
Instruction ko ek cycle rok dena; us cycle pipeline ka woh stage khaali (nop) chalta hai. Table mein "stall" likhte hain.
unified vs split memory
Unified = instructions aur data ek hi memory mein (von Neumann). Split = alag instruction memory / cache aur data memory / cache (Harvard style, Unit 9). MIPS pipeline split use karta hai.

  1. lw CC1 mein IF, CC4 mein MEM (data memory padhni hai).

Diagram kaise padhein: 4 instructions ki pipeline diagram, CC1 to CC8. CC4 wala column box kiya hua hai: usme lw ka MEM aur or ka IF dono hain, dono ko memory chahiye. Neeche label "both need the memory". Baaki columns mein koi do instructions ek hi resource nahi maang rahe.

Solved example (write the answer like this, 5 marks):

Classify pipeline hazards with one example and one solution each. Show a structural hazard on a pipeline diagram.

  1. Structural: two instructions need the same resource in one cycle. Example: with one memory, lw's MEM and the 4th instruction's IF both occur in CC4. Solution: separate instruction and data memories.
  2. Data: an instruction needs a result not yet written. Example: add $s0, $t0, $t1 ; sub $t2, $s0, $t3. Solution: forwarding (stall for load-use).
  3. Control: next PC unknown until a branch resolves. Example: beq. Solution: predict not-taken / delayed branch / stall.
  4. Draw the 4-instruction table above and box CC4.

Answer: structural = resource, data = operand, control = branch; diagram with the CC4 conflict.

Galti mat karna: Resource conflict ko data hazard mat bolo. Aur ye mat likho ki MIPS 5-stage pipeline mein IF–MEM structural hazard hota hai: split memories ki wajah se nahi hota (sirf "agar ek memory ho to" wala example hai).
Ek line mein: Hazard = instruction apne cycle mein nahi chal sakta; structural (resource), data (operand), control (branch); single memory ka IF–MEM conflict split I / D memory se hat jaata hai.

15.1b Control Hazards: Branch Handling and CPI with Stalls

Pehle socho: Highway pe aage do raaste (fork) hain, aur board tab dikhega jab tum fork ke paas pahunchoge. Teen options: (1) ruk jao jab tak board na dikhe (stall); (2) andaza lagao ki seedha jaana hai aur chalte raho; galat nikla to wapas aao (predict not-taken + flush); (3) fork se pehle ek aisa kaam kar lo jo dono raaston mein karna hi hai, jaise petrol bharwana (delayed branch). CPU ko beq ke baad agla instruction turant fetch karna hai, lekin beq ka faisla baad ke stage mein hota hai.
Definition: A control hazard (branch hazard) arises because the pipeline must fetch the next instruction before the branch outcome is known. The branch penalty is the number of cycles lost. It is handled by stalling until the branch resolves, predicting not-taken (fetch sequentially and flush the wrong instructions if the branch is taken), dynamic prediction, or the delayed branch (the instruction after the branch, in the delay slot, is always executed).
Mushkil shabd, aasaan matlab:
branch resolved
Pata chal gaya ki branch lega ya nahi (taken / not taken) aur target kya hai.
taken / not taken
Taken = registers barabar, PC = target. Not taken = PC + 4 pe hi chalo.
flush
Galti se fetch kiye instruction ko pipeline se nikaal dena (usko nop bana dena), taaki woh kuch likhe nahi.
branch penalty
Branch ki wajah se kitne cycles barbaad hue. Branch ID mein decide ho to 1; MEM mein decide ho to 3.
delay slot
Branch ke turant baad wali jagah. Delayed branch mein ye instruction hamesha chalta hai, branch le ya na le.
dynamic prediction
Hardware pichhli baar ka result yaad rakhta hai (1-bit ya 2-bit counter, branch target buffer) aur usi hisaab se guess karta hai. Loops mein bahut sahi guess karta hai.
Kaise kaam karta hai:
  1. Branch kab decide hota hai: basic P&H pipeline mein compare EX mein aur PC update MEM mein → beq ke peeche 3 instructions galat raaste ke fetch ho chuke hote hain (penalty 3). Compare aur target adder ko ID mein le aao → penalty sirf 1 cycle.
  2. Option 1, stall: beq ke baad ek cycle kuch fetch mat karo; ID mein faisla hote hi sahi instruction fetch karo. Har branch pe 1 cycle jaata hai.
  3. Option 2, predict not-taken: maan lo branch nahi lega, PC + 4 wala fetch karte raho. Not taken → 0 loss. Taken → galat instruction flush, target fetch → 1 cycle loss (branch in ID).
  4. Option 3, delayed branch (MIPS): branch ke baad wala instruction hamesha chalta hai. Compiler waha koi aisa instruction rakhta hai jo dono case mein chahiye (branch se pehle wala independent instruction). Kuch na mile to nop.
  5. Option 4, dynamic prediction: history ke basis pe taken / not-taken guess, galat guess pe flush.

Stall (branch decided in ID): agla instruction CC2 ki jagah CC3 mein fetch hota hai.

Delayed branch ka example:

Before:                     After (delay slot filled):
add $s1, $s2, $s3           beq $t1, $t2, L
beq $t1, $t2, L             add $s1, $s2, $s3   # delay slot, always runs

add ko branch ke baad le jaana safe hai kyunki add $t1 / $t2 ko nahi badalta, aur add dono raaston mein waise bhi chalna tha. Ab us slot mein waste nahi.

Formula (CPI with stalls): CPI = 1 + (stall cycles per instruction)
Branch stalls per instruction = (fraction of branches) × (fraction that pays the penalty) × (penalty cycles)
Time = N × CPI × tcycle · speedup over non-pipelined (balanced k stages) = k / CPI
Always stall: har branch penalty deta hai. Predict not-taken: sirf taken branches penalty dete hain.
Solved example 1 (easy):

20 % of instructions are branches. The pipeline always stalls 1 cycle on a branch. Find the CPI.

  1. Stalls per instruction = 0.20 × 1 = 0.20.
  2. CPI = 1 + 0.20 = 1.20.

Answer: CPI = 1.20.

Solved example 2 (exam-level):

20 % of instructions are branches and 60 % of branches are taken. The clock is 200 ps. Compare the CPI and the time for 106 instructions for: (a) predict not-taken with branch in ID (penalty 1), (b) predict not-taken with branch in MEM (penalty 3).

  1. Taken branches per instruction = 0.20 × 0.60 = 0.12.
  2. (a) Stalls = 0.12 × 1 = 0.12 → CPI = 1.12.
  3. (a) Time = 106 × 1.12 × 200 ps = 224 × 106 ps = 224 µs.
  4. (b) Stalls = 0.12 × 3 = 0.36 → CPI = 1.36.
  5. (b) Time = 106 × 1.36 × 200 ps = 272 × 106 ps = 272 µs.
  6. Comparison: branch ko ID mein decide karne se 272 → 224 µs; 272 / 224 = 1.21 guna tez.

Answer: (a) CPI 1.12, 224 µs; (b) CPI 1.36, 272 µs.

Galti mat karna: (1) Predict not-taken mein not-taken branches pe bhi penalty jod dena: unka loss 0 hai. (2) Branch hazard ko data hazard bolna. (3) Delayed branch mein slot ka instruction "sirf taken pe" chalta hai sochna: woh hamesha chalta hai.

Trick: "Ruko, Andaza, Pehle-kaam" = stall, predict not-taken, delayed branch. Penalty: ID mein faisla = 1, MEM mein = 3.

Ek line mein: Branch ka faisla der se hota hai; stall (har branch 1 cycle), predict not-taken (sirf taken pe 1), delayed branch (slot hamesha chalta); CPI = 1 + branch% × penalty wala% × penalty.

15.2 RAW, WAR, WAW: Why Only RAW Matters In-Order

Pehle socho: Whiteboard pe ek number likha hai. (1) Tumhe woh number padhna hai jo dost abhi likhne wala hai: tumhe intezaar karna hoga (RAW). (2) Tum pehle padhoge, phir dost mitaake naya likhega: agar dost jaldi kar de to tum galat padhoge (WAR). (3) Dono likhenge: aakhir mein jo baad wala hai uska number rehna chahiye (WAW). Hamare 5-stage pipeline mein sab ek line mein, ek hi order mein chalte hain, isliye sirf pehla wala (RAW) problem karta hai.
Definition: RAW (read after write, true dependence): a later instruction reads a register that an earlier one writes. WAR (write after read, anti-dependence): a later instruction writes a register that an earlier one reads. WAW (write after write, output dependence): two instructions write the same register. In the in-order 5-stage MIPS pipeline only RAW causes hazards.
Mushkil shabd, aasaan matlab:
dependence
Do instructions ka ek hi register se rishta, jisse unka order badalna risky hai.
in-order
Instructions program ke order mein hi stages se guzarte hain; koi aage nahi nikalta.
register renaming
Out-of-order CPUs mein WAR / WAW hataane ki technique: alag physical register de do, naam ka takraav khatam.
Kaise pehchaanein (I1 pehle, I2 baad mein):
  1. RAW: I1: add $s0, $t0, $t1 ; I2: sub $t2, $s0, $t3. I2 padhta hai $s0, jo I1 likhta hai.
  2. WAR: I1: sub $t2, $s0, $t3 ; I2: add $s0, $t4, $t5. I2 likhta hai $s0, jo I1 padhta hai.
  3. WAW: I1: add $s0, $t0, $t1 ; I2: sub $s0, $t2, $t3. Dono $s0 likhte hain.
  4. Sirf RAW kyun: har instruction registers ID (stage 2) mein padhta hai aur WB (stage 5) mein likhta hai, aur order same rehta hai. Baad wala instruction kabhi pehle wale se pehle WB tak nahi pahunch sakta → WAW nahi. Baad wale ka WB (stage 5) pehle wale ke ID (stage 2) ke baad hi aata hai → WAR nahi.
  5. WAR / WAW sirf out-of-order ya alag-alag length ke pipelines mein problem hain; wahan register renaming fix hai.
Solved example (MCQ type):

Classify: (a) add $s0, $t0, $t1 ; sub $t2, $s0, $t3. (b) lw $t0, 0($s1) ; addi $s1, $s1, 4 (dependence on $s1).

  1. (a) I1 likhta $s0, I2 padhta $s0 → read after write → RAW.
  2. (b) I1 (lw) $s1 padhta hai (base address), I2 (addi) $s1 likhta hai → write after read → WAR. In-order pipeline mein ye koi hazard nahi.

Answer: (a) RAW, (b) WAR (harmless in the 5-stage in-order pipeline).

Galti mat karna: Naam "kya pehle hua" ke order mein hai: RAW = pehle write (I1), phir read (I2). add $s0 → sub uses $s0 ko WAR mat bolo.
Ek line mein: RAW = true dependence, sirf yahi 5-stage in-order MIPS mein hazard; WAR / WAW nahi hote kyunki sab ID mein padhte, WB mein likhte, same order mein.

15.3 The Naive Fix: Stalls (Bubbles)

Pehle socho: Tiffin dabba line mein ek dabbawala ko doosre ka label chahiye jo abhi chhapa nahi. Seedha tareeka: woh ruk jaaye, aur uske peeche wale bhi (line hai, koi overtake nahi karta). Line mein jo khaali jagah banti hai, use bubble kehte hain. Kaam sahi hota hai, par time barbaad hota hai.
Definition: A stall (pipeline bubble) is a cycle in which an instruction is held in its stage, together with all instructions behind it, until its operand is available; the empty slot that travels down the pipeline behaves like a nop. Without forwarding, a dependent instruction must wait until the producer has written the register file in WB.
Mushkil shabd, aasaan matlab:
nop
"No operation": aisa instruction jo kuch nahi karta. Bubble = hardware ka banaya nop.
distance
Producer aur consumer ke beech kitne instructions ka gap. Turant agla = distance 1.
hazard detection unit
ID stage mein ek circuit jo dependence pakad ke stall karta hai.
interlock
Hardware khud rokna (stall). Early MIPS ("Microprocessor without Interlocked Pipeline Stages") ye kaam compiler pe chhodta tha: compiler nop daalta tha.
Kaise kaam karta hai (no forwarding):
  1. add $s0 apna result CC5 (WB) mein register file mein likhta hai, pehle aadhe cycle mein.
  2. sub ko $s0 ID mein padhna hai. Normally sub ka ID CC3 mein hota. Wahan $s0 purana hai → galat.
  3. sub ko tab tak ID mein rok do jab tak padhai CC5 ke doosre aadhe mein na ho (wahan nayi value mil jaayegi).
  4. CC3 → CC5 = 2 cycles extra → 2 stalls. sub ka EX CC4 ki jagah CC6 mein.
  5. Peeche wala and bhi ruka (IF mein), sab 2 cycle late. Total 7 ki jagah 9 cycles.
  6. Rule: distance 1 → 2 stalls; distance 2 → 1 stall; distance 3 ya zyada → 0 stalls.
  7. Hardware stall kaise karta hai: (a) PC aur IF/ID register ko update nahi hone deta (wahi instructions dobara fetch / decode); (b) ID/EX mein jaane wale saare control signals 0 kar deta hai → EX, MEM, WB mein kuch nahi likha jaata = bubble.

add → sub (distance 1), no forwarding: 9 cycles, 2 stalls

add $s0, $t0, $t1IFIDEXMEMWB
sub $t2, $s0, $t3IFIDstallstallEXMEMWB
and $t4, $t5, $t6IFstallstallIDEXMEMWB

Diagram kaise padhein: add normal staircase mein (CC1 to CC5). sub CC2 mein fetch hota hai, phir do "stall" boxes (CC3, CC4), aur ID CC5 mein: bilkul add ke WB wale column mein (same cycle likho aur padho). and bhi do cycle right khisak gaya. Last WB CC9 mein = 9 cycles.

Formula: CPI = 1 + (stall cycles per instruction) · Total cycles = (k + n − 1) + total stalls
Solved example 1 (easy):

No forwarding. add $s0, $t0, $t1 ; sub $t2, $s0, $t3 ; and $t4, $t5, $t6. How many stalls and total cycles?

  1. sub ko $s0 chahiye, distance 1 → 2 stalls.
  2. and independent hai, lekin sub ke peeche hai, to woh bhi 2 late (koi extra stall nahi).
  3. Ideal = 5 + (3 − 1) = 7. Total = 7 + 2 = 9.

Answer: 2 stalls, 9 cycles.

Solved example 2 (CPI, exam-level):

No forwarding. In a program 30 % of instructions use the result of the immediately previous instruction and another 10 % use the result of the instruction two before. Find the CPI and the execution time of 106 instructions at 200 ps.

  1. Distance 1 → 2 stalls: 0.30 × 2 = 0.60 stall cycles per instruction.
  2. Distance 2 → 1 stall: 0.10 × 1 = 0.10.
  3. CPI = 1 + 0.60 + 0.10 = 1.70.
  4. Time = 106 × 1.70 × 200 ps = 340 × 106 ps = 340 µs (ideal CPI 1 hota to 200 µs).

Answer: CPI = 1.70, time = 340 µs. Isliye forwarding chahiye (15.4).

Galti mat karna: (1) 3 stalls ginna: register file ka "pehle likho, phir padho" bhool gaye. (2) Sirf dependent instruction ko rokna aur peeche walon ko aage nikal jaane dena: in-order pipeline mein sab ke sab rukte hain.

Trick: Bina forwarding: distance 1 → 2, distance 2 → 1, distance 3 → 0 (stalls + distance = 3).

Ek line mein: Stall = dependent instruction (aur peeche wale) rok do jab tak value register file mein na aaye; no forwarding mein back-to-back dependence = 2 bubbles; CPI = 1 + stalls per instruction.

15.4 Forwarding (Bypassing)

Pehle socho: Dost ne exam ka answer nikaal liya hai, lekin abhi register (notebook) mein likh raha hai. Tumhe notebook ka intezaar kyun karna? Woh seedha bol de, kaam ho gaya. CPU mein add ka result EX stage ke end mein ban jaata hai (CC3), WB (CC5) tak rukne ki zaroorat nahi. Pipeline register (EX/MEM ya MEM/WB) se seedha ALU ke input pe bhej do. Isse kehte hain forwarding.
Definition: Forwarding (bypassing) is a technique in which a result is sent directly from a pipeline register (EX/MEM or MEM/WB) to the ALU input of a later instruction, instead of waiting for it to be written into the register file. A forwarding unit compares register numbers and drives multiplexers (ForwardA, ForwardB) in front of the ALU.
Mushkil shabd, aasaan matlab:
EX/MEM → EX
Producer abhi MEM stage mein hai (ek instruction aage). Uska ALU result EX/MEM register mein pada hai → consumer ke EX mein bhejo.
MEM/WB → EX
Producer WB stage mein hai (do instructions aage). Result MEM/WB register mein → consumer ke EX mein bhejo.
ForwardA / ForwardB
ALU ke do inputs (A = rs wala, B = rt wala) ke aage 3-input MUX ka select. 00 = register file, 10 = EX/MEM, 01 = MEM/WB.
ID/EX.Rs
"ID/EX register mein jo instruction hai uska rs number." Dot ke pehle register ka naam, baad mein field.
Kaise kaam karta hai:
  1. Har cycle forwarding unit EX wale instruction ke source register numbers (ID/EX.Rs, ID/EX.Rt) ko aage wale instructions ke destination (EX/MEM.Rd, MEM/WB.Rd) se compare karta hai.
  2. Match EX/MEM ke saath (aur woh instruction sach mein register likhta ho, aur Rd ≠ $zero): ForwardA = 10 → ALU ko EX/MEM wala result.
  3. Match MEM/WB ke saath (aur EX/MEM ke saath match nahi): ForwardA = 01 → MEM/WB wala result.
  4. Koi match nahi: ForwardA = 00 → register file wali value.
  5. Rt ke liye bilkul same rules ForwardB pe.
  6. Distance 3 ya zyada: register file khud handle karta hai (pehle aadhe mein likha, doosre mein padha).
EX hazard:  if (EX/MEM.RegWrite and EX/MEM.Rd != 0
               and EX/MEM.Rd == ID/EX.Rs)                ForwardA = 10
MEM hazard: if (MEM/WB.RegWrite and MEM/WB.Rd != 0
               and not (EX hazard for Rs)
               and MEM/WB.Rd == ID/EX.Rs)                ForwardA = 01
(same two conditions with Rt give ForwardB)

Har condition ka WHY: RegWrite check: sw / beq register nahi likhte, unka "Rd" bekaar hai. Rd ≠ 0: $zero hamesha 0 rehna chahiye, usko likhne ki koshish forward nahi karni. "not EX hazard": agar dono mein match ho to sabse naya (EX/MEM) result jeetna chahiye.

P&H chain with forwarding: 9 cycles, 0 stalls ($1 = 10, $3 = 4 maan lo, to sub ka result $2 = 6)

InstructionCC1CC2CC3CC4CC5CC6CC7CC8CC9
sub $2, $1, $3IFIDEXMEMWB
and $12, $2, $5IFIDEXMEMWB
or $13, $6, $2IFIDEXMEMWB
add $14, $2, $2IFIDEXMEMWB
sw $15, 100($2)IFIDEXMEMWB
  1. CC3: sub EX mein 10 − 4 = 6 banata hai. Edge pe 6 → EX/MEM.
  2. CC4: and EX mein. EX/MEM.Rd = $2 = ID/EX.Rs ($2) → ForwardA = 10, and ko 6 milta hai.
  3. CC5: or EX mein. or $13, $6, $2 mein $2 = rt. Ab sub MEM/WB mein → ForwardB = 01. (EX/MEM mein ab and hai, uska Rd = $12, match nahi.)
  4. CC5: add $14, $2, $2 ID mein register file padhta hai. Usi cycle sub WB pehle aadhe mein $2 = 6 likh deta hai → sahi value, forwarding nahi chahiye.
  5. CC6: sw $15, 100($2) ID mein: $2 already register file mein.
  6. Bina forwarding yahi chain 11 cycles leti (and aur or dono ruke): 2 cycles bache.

Priority example: add $1, $1, $2 ; add $1, $1, $3 ; add $1, $1, $4. Teesre add ke EX (CC5) mein $1 do jagah hai: MEM/WB mein (pehle add ka, purana) aur EX/MEM mein (doosre add ka, naya). Rule "not EX hazard" ki wajah se EX/MEM (ForwardA = 10) chuna jaata hai: sahi, kyunki program order mein sabse naya value wahi hai.

Diagram kaise padhein: Upar wali pipeline diagram mein orange arrows forwarding hain: sub ke EX ke end se and ke EX ke start tak (EX/MEM → EX), aur sub ke MEM ke end se or ke EX tak (MEM/WB → EX). Arrows hamesha aage (right / neeche) jaate hain, peeche time mein kabhi nahi. Neeche wala hardware: ID/EX se RD1, RD2 do 3-input MUX (A, B) mein, unke inputs 00 (register file), 10 (EX/MEM se orange wire), 01 (MEM/WB se wire). Neeche "Forwarding unit" box ID/EX.Rs / Rt ko EX/MEM.Rd aur MEM/WB.Rd se compare karke MUX selects (dashed) deta hai.

Solved example 1 (MCQ type):

and $12, $2, $5 directly follows sub $2, $1, $3. Where does and's first ALU operand come from, and what is ForwardA? How many stalls with forwarding?

  1. Distance 1: jab and EX mein hai, sub MEM mein hai, uska result EX/MEM register mein.
  2. $2 and ka rs hai → ALU input A → ForwardA = 10.
  3. Result time pe mil gaya → 0 stalls.

Answer: from the EX/MEM pipeline register, ForwardA = 10, 0 stalls.

Solved example 2 (write the answer like this, 5 marks):

Explain forwarding with the forwarding hardware and write the EX-hazard and MEM-hazard conditions.

  1. An ALU result is ready at the end of EX, two cycles before WB. Forwarding sends it from the EX/MEM or MEM/WB pipeline register directly to the ALU inputs of later instructions.
  2. Hardware: two 3-input MUXes in front of the ALU (ForwardA, ForwardB; 00 register file, 10 EX/MEM, 01 MEM/WB) and a forwarding unit that compares ID/EX.Rs and ID/EX.Rt with EX/MEM.Rd and MEM/WB.Rd.
  3. EX hazard: EX/MEM.RegWrite and EX/MEM.Rd ≠ 0 and EX/MEM.Rd = ID/EX.Rs → ForwardA = 10.
  4. MEM hazard: MEM/WB.RegWrite and MEM/WB.Rd ≠ 0 and not EX hazard and MEM/WB.Rd = ID/EX.Rs → ForwardA = 01. (Same for Rt / ForwardB.)
  5. Draw the sub-and-or-add-sw diagram with the two arrows.

Answer: as above; ALU-to-ALU dependences need 0 stalls with forwarding.

Galti mat karna: (1) Forwarding arrow ko peeche ki taraf (pichhle cycle mein) draw karna: data future se past mein nahi ja sakta. (2) Rd ≠ 0 check bhoolna. (3) Dono match hon to MEM/WB se forward karna: naya EX/MEM jeetta hai.

Trick: "1 aage → EX/MEM (10), 2 aage → MEM/WB (01), 3 aage → register file (00)."

Ek line mein: Result ko register file ka intezaar kiye bina EX/MEM ya MEM/WB se seedha ALU tak bhejo; ALU → ALU dependence mein 0 stall.

15.5 The Load-Use Hazard: Forwarding + One Stall

Pehle socho: add ka result EX ke end mein ban jaata hai, isliye agla instruction usse turant le sakta hai. Lekin lw ka data memory se aata hai, yaani MEM stage ke end mein, ek cycle aur baad. Agla instruction use apne EX ki shuruaat mein chahta hai, jo bilkul usi cycle mein hai jisme lw abhi memory padh raha hai. Data abhi bana hi nahi; forwarding time mein peeche nahi bhej sakta. Isliye ek cycle rukna hi padega.
Definition: A load-use hazard occurs when an instruction uses the register loaded by the immediately preceding lw. Because the loaded data is available only at the end of the MEM stage, one stall cycle is required even with forwarding; after the stall the value is forwarded from MEM/WB to EX.
Mushkil shabd, aasaan matlab:
load-use
lw ke turant baad wala instruction usi register ko use kare. lw $2, 20($1) ; and $4, $2, $5.
MemRead (ID/EX.MemRead)
ID/EX mein baitha instruction load hai, iski pehchaan.
IF/ID.Rs, IF/ID.Rt
ID stage wale (agle) instruction ke source registers.
Kaise kaam karta hai:
  1. lw $2, 20($1): CC3 EX mein address = $1 + 20 (jaise $1 = 100 → 120). CC4 MEM mein Mem[120] padha, data CC4 ke end mein ready.
  2. and $4, $2, $5 normally CC4 mein EX karta: use CC4 ki shuruaat mein $2 chahiye. Data abhi nahi → impossible.
  3. Hazard detection unit (ID mein, CC3): ID/EX.MemRead = 1 aur ID/EX.Rt ($2) = IF/ID.Rs ($2) → stall.
  4. Stall: PC aur IF/ID hold, ID/EX mein bubble (control 0). and ka EX CC5 mein chala jaata hai.
  5. CC5 mein lw MEM/WB mein hai → ForwardA = 01 → and ko $2 mil jaata hai.
  6. Bina forwarding yahi 2 stalls hote (WB tak wait). lw aur use ke beech ek independent instruction ho to 0 stall.
if (ID/EX.MemRead and

Diagram kaise padhein: lw normal (CC1 to CC5). and ki row mein ID ke baad ek stall box (CC4), phir EX CC5 mein. Orange arrow lw ke MEM ke end (CC4) se and ke EX ki shuruaat (CC5) tak: MEM/WB → EX forwarding. Dhyan do arrow time mein aage jaata hai; stall na hota to arrow seedha upar-neeche (same cycle) hota, jo impossible hai.

Formula: Load-use stalls per instruction = (fraction of loads) × (fraction of loads followed immediately by a use) × 1
CPI = 1 + load-use stalls + branch stalls
Solved example 1 (easy):

With forwarding: lw $t0, 0($t1) ; add $t2, $t0, $t3. Stalls and total cycles? Without forwarding?

  1. Load ke turant baad use → 1 stall (forwarding ke saath).
  2. Ideal = 5 + (2 − 1) = 6. Total = 6 + 1 = 7.
  3. Without forwarding: add ko WB tak rukna → 2 stalls → 6 + 2 = 8.

Answer: with forwarding 1 stall, 7 cycles; without 2 stalls, 8 cycles.

Solved example 2 (CPI, exam-level):

A pipeline has full forwarding. 25 % of instructions are loads and 40 % of loads are immediately followed by an instruction that uses the loaded value. 15 % of instructions are branches, each costing 1 stall cycle. Find the CPI and the speedup over an unpipelined machine (balanced 5 stages).

  1. Load-use stalls = 0.25 × 0.40 × 1 = 0.10.
  2. Branch stalls = 0.15 × 1 = 0.15.
  3. ALU → ALU dependences: forwarding se 0.
  4. CPI = 1 + 0.10 + 0.15 = 1.25.
  5. Unpipelined: har instruction 5 stage-times. Pipelined: 1.25 stage-times per instruction. Speedup = 5 / 1.25 = 4.

Answer: CPI = 1.25, speedup = 4.

Solved example 3 (write the answer like this):

Why can't forwarding alone resolve a load-use hazard?

  1. The loaded value is produced only at the end of the MEM stage.
  2. The next instruction needs it at the beginning of its EX stage, which is the same cycle as the load's MEM.
  3. Forwarding can only send a value forward in time, not backward, so the dependent instruction must be stalled one cycle; then the value is forwarded MEM/WB → EX.
  4. Detection: ID/EX.MemRead and (ID/EX.Rt = IF/ID.Rs or ID/EX.Rt = IF/ID.Rt).

Answer: data ready after MEM, needed at EX of the next instruction in the same cycle → 1 stall + MEM/WB forwarding.

Galti mat karna: (1) "Forwarding se load-use stall bhi khatam" likhna: 1 stall bachta hai. (2) Forwarding arrow lw ke EX se draw karna: EX mein sirf address bana hai, data MEM ke end mein. (3) lw ke baad independent instruction ho to bhi stall lagana: tab 0 stall.
Ek line mein: Load ka data MEM ke end mein aata hai, agle instruction ko EX ki shuruaat mein chahiye, isliye forwarding ke saath bhi 1 stall, phir MEM/WB → EX.

15.6 Compiler Scheduling (reordering to remove load-use stalls)

Pehle socho: Maggi banate waqt paani ubalne ka intezaar karte ho (stall). Smart tareeka: usi waqt pyaaz kaat lo, jo baad mein chahiye hi tha. Kaam ka order badla, result wahi, time bacha. Compiler bhi yahi karta hai: lw ke baad ka khaali slot kisi aise instruction se bhar deta hai jo us load pe depend nahi karta.
Definition: Compiler (instruction) scheduling is the reordering of independent instructions by the compiler so that a load is not immediately followed by an instruction that uses its result, removing load-use stalls without changing the program's result. All RAW, WAR and WAW dependences (through registers and memory) must be preserved.
Mushkil shabd, aasaan matlab:
independent instruction
Jo na load ka register padhta hai, na koi aisa register likhta hai jo beech ke instructions use karte hain.
legal reordering
Order badalne ke baad bhi har register aur memory location mein wahi final value aaye.
load delay slot
lw ke turant baad ki jagah; yahan independent instruction rakho.
Kaise karein (steps):
  1. Har lw dhundo jiske turant baad wala instruction uska register use karta hai (load-use pair).
  2. Aage ya peeche se ek independent instruction dhundo (aksar doosra lw).
  3. Check karo: use upar khiskaane se koi RAW / WAR / WAW nahi tootna chahiye (jo register woh likhta hai, beech mein koi padh / likh nahi raha; jo woh padhta hai, beech mein koi likh nahi raha; store ke upar load tabhi jab address alag ho).
  4. Use load-use pair ke beech rakh do.
  5. Cycles dobara gino: 5 + (n − 1) + bache hue stalls.

Easy example (with forwarding). Original: lw $t0, 0($s1) ; add $t1, $t0, $s2 ; sw $t1, 4($s1) ; lw $t3, 8($s1). lw → add load-use = 1 stall → 5 + 3 + 1 = 9 cycles. lw $t3 kisi pe depend nahi karta aur koi usse pehle $t3 use nahi karta → upar khiskao:

InstructionCC1CC2CC3CC4CC5CC6CC7CC8

Ab add aur lw $t0 ke beech lw $t3 hai: add ko $t0 MEM/WB se, sw ko $t1 EX/MEM se. 0 stalls, 8 cycles (9 se 8).

Solved example (MCQ type):

lw $t1, 0($t0) ; add $t2, $t1, $t3 ; sub $t4, $t5, $t6. Which reordering is ILLEGAL: (a) move sub between lw and add, (b) move sub before lw, (c) move add before lw?

  1. (a) sub $t1 / $t2 se koi lena-dena nahi → legal, aur load-use stall bhi hat jaata hai (best choice).
  2. (b) sub kisi pe depend nahi → legal (lekin stall nahi hatega).
  3. (c) add ko $t1 chahiye jo lw laata hai (RAW). add pehle chala to purana $t1 use karega → illegal.

Answer: (c) is illegal; (a) is the useful legal move (removes the stall).

Galti mat karna: (1) Load ko us store ke upar le jaana jo usi address pe likhta hai (memory RAW tootega). (2) Do instructions jo same register likhte hain unka order badalna (WAW). (3) Scheduled version mein bhi stall ginna jab beech mein ek independent instruction aa gaya ho.

Trick: "lw ke baad gap bharo, dependence mat todo." Sabse aasaan filler: agla lw upar khiskao.

Ek line mein: Compiler independent instructions (aksar loads) ko upar khiska ke load-use slot bharta hai; P&H example 13 → 11 cycles; har dependence bachani zaroori.
