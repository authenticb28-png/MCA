Unit 11 · MIPS Registers & Instruction Formats

Is unit ki kahani: Unit 10 mein humne kaha "RISC = fixed 32-bit, load/store". Ab ek asli RISC, MIPS, ko andar se dekhte hain: CPU ke paas 32 registers hain (har ek ka kaam software ne tay kiya hai), aur har instruction 32 bits ka hai jo teen "formats" (R, I, J) mein se ek mein bata hota hai. Is unit ke baad tum koi bhi MIPS instruction ko binary/hex mein badal paoge aur hex ko wapas assembly mein. Unit 12 mein inhi instructions se C program likhenge, aur Unit 13 mein dekhenge ki hardware in fields ko kaise use karta hai.

11.1 Why MIPS for teaching

Pehle socho: Gaadi chalana seekhna ho to log pehle simple manual car pe seekhte hain, Formula-1 pe nahi. Ek baar clutch-gear samajh gaye to koi bhi gaadi chala loge. MIPS computer architecture ki "simple manual car" hai: sirf 3 formats, har instruction 32 bits, poora ek hafte mein seekh sakte ho, aur yahi soch RISC-V aur ARM mein seedhi kaam aati hai.
Definition: MIPS (Microprocessor without Interlocked Pipeline Stages) is a classic RISC ISA from Stanford (John Hennessy, 1984) with 32 general-purpose 32-bit registers, fixed 32-bit instructions in three formats (R, I, J) and a load/store memory model. It is used for teaching because it is clean, small and well supported by simulators and textbooks.
Mushkil shabd, aasaan matlab:
Format
32 bits ko alag-alag hisson (fields) mein baantne ka tareeka. MIPS mein sirf 3: R, I, J.
MARS / SPIM
Computer pe chalne wale MIPS simulators. Code likho, ek-ek line chalao (single-step), har register ki value dekho. Lab mein MARS 4.5.
Patterson & Hennessy (P&H)
Course ki textbook "Computer Organization and Design"; iska datapath aur pipeline MIPS pe bana hai (Units 13 to 15).
Kyun MIPS (4 reasons, exam mein yahi likho):
  1. Clean, fixed-width design: har instruction 32 bits, sirf 3 formats → poora ISA chhota, seekhna aasaan.
  2. Tooling: MARS simulator mein step-by-step chala ke har register dekh sakte ho.
  3. Textbook: P&H ka datapath aur pipeline MIPS pe bana hai.
  4. Transferable: registers + formats wali soch RISC-V aur ARM mein waise hi chalti hai; sirf syntax badalta hai.
  5. Real history: Stanford 1984; SGI workstations, PlayStation 1 (R3000A), Nintendo 64 (VR4300), PS2 (R5900) mein chala.
Solved example (direct):

How many bytes long is every MIPS instruction, and how many instruction formats does MIPS have?

  1. Har instruction 32 bits.
  2. 1 byte = 8 bits, to 32 / 8 = 4 bytes. Isliye agla instruction PC + 4 pe.
  3. Formats: R, I, J = 3.

Answer: 4 bytes; 3 formats (R, I, J).

Galti mat karna: MIPS ke 3 formats hain, RISC-V ke 6 (R, I, S, B, U, J). Dono ko mix mat karna.
Ek line mein: MIPS = simple, fixed 32-bit, 3-format RISC jo seekhne mein aasaan aur RISC-V/ARM tak transfer hota hai.

11.2 MIPS register set aur conventions

Pehle socho: Hostel ke ek room mein 32 lockers hain. Hardware ke liye sab lockers ek jaise hain, par hostel walon ne rule bana diya: locker 4 se 7 mein "doston ke liye saamaan" (arguments), locker 2-3 mein "wapas milne wala jawab" (return value), locker 29 mein "stack ka pata", locker 31 mein "wapas kahan aana hai" ka parchi. Agar sab ye rule maanein to kisi ka bhi likha function kisi ke bhi function ko call kar sakta hai. Hardware ko farak nahi padta, ye rules software ka agreement (convention) hain.
Definition: MIPS has 32 general-purpose registers of 32 bits each ($0 to $31). The hardware treats them alike (except $zero, which is always 0), but the register convention gives each a software role. Caller-saved registers ($t, $a, $v) may be changed by a called function, so the caller must save them if it needs their values. Callee-saved registers ($s, $sp, $fp, $ra, $gp) must be restored by the called function before it returns. PC, HI and LO are separate special registers.
Mushkil shabd, aasaan matlab:
Register
CPU ke andar ek chhoti, bahut tez 32-bit memory. Sab maths registers pe hota hai.
Caller
Jo function doosre ko call karta hai (jaise main).
Callee
Jo function call hota hai (jaise sum).
Caller-saved
"Bulaane wala khud bachaye". Callee isko bina bataye badal sakta hai. Caller ko value chahiye to call se pehle stack pe rakh le.
Callee-saved
"Bulaya gaya bachaye". Callee use kare to pehle purani value save kare aur return se pehle wapas daal de. Caller ke liye value "safe" hai.
Stack
Memory ka ek hissa jahan functions temporary cheezein rakhte hain (Unit 12). $sp uska top batata hai.
PC (program counter)
Agle instruction ka address. Ye 32 registers mein se nahi hai; khud PC + 4 hota hai ya branch/jump se badalta hai.
HI, LO
Do special registers jahan mult aur div apna result rakhte hain. mfhi/mflo se padhte hain.
Har register ka naam, number, kaam aur KYUN:
  1. $zero ($0): hamesha 0. Isme likho to bhi 0 hi rahega (write ignore). Kyun: 0 itna common hai (copy karna, compare karna, clear karna) ki ek register ko permanently 0 bana diya. Jaise move $t0, $t1 asal mein addu $t0, $zero, $t1 hai (0 + $t1).
  2. $at ($1): assembler temporary. Kyun: pseudo-instructions (jaise blt, la, bada li) ko assembler 2 asli instructions mein todta hai aur beech ka result $at mein rakhta hai. Tum ise mat chhuo.
  3. $v0, $v1 ($2, $3): "values" = return values. Function apna jawab $v0 mein deta hai (64-bit jawab ho to $v1 bhi). Syscall ka code bhi $v0 mein daalte hain.
  4. $a0 to $a3 ($4 to $7): "arguments". Function ko pehle 4 inputs inme dete hain; zyada hon to stack pe. Kyun registers mein: memory se tez.
  5. $t0 to $t7 ($8 to $15), $t8, $t9 ($24, $25): "temporaries", caller-saved. Chhote-mote hisaab ke liye. Callee inhe bina puchhe badal sakta hai, isliye inko save karne ki zimmedari caller ki. Kyun aisa rule: chhota function bina stack ke jaldi kaam kar le.
  6. $s0 to $s7 ($16 to $23): "saved", callee-saved. Lambi zindagi wale variables (jaise loop ka sum jo function call ke baad bhi chahiye). Callee inhe use kare to pehle stack pe save, return se pehle restore.
  7. $k0, $k1 ($26, $27): kernel. OS ke interrupt handler ke liye reserved; user program inhe use na kare.
  8. $gp ($28): global pointer. Global/static data area ke beech mein point karta hai, taaki global variable ek hi lw (offset ke saath) se mil jaaye.
  9. $sp ($29): stack pointer. Stack ke top (aakhri pushed word) ka address. Stack neeche ki taraf badhta hai.
  10. $fp ($30): frame pointer. Current function ke stack frame ki shuruaat pe fixed rehta hai, jabki $sp function ke beech badal sakta hai. Locals ko fixed offset se dhoondhne mein madad.
  11. $ra ($31): return address. jal isme PC + 4 likhta hai; jr $ra se wapas aate hain.

Diagram kaise padhein: Chaar columns: naam, number, use, saved by. Pehle number column dekho aur ranges yaad karo: 0, 1, 2-3, 4-7, 8-15, 16-23, 24-25, 26-27, 28, 29, 30, 31. Phir "saved by" column: $t aur $a/$v ke saamne "caller", $s ke saamne "CALLEE" (highlighted). Example: $sp ki row = 29, stack pointer, callee.

Caller vs callee, values ke saath:

main has a running total 50 in $s0 and a temporary 7 in $t0. It calls f. Inside, f uses both $s0 and $t0. What does main see after f returns?

  1. $t0 caller-saved hai → f use badal sakta hai (maan lo 99 kar diya) bina wapas kiye.
  2. Agar main ko 7 baad mein chahiye tha, to main ko call se pehle 7 stack pe save karna chahiye tha.
  3. $s0 callee-saved hai → f ne shuru mein 50 stack pe rakha (sw $s0, 0($sp)), apna kaam kiya, aur jr $ra se pehle 50 wapas load kiya (lw $s0, 0($sp)).
  4. Isliye main ko $s0 = 50 milta hai (guaranteed), $t0 kuch bhi ho sakta hai.

Answer: $s0 = 50 (preserved by f); $t0 is not guaranteed (main must save it itself if needed).

Diagram kaise padhein: Left box CPU: PC, HI·LO, 32 registers aur ALU. Right box memory (2³² bytes, har byte ka apna address). Memory upar se neeche: stack (0x7FFFFFFC se neeche badhta hai), free, heap (upar badhta hai), .data (0x10010000), .text (0x00400000, code). Beech ke arrows: data ke liye sirf lw/sw, aur instruction ke liye fetch. Yahi load/store model hai.

Solved example (exam MCQ / match):

Match: $zero, $a0, $t0, $sp, $ra with numbers. After addi $zero, $zero, 5, what is in $zero?

  1. $zero = 0, $a0 = 4 ($a0-$a3 = 4-7 ka pehla), $t0 = 8 ($t0-$t7 = 8-15 ka pehla), $sp = 29, $ra = 31.
  2. $zero mein likhna ignore hota hai → value 0 hi rahegi.

Answer: 0, 4, 8, 29, 31; $zero still contains 0.

Galti mat karna: (1) $t aur $s ke roles ulte mat karna: $s callee-saved. (2) PC ko 32 registers mein mat gin-na. (3) $t8, $t9 = 24, 25 (16-23 nahi, wahan $s hain). (4) Return value $v0 mein, $a0 mein nahi.

Trick: "t = temporary, don't trust it; s = saved, it survives." Numbers ke liye ginti: 0 zero, 1 at, 2 v, 4 a, 8 t, 16 s, 24 t, 26 k, 28 gp, 29 sp, 30 fp, 31 ra (2, 4, 8, 16 = doubling!).

Ek line mein: 32 registers, roles convention se: $zero = 0, $v = jawab, $a = arguments, $t = kachcha kaam (caller bachaye), $s = pakka kaam (callee bachaye), $sp stack, $ra wapsi ka pata.

11.3 R-format (register to register)

Pehle socho: Ek form socho jisme fixed boxes hain: "kaam ka type", "pehla number kahan se", "doosra kahan se", "jawab kahan rakhna". Har form same size ka hai, boxes hamesha same jagah. Clerk (CPU) bina soche har box seedha padh leta hai. add $t0, $s1, $s2 jaise instruction mein teeno cheezein registers hain, isliye iska form "Register format" hai.
Definition: The R-format is used for instructions whose operands are all registers (add, sub, and, or, slt, shifts, jr). Its 32 bits are divided as opcode (6) | rs (5) | rt (5) | rd (5) | shamt (5) | funct (6). The opcode is 0 for all R-type instructions; the funct field selects the operation; rs and rt are the source registers and rd is the destination.
Mushkil shabd, aasaan matlab:
Field
32 bits ka ek hissa jiska ek kaam hai.
opcode (6 bits, bits 31-26)
"Operation code": instruction ka type. 6 bits → 2⁶ = 64 possible. R-type ke liye hamesha 000000.
rs (5 bits, 25-21)
"Register source": pehla input register ka number. 5 bits kyun? 32 registers = 2⁵, to 0 se 31 tak 5 bits mein.
rt (5 bits, 20-16)
"Register target": doosra input register (R-type mein).
rd (5 bits, 15-11)
"Register destination": jahan result likhna hai.
shamt (5 bits, 10-6)
"Shift amount": sirf sll/srl/sra mein; kitni position shift. Baaki sab mein 00000. 5 bits kyun: 32-bit number ko 0 se 31 tak shift karna kaafi.
funct (6 bits, 5-0)
"Function": opcode 0 hai, to asli operation yahi batata hai. add = 100000 (0x20), sub = 100010 (0x22).
Hex
Base 16. 4 bits = 1 hex digit (0000 = 0, 1010 = A, 1111 = F). 32 bits = 8 hex digits.
Kaise kaam karta hai (32 bits kyun aur kaise bante hain):
  1. 3 registers × 5 bits = 15 bits. opcode 6 + funct 6 = 12 bits. shamt 5 bits. Total 15 + 12 + 5 = 32. Poora word bhar gaya.
  2. Kyun fixed 32: har instruction 4 bytes → PC + 4 se agla instruction, aur fields hamesha same jagah → decoder simple (Unit 10).
  3. Assembly order ≠ binary order: assembly mein likhte hain add rd, rs, rt (destination pehle), par binary mein order rs, rt, rd.
  4. Encoding recipe: (a) register naam → number; (b) rs, rt, rd mein sahi jagah rakho; (c) har field binary mein, sahi width (5 bits ke liye aage 0 lagao); (d) 32 bits ko 4-4 ke group mein todo; (e) har group → hex digit.
  5. Shifts: sll rd, rt, shamt: source rt mein jata hai, rs = 00000, shamt = shift amount.

Solved example 1 (full encoding walkthrough):

Encode add $t0, $s1, $s2 in binary and hex.

  1. Format: add = R-type → opcode = 000000, funct = 100000 (0x20).
  2. Assembly add rd, rs, rt se: rd = $t0, rs = $s1, rt = $s2.
  3. Numbers: $t0 = 8 ($t0-$t7 = 8-15 ka pehla). $s1 = 17 ($s0 = 16, to $s1 = 17). $s2 = 18.
  4. 5-bit binary: 17 = 16 + 1 → 10001. 18 = 16 + 2 → 10010. 8 → 01000.
  5. shamt = 0 → 00000 (add shift nahi karta).
  6. Binary order mein rakho (rs, rt, rd):
    opcoders ($s1)rt ($s2)rd ($t0)shamtfunct
    00000010001100100100000000100000
    6 bits55556
  7. Jodo: 00000010001100100100000000100000 (count: 6 + 5 + 5 + 5 + 5 + 6 = 32 bits ✓).
  8. 4-4 ke group: 0000 | 0010 | 0011 | 0010 | 0100 | 0000 | 0010 | 0000.
  9. Hex digits: 0000 = 0, 0010 = 2, 0011 = 3, 0010 = 2, 0100 = 4, 0000 = 0, 0010 = 2, 0000 = 0.
  10. Check (ulta): 0x02324020 ko wapas 6-5-5-5-5-6 mein todo → 0, 17, 18, 8, 0, 0x20 → add $t0, $s1, $s2 ✓.

Answer: 000000 10001 10010 01000 00000 100000 = 0x02324020.

Solved example 2 (decode hex → assembly, class homework):

Decode 0x012A4020.

  1. Har hex digit ko 4 bits mein: 0 = 0000, 1 = 0001, 2 = 0010, A = 1010, 4 = 0100, 0 = 0000, 2 = 0010, 0 = 0000.
  2. Poora: 0000 0001 0010 1010 0100 0000 0010 0000.
  3. Pehle 6 bits (opcode) = 000000 → R-type. To ab 6-5-5-5-5-6 mein todo: 000000 | 01001 | 01010 | 01000 | 00000 | 100000.
  4. funct = 100000 = 0x20 → add.
  5. rs = 01001 = 9 = $t1; rt = 01010 = 10 = $t2; rd = 01000 = 8 = $t0; shamt = 0.
  6. Assembly mein rd pehle: add rd, rs, rt.

Answer: add $t0, $t1, $t2.

Solved example 3 (shift):

Encode sll $t0, $t1, 2.

  1. R-type, funct sll = 000000, opcode 000000.
  2. Shift mein source rt = $t1 = 9 = 01001; rs = 00000 (use nahi hota); rd = $t0 = 8 = 01000; shamt = 2 = 00010.
  3. 000000 00000 01001 01000 00010 000000 → 0000 0000 0000 1001 0100 0000 1000 0000.

Answer: 0x00094080.

Galti mat karna: (1) Binary mein rd ko pehle mat likhna; order rs, rt, rd. (2) R-type ka opcode hamesha 0; operation funct se. (3) 5-bit field mein aage ke 0 mat bhoolna (8 = 01000, sirf 1000 nahi). (4) Shift mein source rs mein nahi, rt mein.

Trick: R-format widths: "6-5-5-5-5-6" (dono kinaare 6, beech mein chaar 5). Field order: "Old Rats Take Dinner Some Food" = opcode, rs, rt, rd, shamt, funct.

Ek line mein: R = op 6 | rs 5 | rt 5 | rd 5 | shamt 5 | funct 6; opcode 0, funct operation batata hai, rd destination hai par binary mein teesre number pe aata hai.

11.4 I-format (immediate, loads, stores, branches)

Pehle socho: Kabhi-kabhi instruction ko register nahi, ek seedha number chahiye: "$sp mein se 8 ghatao", "address $sp + 16 se load karo", "agar barabar hain to 5 instructions aage jao". Ye number instruction ke andar hi likha hota hai (immediate = "turant, instruction ke saath hi"). Teen registers ki jagah do registers + ek 16-bit number: yahi Immediate format hai.
Definition: The I-format is used for instructions with a 16-bit constant: arithmetic/logic immediates (addi, andi, ori, slti, lui), loads and stores (lw, sw) and conditional branches (beq, bne). Its fields are opcode (6) | rs (5) | rt (5) | immediate (16). For addi and lw, rt is the destination; for sw, rt is the data to store; for beq/bne, rs and rt are compared and the immediate is a word offset from PC + 4.
Mushkil shabd, aasaan matlab:
Immediate
Instruction ke andar likha number (constant). addi $t0, $t0, 5 mein 5.
Two's complement (recap Unit 4)
Negative number likhne ka tareeka: positive ke bits ulto (invert) aur 1 jodo. 16 bits mein range −32768 se +32767.
Sign extension
16-bit number ko 32-bit banana uska sign bit (bit 15) upar copy karke. 0xFFFB (−5) → 0xFFFFFFFB (phir bhi −5). 0x0005 → 0x00000005.
Zero extension
Upar ke 16 bits mein hamesha 0 bharna. Sirf andi, ori, xori karte hain.
Base + offset
lw $t1, 16($sp): address = $sp (base register) + 16 (offset). Jaise "gali ka number + ghar number".
Branch offset
beq/bne mein immediate = kitne instructions (words) aage/peeche jaana hai, PC + 4 se gin ke.
Kaise kaam karta hai:
  1. Fields: opcode 6 + rs 5 + rt 5 + immediate 16 = 32 bits.
  2. addi rt, rs, imm: rt ← rs + signext(imm). Yahan rt destination hai (R-type ki tarah rd nahi, kyunki rd ki jagah immediate ne le li).
  3. lw rt, offset(rs): rt ← Memory[rs + signext(offset)]. rs = base, rt = destination.
  4. sw rt, offset(rs): Memory[rs + signext(offset)] ← rt. Yahan rt source (data) hai.
  5. beq rs, rt, label: agar rs == rt to PC ← PC + 4 + signext(imm) × 4, warna PC ← PC + 4.
  6. Sign vs zero extend: addi, lw, sw, beq, bne, slti sign-extend; andi, ori, xori zero-extend; lui rt, imm imm ko upar ke 16 bits mein daalta hai.

Diagram kaise padhein: 32-bit patti chaar dabbon mein: 6 | 5 | 5 | 16. lw $t0, 4($t1): opcode 100011 (lw = 0x23), rs 01001 ($t1, base), rt 01000 ($t0, DEST), immediate 0000 0000 0000 0100 (4). Address = $t1 + 4; wahan ka word $t0 mein. Total 0x8D280004.

Formula: Effective address = rs + signext(imm)
Branch target = (PC + 4) + signext(imm) × 4  ⇔  imm = (target − (PC + 4)) / 4
PC = address of the branch itself; PC + 4 = next instruction; × 4 because the offset counts words (4 bytes each).
Solved example 1 (load, class homework):

Encode lw $t1, 16($sp).

  1. lw = I-type, opcode 0x23 = 100011.
  2. lw rt, offset(rs): rt = $t1 = 9 = 01001; rs = $sp = 29 = 11101 (16 + 8 + 4 + 1 = 29); imm = 16.
  3. 16 in 16 bits = 0000 0000 0001 0000.
  4. Rakho: 100011 | 11101 | 01001 | 0000000000010000.
  5. 4-4 group: 1000 1111 1010 1001 0000 0000 0001 0000 → 8 F A 9 0 0 1 0.

Answer: 0x8FA90010.

Solved example 2 (negative immediate, two's complement):

Encode addi $t0, $s1, -5.

  1. addi opcode = 0x08 = 001000.
  2. rs = $s1 = 17 = 10001 (source); rt = $t0 = 8 = 01000 (destination).
  3. −5 ko 16-bit two's complement mein: +5 = 0000 0000 0000 0101.
  4. Invert (0 ↔ 1): 1111 1111 1111 1010.
  5. +1: 1111 1111 1111 1010 + 1 = 1111 1111 1111 1011 = 0xFFFB.
  6. Check: 0xFFFB = 65531; 65531 − 65536 = −5 ✓.
  7. Rakho: 001000 | 10001 | 01000 | 1111111111111011.
  8. 4-4 group: 0010 0010 0010 1000 1111 1111 1111 1011 → 2 2 2 8 F F F B.

Answer: 0x2228FFFB. (Isi tarah addi $sp, $sp, −8 = 0x23BDFFF8, kyunki −8 = 0xFFF8.)

Solved example 3 (branch, easy, forward):

beq $t0, $t1, Done is at address 0x00400008 and Done is at 0x00400020. Find the immediate and encode it.

  1. PC + 4 = 0x00400008 + 4 = 0x0040000C.
  2. Doori (bytes) = target − (PC + 4) = 0x00400020 − 0x0040000C = 0x14 = 20 bytes (0x20 = 32, 0x0C = 12, 32 − 12 = 20).
  3. Words = 20 / 4 = 5. Isliye imm = 5 = 0000 0000 0000 0101.
  4. beq opcode 000100; rs = $t0 = 01000; rt = $t1 = 01001.
  5. 000100 01000 01001 0000000000000101 → 0001 0001 0000 1001 0000 0000 0000 0101.
  6. Check: 0x0040000C + 5 × 4 = 0x0040000C + 0x14 = 0x00400020 ✓.

Answer: imm = 5; word = 0x11090005.

Solved example 4 (branch, exam-level, backward loop):

A loop ends with bne $t0, $zero, Loop at address 0x00400100; Loop is at 0x004000F0. Find the 16-bit immediate (decimal and hex) and the machine word.

  1. PC + 4 = 0x00400100 + 4 = 0x00400104.
  2. target − (PC + 4) = 0x004000F0 − 0x00400104. Sirf last digits: 0xF0 = 240, 0x104 = 260. 240 − 260 = −20 bytes.
  3. Words = −20 / 4 = −5 (negative = peeche jaana).
  4. −5 in 16 bits = 0xFFFB (example 2 jaisa: 0000...0101 → invert 1111...1010 → +1 → 1111 1111 1111 1011).
  5. bne opcode = 000101; rs = $t0 = 01000; rt = $zero = 00000.
  6. 000101 01000 00000 1111111111111011 → 0001 0101 0000 0000 1111 1111 1111 1011.
  7. Check: 0x00400104 + (−5 × 4) = 0x00400104 − 0x14 = 0x004000F0 ✓.

Answer: imm = −5 = 0xFFFB; word = 0x1500FFFB.

Solved example 5 (decode, hex → assembly):

Decode (a) 0x8D280004 (Lab 11) and (b) 0x2108FFFC (addi).

  1. (a) 8 D 2 8 0 0 0 4 → 1000 1101 0010 1000 0000 0000 0000 0100.
  2. Pehle 6 bits = 100011 = 0x23 = lw → I-type, to 6-5-5-16 mein todo: 100011 | 01001 | 01000 | 0000000000000100.
  3. rs = 01001 = 9 = $t1 (base); rt = 01000 = 8 = $t0 (dest); imm = 4. Likho lw rt, imm(rs) → lw $t0, 4($t1).
  4. (b) 2 1 0 8 F F F C → 0010 0001 0000 1000 1111 1111 1111 1100 → 001000 | 01000 | 01000 | 1111111111111100.
  5. Opcode 001000 = addi; rs = $t0; rt = $t0; imm = 0xFFFC.
  6. 0xFFFC ka bit 15 = 1 → negative. Invert: 0000 0000 0000 0011, +1 = 0000 0000 0000 0100 = 4 → imm = −4.

Answer: (a) lw $t0, 4($t1); (b) addi $t0, $t0, −4.

Galti mat karna: (1) lw mein rt destination hai, source nahi. (2) 0xFFFB ko 65531 mat padhna; sign-extend karke −5. (3) Branch offset PC se nahi, PC + 4 se; aur bytes nahi, words (÷ 4). (4) andi/ori/xori zero-extend karte hain, sign-extend nahi.

Trick: I-format = "6-5-5-16". Branch: "agle se gino, chaar se bhaago" = (target − (PC + 4)) ÷ 4.

Ek line mein: I = op 6 | rs 5 | rt 5 | imm 16; addi/lw mein rt destination, address = rs + signext(imm), branch imm = (target − (PC + 4)) / 4.

11.5 J-format (jumps)

Pehle socho: Branch sirf ±32768 instructions tak ja sakta hai (16-bit offset). Door kisi function pe jaana ho to? Jump instruction ko register ki zaroorat nahi, bas ek bada address chahiye. To opcode ke baad bache saare 26 bits address ko de do. Aur kyunki har instruction ka address 4 ka multiple hai (last 2 bits hamesha 00), un 2 bits ko likhne ki zaroorat hi nahi: 26 bits asal mein 28 bits ka kaam karte hain.
Definition: The J-format is used for the unconditional jumps j (opcode 2) and jal (opcode 3). Its fields are opcode (6) | address (26). The 32-bit target is formed pseudo-directly: target = PC+4[31:28] ‖ address ‖ 00, so a jump can reach any instruction in the current 256 MB region. jal also stores PC + 4 in $ra.
Mushkil shabd, aasaan matlab:
address field (26 bits)
Target ka word number (byte address ÷ 4), bina upar ke 4 bits ke.
‖ (concatenate)
Bits ko saath mein chipkana. 0000 ‖ 11 = 000011.
Pseudo-direct
"Lagbhag seedha" address: 28 bits instruction se, upar ke 4 bits current PC + 4 se.
256 MB region
28 bits = 2²⁸ bytes = 256 MB. Jump sirf usi 256 MB block ke andar ja sakta hai jisme PC + 4 hai.
jr
Jump register: register mein rakhe address pe jao. Ye R-type hai (funct 0x08), J-type nahi.
Kaise kaam karta hai (encode aur target banana):
  1. Opcode: j = 000010, jal = 000011.
  2. Encode: address field = target ÷ 4 (= target >> 2), sirf neeche ke 26 bits rakho.
  3. Decode (CPU kya karta hai): 26-bit field ko 2 baar left shift (× 4) → 28 bits.
  4. Upar ke 4 bits PC + 4 se lo (bits 31-28).
  5. Target = PC+4[31:28] ‖ address ‖ 00 (4 + 26 + 2 = 32 bits).
  6. jal pehle $ra ← PC + 4 likhta hai (wapas aane ka pata), phir jump.
  7. 256 MB se door jaana ho to address register mein load karke jr use karo.

Diagram kaise padhein: Upar 6 | 26 patti: opcode (j = 2, jal = 3) aur 26-bit address. Neeche target banane ki patti: left mein PC+4 ke upar ke 4 bits, beech mein instruction ke 26 bits, right mein "00" (× 4). Example line: j 0x00400018 → field = 0x100006 → word 0x08100006.

Solved example 1 (encode j):

Encode j 0x00400018 and verify the target.

  1. Target binary: 0x00400018 = 0000 0000 0100 0000 0000 0000 0001 1000.
  2. ÷ 4 (do bits right shift): 0x00400018 >> 2 = 0x00100006. (Decimal: 4194328 / 4 = 1048582 = 0x100006.)
  3. 26 bits mein: 00 0001 0000 0000 0000 0000 0110.
  4. Opcode j = 000010. Jodo: 000010 | 00000100000000000000000110.
  5. 4-4 group: 0000 1000 0001 0000 0000 0000 0000 0110 → 0 8 1 0 0 0 0 6.
  6. Verify: PC+4 upar ke 4 bits = 0000 (code 0x004xxxxx mein hai). 0x100006 × 4 = 0x400018. 0000 ‖ ... → 0x00400018 ✓.

Answer: 0x08100006.

Solved example 2 (jal):

Encode jal 0x00400030. If this jal is at address 0x00400020, what goes into $ra?

  1. 0x00400030 >> 2 = 0x0010000C (0x30 / 4 = 0x0C, 0x400000 / 4 = 0x100000).
  2. Opcode jal = 000011. 000011 | 00 0001 0000 0000 0000 0000 1100.
  3. 4-4 group: 0000 1100 0001 0000 0000 0000 0000 1100 = 0x0C10000C.
  4. $ra = PC + 4 = 0x00400020 + 4 = 0x00400024.

Answer: 0x0C10000C; $ra = 0x00400024 (= 4194340 decimal).

Galti mat karna: (1) Field mein poora address mat likhna; pehle ÷ 4. (2) j kisi bhi 32-bit address pe nahi ja sakta, sirf current 256 MB block mein. (3) jr J-format nahi, R-format hai. (4) Class ki "MIPS Encoding Reference" sheet j ko PC-relative dikhati hai (teaching variant); exam mein lecture wala rule (PC+4[31:28] ‖ addr ‖ 00) likho.

Trick: J = "6 + 26". Encode: "÷ 4, upar ke 4 phenko". Decode: "× 4, upar PC ke 4 chipkao".

Ek line mein: J = op 6 | address 26; target = PC+4[31:28] ‖ address ‖ 00 (256 MB region); j = 2, jal = 3 (jal $ra mein PC + 4 bhi rakhta hai).

11.6 RISC-V ka modular ISA

Pehle socho: Pizza order karte waqt base (dough + sauce) fixed hai, toppings tum chunte ho: cheese, olives, paneer. Chhote bachche ke liye sirf base, party ke liye sab toppings. RISC-V aisa hi hai: chhota base ISA (RV32I) + jo extension chahiye woh jodo. Aur MIPS jaisi hi RISC DNA: 32 registers, zero register, fixed 32-bit, load/store.
Definition: RISC-V is an open, royalty-free RISC ISA organised as a small mandatory base integer ISA (RV32I: about 40 instructions, registers x0 to x31 with x0 = 0) plus optional standard extensions: M (multiply/divide), A (atomic), F (single float), D (double float), C (compressed 16-bit), V (vector). It uses six basic formats: R, I, S, B, U, J.
Mushkil shabd, aasaan matlab:
Base ISA (RV32I)
Har RISC-V chip mein zaroori minimum: integer add/sub, logic, load/store, branch, jump. "32" = 32-bit registers, "I" = integer.
Extension
Optional instruction groups. Naam mein letter jodte hain: RV32IMAFD = base + M + A + F + D.
Atomic
Ek operation jo beech mein toot nahi sakta; multicore mein do cores ek hi variable ko ek saath na bigaadein.
S, B, U formats
S = store, B = branch, U = upper immediate (lui jaisa). MIPS mein ye sab I-format mein the.
x0
RISC-V ka $zero: hamesha 0.
Kaise kaam karta hai:
  1. Base RV32I chuno (about 40 instructions): har chip mein.
  2. Zaroorat ke hisaab se letters jodo: microcontroller = RV32IMC; laptop-class = RV64IMAFDC + V.
  3. Formats 6 hain (MIPS ke 3 ki jagah) kyunki store, branch aur upper-immediate ko alag format diye gaye taaki register fields hamesha same bit positions pe rahein (rd hamesha bits 11-7, rs1 bits 19-15, rs2 bits 24-20). Isse hardware register file ko instruction poora decode hone se pehle hi padh sakta hai.
  4. Field order bhi alag: RISC-V R-type = funct7 (7) | rs2 (5) | rs1 (5) | funct3 (3) | rd (5) | opcode (7). Opcode neeche (bits 6-0) aur 7 bits ka; MIPS mein opcode upar (31-26) aur 6 bits.
  5. Immediate: RISC-V I-type mein 12 bits; MIPS I-type mein 16 bits.

Diagram kaise padhein: Beech mein bada gola RV32I (base, about 40 instructions). Chaaron taraf chhe chhote gole: M (multiply/divide), A (atomic), F (single float), D (double float), C (compressed 16-bit), V (vector). Har gola base se line se juda hai: "pick your letters, get your ISA". Neeche: RV32IMAFD = base + M + A + F + D.

Solved example (write the answer like this, 4 marks):

Explain RISC-V's modular ISA and compare it with MIPS32 (five points).

  1. Modular: mandatory base RV32I (about 40 integer instructions, x0 to x31, x0 = 0) plus optional extensions M, A, F, D, C, V; a chip implements only what it needs, e.g. RV32IMAFD.
  2. Draw D11.6a.
  3. Comparison: both 32 registers with a hardwired zero; both fixed 32-bit load/store RISC; MIPS has 3 formats, RISC-V 6 (R, I, S, B, U, J) with register fields in fixed positions; RISC-V adds 16-bit compressed instructions (C); MIPS proprietary, RISC-V open and royalty-free.

Answer: base + extensions model, and the five-row comparison table.

Galti mat karna: RISC-V ke 3 formats nahi, 6. Har RISC-V chip floating point nahi karti (sirf F/D ke saath). RISC-V proprietary nahi hai.
Ek line mein: RISC-V = MIPS jaisa RISC, par open aur modular: base RV32I + M A F D C V, aur 6 formats jisme register fields hamesha same jagah.

11.E1 Extra (Lab 11): MIPS assembly toolkit

Pehle socho: Instructions to aa gaye, par asli program chalane ke liye aur cheezein chahiye: data kahan rakhein (directives), screen pe kaise print karein (syscall), aur kuch shortcuts (pseudo-instructions) jo assembler khud asli instructions mein badal de. Ye lab ka "toolkit" hai. syscall hi bahar ki duniya (keyboard, screen) ki khidki hai.
Definition: An assembler directive (.data, .text, .word, .asciiz, .space, .globl) tells the assembler how to lay out the program and data; it is not executed. A pseudo-instruction (li, la, move, blt, bge, nop) is a convenience instruction that the assembler expands into one or more real instructions, using $at if needed. A syscall requests an operating-system service selected by the code in $v0, with arguments in $a0 and $a1.
Mushkil shabd, aasaan matlab:
.data / .text
.data ke neeche variables (0x10010000 se), .text ke neeche code (0x00400000 se).
.word / .asciiz / .space n
.word 10 = ek 4-byte number. .asciiz "Hi" = string + end mein 0 byte. .space 400 = 400 bytes khaali jagah (100 words).
.globl main
main label ko bahar (simulator) ko dikhana, taaki program wahan se shuru ho.
la vs lw
la $t0, x = x ka address lao. lw $t1, x = x ki value lao.
HI / LO
mult ka 64-bit result: upar ke 32 bits HI mein, neeche ke LO mein. div: LO = quotient (bhaagfal), HI = remainder (shesh).
sll / srl / sra
Shift left logical (× 2ⁿ), shift right logical (left se 0 bharo), shift right arithmetic (left se sign bit copy karo, negative number negative hi rahe).
Alignment
lw/sw ka address 4 ka multiple hona chahiye (0, 4, 8). 2 pe lw = error.
Endianness
4-byte word ke bytes memory mein kis order mein. Big-endian: bada (most significant) byte pehle. Little-endian: chhota byte pehle.
Kaise kaam karta hai (syscall ka 3-step pattern):
  1. li $v0, code: kaunsi service chahiye.
  2. Argument set karo: $a0 mein number (print int) ya string ka address (print string).
  3. syscall likho. Read int ke baad answer $v0 mein aata hai, turant move karke kahin aur rakh lo (agla syscall $v0 badal dega).

Solved example 1 (HI/LO, Lab question):

After div $t0, $t1 with $t0 = 17 and $t1 = 5, which instruction gets the remainder, and what are HI and LO? What about −17 ÷ 5?

  1. 17 ÷ 5: 5 × 3 = 15, 17 − 15 = 2. Quotient 3, remainder 2.
  2. Rule: LO = quotient = 3, HI = remainder = 2.
  3. Remainder chahiye → mfhi (HI se nikaalo).
  4. −17 ÷ 5: MIPS zero ki taraf kaatta hai → quotient = −3; remainder = −17 − (−3 × 5) = −17 + 15 = −2.

Answer: mfhi; LO = 3, HI = 2. For −17 ÷ 5: LO = −3, HI = −2.

Solved example 2 (shifts, logic, mult):

(a) $t0 = −16. Find sll, srl, sra by 2. (b) 0xCA AND/OR/XOR 0x0F. (c) 100000 × 100000: HI and LO?

  1. (a) −16 = 0xFFFFFFF0. sll 2 → × 4 = −64. srl 2 → left se 0 aate hain → 0x3FFFFFFC = 1073741820 (bada positive). sra 2 → sign bit (1) copy → −16 / 4 = −4.
  2. (b) 0xCA = 1100 1010, 0x0F = 0000 1111. AND = 0000 1010 = 0x0A. OR = 1100 1111 = 0xCF. XOR = 1100 0101 = 0xC5. NOR = NOT(OR) → low byte 0011 0000 = 0x30 (32 bits mein 0xFFFFFF30).
  3. (c) 100000 × 100000 = 10¹⁰ = 0x2540BE400 (34 bits, 32 mein fit nahi). Upar wala hissa HI = 0x2 = 2; neeche ke 32 bits LO = 0x540BE400 = 1410065408.

Answer: (a) −64, 1073741820, −4; (b) 0x0A, 0xCF, 0xC5; (c) HI = 2, LO = 1410065408.

Diagram kaise padhein: Word 0x12345678 address B pe. Upar ki row big-endian: B+0 = 12, B+1 = 34, B+2 = 56, B+3 = 78 (bada byte pehle). Neeche little-endian: B+0 = 78, B+1 = 56, B+2 = 34, B+3 = 12 (chhota byte pehle). lb $t1, 0($t0) big pe 0x12, little pe 0x78 deta hai. Neeche alignment rule: lw/sw ko 4 ka multiple address chahiye.

Solved example 3 (bug hunt, Lab 11):

x is .word 42. A student writes la $a0, x then print-integer and gets a large number like 268500992. Why? Fix it.

  1. la x ka address deta hai (0x10010000 = 268500992), value nahi.
  2. Value 42 chahiye → lw $a0, x.
  3. Saath mein li $v0, 1 zaroor ho, warna syscall ko pata nahi kaunsi service.

Answer: replace la with lw $a0, x (la = address, lw = value).

Galti mat karna: (1) syscall se pehle li $v0, n bhoolna. (2) Doosra integer padhne se pehle pehla $v0 se copy na karna. (3) div ke baad mflo/mfhi ulta: mflo = quotient, mfhi = remainder. (4) lw $t1, 2($t0) = unaligned (2 multiple of 4 nahi). (5) Encoding question mein blt jaise pseudo ko asli instruction maan lena.

Trick: syscall codes: "1 print int, 4 print string, 5 read int, 10 exit" = "1-4 likho, 5 padho, 10 pe bye". div: "LO = Lena (quotient), HI = Hisaab baaki (remainder)".

Ek line mein: Directives layout batate hain, pseudo-instructions assembler ke shortcuts hain, syscall = li $v0 → $a0 → syscall; div mein LO quotient, HI remainder; la address, lw value.
