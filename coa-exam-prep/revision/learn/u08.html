Unit 8 · Memory: SRAM vs DRAM & the Memory Stack

Is unit ki kahani: Unit 7 ka register file flip-flops se bana hai: bahut tez, par sirf 32 words. Ek photo hi lakhon bytes ki hoti hai, OS billions bytes ka. Itni badi memory flip-flops se banana bahut mehenga hai. Is unit mein do sasti memory cells seekhenge: SRAM (6 transistor, tez, cache ke liye) aur DRAM (1 transistor + 1 capacitor, sasti aur dense, main memory ke liye). Phir dekhenge ki inhe memory hierarchy mein kaise layer karte hain taaki computer "upar jitna tez, neeche jitna bada" lage. Unit 9 mein yahi memory CPU se bus ke through judegi (Von Neumann / Harvard).

8.1 Register Files; the Need for Bigger Memory

Pehle socho: Padhai karte waqt teen jagah cheezein hoti hain: desk pe kaagaz (turant haath mein, par 2–3 hi aate hain), bookshelf (thoda uthna padta hai, 50 kitaabein), library (jaana padta hai, lakhon kitaabein). Sab kuch desk pe rakhna possible nahi: desk itni badi banegi hi nahi, aur bahut mehengi hogi. Computer mein bhi yahi hai: register file = desk, cache (SRAM) = bookshelf, main memory (DRAM) = library. Koi bhi ek memory tez + badi + sasti teeno ek saath nahi ho sakti.
Definition: Register files are fast but tiny because each bit is stored in a flip-flop (about 20 or more transistors per bit). Large memories therefore use denser storage cells, SRAM (6 transistors per bit) and DRAM (1 transistor + 1 capacitor per bit), trading speed for capacity. Since no single technology is fast, large and cheap at the same time, computers combine several of them in a memory hierarchy.
Mushkil shabd, aasaan matlab:
transistor
Chip ka sabse chhota electronic switch (ON/OFF). Gate, latch, memory cell sab inhi se bante hain. Ek bit mein jitne kam transistors, utni zyada bits ek chip mein aayengi.
transistors per bit
Ek bit store karne mein kitne transistors lage. Flip-flop: 20+. SRAM: 6. DRAM: 1 (plus ek capacitor).
density
Ek mm² chip area mein kitni bits. Kam transistors per bit = zyada density = sasti memory.
cost per bit
Ek bit store karne ka kharcha. Area zyada = kharcha zyada.
volatile
Power gayi to data gaya. Flip-flop, SRAM, DRAM teeno volatile hain.
word / address line
Memory ek lambi list hai; har khaane (word) ka ek number (address). Address bhejne wale wires = address lines.
Kaise kaam karta hai (problem step by step):
  1. Register file: 32 registers × 32 bits = 1024 bits = sirf 128 bytes. ALU ke bilkul paas, ek cycle se kam mein access.
  2. Har bit ek flip-flop hai, aur ek flip-flop ≈ 20+ transistors.
  3. Agar 1 GB (≈ 8 × 10⁹ bits) flip-flops se banayein: 8 × 10⁹ × 20 = 1.6 × 10¹¹ transistors sirf memory mein. Chip itni badi aur mehengi ho jayegi ki banana practical nahi.
  4. Isliye chhoti cells chahiye: SRAM (6T) caches ke liye, DRAM (1T1C) main memory ke liye.
  5. Core tension: fast memory = chhoti aur mehengi; badi memory = slow aur sasti. Solution: sab ko layer karo (memory hierarchy, 8.5).
Formula: Address lines = log₂(number of words)  ·  Capacity = 2^(address lines) × word width  ·  Transistors = bits × transistors per bit
Same rule as the register file (32 registers → 5 bits). Memory with 2ⁿ words needs n address lines.
Solved example 1 (transistors per bit):

How many transistors are needed to store 1 KB (8192 bits) using flip-flops (20 T/bit), SRAM and DRAM?

  1. 1 KB = 1024 bytes × 8 = 8192 bits.
  2. Flip-flops: 8192 × 20 = 163,840 transistors.
  3. SRAM: 8192 × 6 = 49,152 transistors.
  4. DRAM: 8192 × 1 = 8,192 transistors (+ 8,192 capacitors).

Answer: FF ≈ 163,840; SRAM 49,152; DRAM 8,192 (+ 8,192 capacitors). Isliye badi memory DRAM se banti hai.

Solved example 2 (address lines):

A memory has 64 K words of 8 bits each (64 K = 65,536). How many address lines does it need, and what is its capacity? How many address lines does a 1 M × 8 memory need?

  1. 65,536 = 2¹⁶ (2¹⁰ = 1024, 2⁶ = 64, 1024 × 64 = 65,536). Isliye address lines = 16.
  2. Capacity = 65,536 words × 8 bits = 65,536 bytes = 64 KB.
  3. 1 M = 2²⁰ = 1,048,576 words → 20 address lines, 8 data lines, capacity 1 MB.

Answer: 16 address lines, 64 KB; 1 M × 8 needs 20 address lines.

Galti mat karna: (1) "Registers DRAM se bane hain" galat hai: registers flip-flops hain, caches SRAM, main memory DRAM. (2) "Register file aur bada kar do" free nahi hai: area, power aur access time teeno badhte hain. (3) Address lines width se nahi, words ki ginti se aate hain.

Trick: Transistor count yaad rakho: 20 → 6 → 1 (flip-flop → SRAM → DRAM). Number jitna chhota, memory utni badi aur slow.

Ek line mein: Flip-flop (20+ T/bit) bahut mehenga hai, isliye badi memory SRAM (6T) aur DRAM (1T1C) se banti hai; koi memory tez + badi + sasti ek saath nahi, isliye hierarchy.

8.2 SRAM: 6T Cell Structure and Behaviour

Pehle socho: Ek see-saw socho jisko do log dono taraf se pakad ke rakhte hain: ek side neeche hai to woh neeche hi rahegi, kyunki dono log usse lagatar dhakel rahe hain. Thoda hila bhi to turant wapas apni jagah. SRAM ka bit aise hi "zinda" tarike se pakda rehta hai (active storage): do inverters ek doosre ko lagatar sahi value dete rehte hain. Isliye jab tak bijli hai, data rehta hai, refresh ki zarurat nahi. Isiliye naam Static RAM.
Definition: SRAM (Static RAM) stores each bit in a bistable latch made of two cross-coupled inverters (4 transistors) plus two access transistors that connect the latch to the bit lines when the word line is high, giving a 6-transistor (6T) cell. It keeps its data without refresh as long as power is applied, and its read is non-destructive.
Mushkil shabd, aasaan matlab:
inverter
NOT gate: 1 andar → 0 bahar. CMOS mein 2 transistors (1 PMOS + 1 NMOS).
cross-coupled inverters
Do inverters ek gol ghere mein: pehle ka output doosre ka input, doosre ka output pehle ka input. Q = 1 → doosra inverter Q' = 0 deta hai → pehla inverter Q = 1 hi rakhta hai. Ye loop khud ko sahi rakhta hai.
bistable latch
Circuit jiski do stable halat hain (Q = 1 ya Q = 0) aur woh kisi ek mein tiki rehti hai. Unit 5 ka basic bistable yahi hai.
access transistor (M5, M6)
Darwaze: ON hon to latch bit lines se jud jaata hai, OFF hon to latch akela band rehta hai.
word line (WL)
Row select wire. WL = 1 → us row ke saare cells ke darwaze khul jaate hain. Matlab "ye cell chuno".
bit lines (BL, BL')
Data wires: BL pe bit, BL' pe uska ulta (complement). Inhi se data andar-bahar jaata hai.
pre-charge
Read se pehle dono bit lines ko 1 (high voltage) pe charge karke tayaar rakhna.
sense amplifier
Ek sensitive circuit jo dono bit lines ka bahut chhota voltage farak pakad ke use poora 0 ya 1 bana deta hai.
non-destructive read
Padhne se stored value nahi mit-ti.

Diagram kaise padhein: Left aur right mein do khadi lines BL aur BL' (data wires). Upar aadi line WL (highlighted). Beech ke box mein do inverters ek loop mein: left node Q, right node Q'. Q se BL tak M5, Q' se BL' tak M6, dono ke gate WL se jude. Count: inverters 2 × 2 = 4 transistors + M5 + M6 = 6. Trace: WL = 0 → M5, M6 OFF → latch akela, value hold. WL = 1 → Q BL se aur Q' BL' se jud jaate hain.

Kaise kaam karta hai:
  1. Hold (kuch nahi ho raha): WL = 0, darwaze band. Maan lo Q = 1, to doosra inverter Q' = 0 banata hai, jo pehle inverter ko Q = 1 rakhne pe majboor karta hai. Thoda leakage hua to power supply turant theek kar deti hai.
  2. Read step 1: dono bit lines BL aur BL' ko high pe pre-charge karo.
  3. Read step 2: WL = 1 karo, M5 aur M6 ON.
  4. Read step 3: jis side 0 stored hai (yahan Q' = 0), woh apni bit line (BL') ko thoda neeche kheenchti hai. BL high hi rehti hai.
  5. Read step 4: sense amplifier dekhta hai "BL' gira, BL nahi" → output 1. Latch apni value khud pakde hue hai, isliye read non-destructive.
  6. Write step 1: nayi value bit lines pe zor se daalo: 0 likhna hai to BL = 0, BL' = 1.
  7. Write step 2: WL = 1 karo.
  8. Write step 3: bit line drivers latch se zyada strong hain, to Q ko 0 aur Q' ko 1 kar dete hain (overpower).
  9. Write step 4: WL = 0. Latch palat chuka hai aur ab nayi value hold karta hai.
Solved example (write the answer like this):

Draw the 6T SRAM cell and explain how a stored bit is read. Why is the read non-destructive? (5 marks)

  1. Draw D8.2a: two cross-coupled inverters (4 transistors) holding Q and Q'; access transistors M5, M6 connect Q to BL and Q' to BL'; their gates are driven by the word line WL.
  2. Read: both bit lines are pre-charged high; WL is raised; the side storing 0 pulls its bit line slightly low; a sense amplifier detects which bit line dropped and outputs the bit.
  3. Write: the bit lines are driven to the new value and its complement; WL is raised; the strong drivers overpower the latch, which flips and holds the new value.
  4. The read is non-destructive because the latch actively drives its nodes from the power supply, so it keeps its value while being read.
  5. SRAM is static (no refresh), fast (a few ns) but needs 6 transistors per bit, so it is used for caches and register files.

Answer: diagram + 4 read steps + 4 write steps + "active latch, so non-destructive".

Scorecard: very fast (a few ns) · no refresh · non-destructive read · low density (6T/bit) · expensive · constant leakage (static) power → caches L1/L2/L3, register files, buffers.
Galti mat karna: (1) "SRAM ko refresh chahiye" galat: refresh DRAM ko chahiye. (2) Latch mein 6 transistors bolna: latch = 4, baaki 2 access transistors hain (M5, M6). (3) "SRAM read data mita deta hai" galat: woh DRAM hai. (4) Word line pe data nahi chalta, data bit lines pe chalta hai; WL sirf select karti hai.

Trick: 6T = 4 + 2: "4 pakadte hain (latch), 2 darwaza kholte hain (access)". Word line = Which cell; Bit line = Bit ka data.

Ek line mein: SRAM 6T = 2 cross-coupled inverters (4T, bit ko zinda pakadte hain) + 2 access transistors (WL se khulte hain); read = pre-charge, WL, sense amp, non-destructive; refresh nahi, tez, mehenga → cache.

8.3 DRAM: 1T1C Cell, Refresh, Destructive Read

Pehle socho: Ek chhed wali baalti socho. Baalti mein paani = 1, khaali = 0. Problem: paani dheere-dheere tapakta rehta hai, to thodi der mein "1" bhi "0" jaisa dikhne lagega. Isliye har thodi der mein koi aake baalti check karta hai aur bhar deta hai: ye refresh hai. Aur baalti itni chhoti hai ki paani dekhne ke liye use bade bartan (bit line) mein undelna padta hai, to baalti khaali ho jaati hai: ye destructive read hai, isliye padhne ke baad wapas bharna padta hai. Fayda: baalti bahut chhoti aur sasti hai, to lakhon-karodon rakh sakte ho. Yahi DRAM hai: passive storage, bahut dense, par refresh aur write-back chahiye.
Definition: DRAM (Dynamic RAM) stores each bit as charge on a tiny capacitor that is connected to the bit line through one access transistor (a 1T1C cell). Because the charge leaks away, every row must be refreshed periodically (about every 64 ms), and because reading shares the capacitor's charge with the bit line, the read is destructive and the value must be written back.
Mushkil shabd, aasaan matlab:
capacitor
Charge (bijli) store karne wala chhota "bucket". Charged = 1, empty = 0.
1T1C
1 transistor (darwaza) + 1 capacitor (bucket) per bit. Sabse chhota memory cell.
leakage
Capacitor ka charge dheere-dheere apne aap nikal jaana, jaise baalti se paani tapakna.
retention time
Kitni der tak charge itna rehta hai ki 1 pehchana ja sake. Class mein: 64 ms ke andar refresh karna hai.
refresh
Row ko padh ke turant wapas poori value likhna, taaki charge phir se full ho jaaye. Har row lagbhag har 64 ms mein.
row
DRAM cells ek grid mein hote hain; ek word line ek poori row ko ek saath kholti hai. Refresh row-by-row hota hai.
charge sharing
Capacitor ko bit line se jodne pe uska charge bit line mein bant jaata hai. Bit line badi hai, to voltage bas thoda sa badalta hai, aur capacitor khaali ho jaata hai.
sense amplifier
Bit line ke us chhote se badlaav ko pakad ke poora 0 ya 1 bana deta hai, aur wahi value wapas cell mein likh deta hai.
write-back
Read ke baad value cell mein wapas likhna (kyunki read ne use mita diya).
µs, ms, ns
1 ms = 1000 µs; 1 µs = 1000 ns. 64 ms = 64,000 µs.

Diagram kaise padhein: Left mein khadi line = bit line (BL). Upar aadi line = word line (WL). Beech mein ek transistor: ek taraf BL, doosri taraf capacitor (do parallel plates), capacitor ka doosra sira ground. Transistor ka gate WL se juda. Trace: WL = 1 → transistor ON → capacitor BL se juda. Write 1: BL ko high karo → capacitor charge. Write 0: BL low → capacitor khaali.

Kaise kaam karta hai:
  1. Store: WL = 0, transistor OFF, capacitor akela. Charge hai to 1, nahi to 0.
  2. Write: BL ko desired value pe rakho, WL = 1. Capacitor charge (1) ya discharge (0) ho jaata hai. WL = 0.
  3. Leakage: capacitor ka charge dheere-dheere nikalta hai. Class curve: 0 ms pe full, 20 ms pe kam hota hua, 50 ms pe weak, 64 ms tak sense threshold ke neeche (lost).
  4. Refresh: DRAM controller har row ko ~64 ms ke andar padh ke wapas likhta hai. Us waqt woh hissa memory busy rehta hai (performance + power cost). Isiliye naam Dynamic.
  5. Read step 1 (access): WL = 1. Capacitor ka charge bit line ke saath share hota hai.
  6. Read step 2 (tiny signal): bit line ka voltage bahut thoda sa upar ya neeche hota hai. Capacitor ab apni value kho chuka hai.
  7. Read step 3 (sense amp): sense amplifier us chhote farak ko poora 0 ya 1 bana deta hai.
  8. Read step 4 (write-back): wahi poori value turant capacitor mein wapas likh di jaati hai. Har DRAM read asal mein read + rewrite hai.
  9. Speed: 50–100 ns (sense time + row open karna + pre-charge), SRAM se 10 guna se zyada slow. Use: main memory (8/16/32 GB RAM stick), GPU memory (GDDR).

Diagram kaise padhein: X-axis = time (ms), Y-axis = capacitor charge. Dashed curve = bina refresh ke charge girta jaata hai aur "sense threshold" line ke neeche chala jaata hai (data lost). Solid sawtooth = har 64 ms pe refresh charge ko wapas full kar deta hai, isliye charge kabhi threshold ke neeche nahi jaata.

Formula: Per-row refresh interval = retention time ÷ number of rows  ·  Refresh busy fraction = time per row refresh ÷ per-row interval (= rows × time per row ÷ retention time)
64 ms = 64,000 µs. 8192 rows → 64,000 ÷ 8192 = 7.8125 µs.
Solved example 1 (class homework):

A DRAM with 8192 rows must refresh every row within 64 ms. What is the interval between row refreshes? Repeat for 4096 and 16384 rows.

  1. ms ko µs mein badlo: 64 ms × 1000 = 64,000 µs.
  2. 8192 rows: 64,000 ÷ 8192. 8192 × 8 = 65,536 (thoda zyada), 8192 × 7.8 = 63,897.6, 8192 × 7.8125 = 64,000. To 7.8125 µs ≈ 7.8 µs.
  3. 4096 rows (aadhi rows → double time): 64,000 ÷ 4096 = 15.625 µs ≈ 15.6 µs.
  4. 16384 rows (double rows → aadha time): 64,000 ÷ 16384 = 3.90625 µs ≈ 3.91 µs.

Answer: 7.8 µs (8192), 15.6 µs (4096), 3.91 µs (16384).

Solved example 2 (exam-level, refresh overhead):

A DRAM bank has 8192 rows, a 64 ms retention window, and each row refresh blocks the bank for 50 ns. What fraction of time is spent refreshing? Repeat for 60 ns per row (mock 2).

  1. Per-row interval = 7.8125 µs = 7812.5 ns (× 1000).
  2. Har 7812.5 ns mein 50 ns busy. Fraction = 50 ÷ 7812.5 = 0.0064.
  3. Percent: 0.0064 × 100 = 0.64 %.
  4. 60 ns: 60 ÷ 7812.5 = 0.00768 → 0.77 %.
  5. Check doosre tarike se: 8192 × 60 ns = 491,520 ns = 0.49 ms busy har 64 ms mein; 0.49 ÷ 64 = 0.0077 → 0.77 %.

Answer: 0.64 % (50 ns), 0.77 % (60 ns).

Galti mat karna: (1) "Transistor bit store karta hai" galat: capacitor karta hai, transistor sirf darwaza hai. (2) DRAM read ke baad write-back bhool jaana. (3) Poori chip ka refresh period (64 ms) aur per-row interval (7.8 µs) mix karna. (4) ms ko µs mein badalna bhoolna (× 1000).

Trick: DRAM = Dynamic = Drains (charge tapakta hai) → refresh. "64 ÷ 8192 = 7.8" seedha yaad kar lo.

Ek line mein: DRAM = 1T1C (capacitor mein charge = bit); charge leak hota hai → har row ~64 ms mein refresh (8192 rows → 7.8 µs per row); read charge baant deta hai → sense amp + write-back; dense, sasta, 50–100 ns → main memory.

8.4 SRAM vs DRAM Comparison

Pehle socho: Dono mein "better" koi nahi. SRAM ek bodyguard jaisa hai jo bit ko lagatar pakad ke rakhta hai: tez aur bharosemand, par mehenga aur jagah leta hai. DRAM ek baalti hai: sasti, chhoti, karodon rakh lo, par bharte rehna padta hai. Har farak ek hi baat se aata hai: SRAM active storage (latch), DRAM passive storage (charge).
Definition: SRAM stores a bit actively in a 6-transistor latch, which makes it fast, refresh-free and non-destructive to read but low in density and expensive; DRAM stores a bit passively as charge in a 1T1C cell, which makes it dense and cheap but slower, and it needs refresh and a write-back after every read. SRAM trades density for speed; DRAM trades speed for density.

passive storage
Value bas charge ke roop mein padi hai, koi use pakad ke nahi rakhta (DRAM capacitor).
GDDR
Graphics card ki DRAM (GPU memory).

Solved example 1 (class exit ticket):

Give three reasons why SRAM is faster than DRAM.

  1. SRAM ka latch bit lines ko actively drive karta hai: strong signal, jaldi sense hota hai. DRAM ka chhota capacitor sirf thoda sa signal deta hai.
  2. SRAM mein destructive read / write-back nahi, aur refresh ki rukawat nahi.
  3. SRAM chhote arrays mein CPU chip pe hi (same logic process) banti hai; DRAM chip ke bahar hai aur har access mein row activation + pre-charge chahiye.

Answer: active drive, no write-back/refresh, on-chip small arrays (DRAM off-chip with row activation and pre-charge).

Solved example 2 (match type + density):

Match with SRAM or DRAM: needs refresh; six transistors per bit; used for L1 cache; destructive read; higher density. If DRAM is about 6× denser, how many DRAM bits fit in the area of 100 SRAM bits?

  1. Needs refresh → DRAM (capacitor leaks).
  2. Six transistors → SRAM.
  3. L1 cache → SRAM (fast).
  4. Destructive read → DRAM.
  5. Higher density → DRAM.
  6. Density: 100 × 6 = 600.

Answer: DRAM, SRAM, SRAM, DRAM, DRAM; 600 bits.

Galti mat karna: (1) "DRAM non-volatile hai" galat: dono power ke bina data kho dete hain (non-volatile = flash/SSD). (2) Uses ulta likhna: cache = SRAM, main memory / RAM stick = DRAM. (3) "SRAM better hai" likhna: dono alag kaam ke liye hain.

Trick: SRAM = Speed, Stable, Small (cache). DRAM = Dense, Dynamic (refresh), Destructive read.

Ek line mein: SRAM = 6T active latch (tez, refresh nahi, mehenga, cache); DRAM = 1T1C passive charge (dense ≈ 6×, sasta, refresh + write-back, main memory); har farak active vs passive se aata hai.

8.5 Memory Hierarchy and the Memory Wall

Pehle socho: Tum desk pe padh rahe ho. Jo abhi chahiye woh desk pe (registers), thoda pehle wali kitaabein drawer mein (L1), shelf pe (L2/L3), library mein (DRAM), aur purana saamaan godown mein (disk). Tum 90 % baar desk/drawer se hi kaam chala lete ho kyunki jo abhi use kiya woh phir use karoge, aur jo kitaab nikali uske paas wale page bhi padhoge. Isse poora system upar jitna tez aur neeche jitna bada lagta hai. Problem (memory wall): CPU har saal bahut tez hota gaya, par library (DRAM) tak jaane ka time lagbhag waisa hi raha.
Definition: The memory hierarchy arranges storage in levels (registers, L1, L2, L3 caches, main memory, disk) from small, fast and expensive per bit to large, slow and cheap per bit; it works because programs show locality, so most accesses are served by the fast upper levels. The memory wall is the growing gap between processor speed and DRAM latency, which makes memory access, not computation, the main limit on performance.
Mushkil shabd, aasaan matlab:
cache
CPU ke paas chhoti SRAM memory jo haal hi mein use hua data rakhti hai. L1 sabse chhota/tez, phir L2, L3.
latency
Maangne se milne tak ka time. L1 ≈ 1 ns, DRAM ≈ 50–100 ns.
temporal locality
"Time" wali: jo data abhi use hua, woh jaldi phir use hoga. Loop counter i har iteration mein.
spatial locality
"Space/jagah" wali: jo address use hua, uske paas wale address jaldi use honge. Array ke elements a[0], a[1], a[2] ek ke baad ek.
block (cache line)
Cache ek byte nahi, paas-paas ke bytes ka poora tukda (jaise 64 bytes) ek saath laata hai. Isse spatial locality ka fayda.
hit / miss
Hit = data cache mein mil gaya (tez). Miss = nahi mila, neeche wale level se laana pada (slow).
miss rate / miss penalty
Miss rate = kitne % access miss hue. Miss penalty = miss pe neeche se laane mein extra time.
AMAT
Average Memory Access Time: average mein ek access kitna time leta hai.
memory wall
CPU aur DRAM ki speed ka badhta farak, latency ka farak (capacity ka nahi).

Diagram kaise padhein: Pyramid ka sabse patla upar wala hissa = registers (sabse chhote, sabse tez). Neeche jaate hue har band chauda: L1, L2, L3 (SRAM), main memory (DRAM), sabse neeche SSD/HDD (TBs). Right mein har level ka latency aur size likha hai. Left ka arrow: neeche jaao to bada, slow, sasta per bit. Upar = tez + chhota + mehenga.

Kaise kaam karta hai:
  1. CPU ko ek data chahiye. Pehle L1 cache dekhta hai.
  2. Mil gaya (hit) → ≈ 1 ns mein kaam ho gaya.
  3. Nahi mila (miss) → L2 dekho, phir L3, phir DRAM. Jahan mila, wahan se data (poora block) upar wale levels mein copy ho jaata hai.
  4. Har level apne neeche wale level ka ek chhota hissa (subset) rakhta hai.
  5. Temporal locality ka fayda: abhi laya data cache mein rehta hai, agli baar hit. Example: 
    sum = 0;
for (i = 0; i < 1000; i++)
    sum = sum + a[i];
    sum aur i har iteration mein phir use hote hain → temporal. Loop ke instructions bhi baar-baar chalte hain → temporal.
  6. Spatial locality ka fayda: a[0] laane pe poora block (a[0] se a[15], agar 64-byte block aur 4-byte int) aa jaata hai, to a[1] se a[15] sab hit. Instructions bhi ek ke baad ek address pe hain → spatial.
  7. Result: zyadatar accesses upar ke tez levels se, isliye average time chhota.
Formula: AMAT = hit time + miss rate × miss penalty
hit time = fast level ka time; miss rate = fraction (5 % = 0.05); miss penalty = neeche se laane ka extra time.
Solved example 1 (AMAT):

L1 hit time 1 ns, miss rate 5 %, miss penalty 80 ns. Find AMAT. What if the miss rate is halved?

  1. 5 % = 0.05.
  2. 0.05 × 80 = 4 ns.
  3. AMAT = 1 + 4 = 5 ns.
  4. Miss rate 2.5 % = 0.025: 0.025 × 80 = 2; AMAT = 1 + 2 = 3 ns.

Answer: 5 ns; halving the miss rate gives 3 ns (isliye cache itna important hai).

Solved example 2 (exam-level):

Hit time 2 ns, miss rate 10 %, miss penalty 100 ns. AMAT? Also order L2, DRAM, registers, L1, SSD from fastest to slowest.

  1. 10 % = 0.1. 0.1 × 100 = 10 ns.
  2. AMAT = 2 + 10 = 12 ns.
  3. Order: registers (flip-flops, ALU ke paas) → L1 (chhota number = CPU ke paas) → L2 → DRAM → SSD.

Answer: 12 ns; registers, L1, L2, DRAM, SSD.

Diagram kaise padhein: X-axis = year (1980 se 2010), Y-axis = relative performance (log scale: har step 10 guna). Upar ki steep line = Processor (≈ 50 % per year, 1986–2004). Neeche ki lagbhag flat line = DRAM latency (≈ 7 % per year). Dono ke beech ka double arrow = "the gap" = memory wall. Gap har saal badhta gaya.

Memory wall step by step:
  1. CPU performance ≈ 50 % per year badha (1986–2004); DRAM latency sirf ≈ 7 % per year sudhri.
  2. Rough idea: 10 saal mein CPU 1.5¹⁰ ≈ 58 guna, DRAM 1.07¹⁰ ≈ 2 guna. Farak ≈ 29 guna badh gaya.
  3. Aaj: 3 GHz CPU ka ek cycle = 0.33 ns. DRAM access 100 ns = 100 × 3 = 300 cycles ka intezaar.
  4. Matlab ALU khaali baitha rehta hai, memory hi limit hai (Wulf & McKee, 1995).
  5. Responses: deep multi-level caches, prefetching (data pehle se le aana), out-of-order execution (wait karte hue doosre instructions chalana), wider/faster DRAM interfaces, 3-D stacked memory (HBM).
Solved example 3 (write the answer like this):

Draw the memory hierarchy and explain locality and the memory wall. (5 marks)

  1. Draw D8.5a: registers, L1, L2, L3 (SRAM), main memory (DRAM), SSD/HDD, with latency and size; going down, levels are larger, slower and cheaper per bit.
  2. The hierarchy works because of locality. Temporal locality: recently used data is reused soon (loop variables). Spatial locality: nearby addresses are used soon (arrays, sequential code); caches fetch whole blocks.
  3. So most accesses hit the small fast levels; AMAT = hit time + miss rate × miss penalty.
  4. Memory wall: processor performance grew about 50 % per year while DRAM latency improved about 7 % per year, so a DRAM access now costs hundreds of CPU cycles.
  5. Remedies: multi-level caches, prefetching, out-of-order execution, wider/faster DRAM interfaces, HBM.

Answer: pyramid + two types of locality with examples + 50 % vs 7 % gap + remedies.

Galti mat karna: (1) L2 ko L1 ke upar rakhna: chhota number = CPU ke zyada paas = zyada tez. (2) "Memory wall = memory capacity ruk gayi" galat: ye latency (speed) ka gap hai. (3) Temporal aur spatial ulta karna: temporal = same data phir se, spatial = paas wala data. (4) Registers hata dena memory wall ka solution nahi; registers sabse tez level hain.

Trick: Temporal = Time = "phir se wahi". Spatial = Space = "padosi". Hierarchy = desk → drawer → shelf → library → godown (registers → L1 → L2/L3 → DRAM → disk).

Ek line mein: Registers → L1 → L2 → L3 → DRAM → SSD/HDD (neeche bada, slow, sasta); locality (temporal + spatial) se zyadatar access upar se serve hote hain; AMAT = hit + miss rate × penalty; memory wall = CPU 50 %/yr vs DRAM 7 %/yr ka latency gap.
