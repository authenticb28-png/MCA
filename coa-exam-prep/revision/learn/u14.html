Unit 14 · Pipelining

Is unit ki kahani: Unit 13 ka single-cycle processor ek instruction poora khatam karke hi agla shuru karta hai, aur har cycle lw jitna lamba (800 ps) hai. Is unit mein idea hai: kaam ko 5 stages mein kaato aur alag-alag instructions ko alag stages mein ek saath chalao, jaise laundry ya factory assembly line. Clock chhota ho jaata hai aur har cycle ek instruction khatam hota hai. Kuch formulas (cycles, speedup) aur pipeline diagram yahan se aate hain. Jab instructions ek doosre pe depend karte hain to problem aati hai: woh hazards hain (Unit 15). (Is unit ki class slides nahi thi; content Patterson & Hennessy se hai.)

14.1–14.2 The Problem with Single-Cycle, and the Laundry Analogy

Pehle socho: Hostel mein 4 dosto ke kapde (loads A, B, C, D) dhone hain. Har load: wash 30 min, dry 30 min, fold 30 min, stash (almirah mein rakhna) 30 min. Bewakoof tareeka: A ka poora kaam (2 ghante) khatam, phir B shuru. Smart tareeka: A washer se nikal ke dryer mein gaya, usi waqt B washer mein daal do. Machine khaali kyun baithe? Ek load ko utna hi time lagta hai, lekin saare loads bahut jaldi khatam ho jaate hain. CPU mein: single-cycle mein jab ALU kaam kar raha hai, instruction memory khaali baithi hai. Pipelining us khaali machine ko agle instruction ke liye use karta hai.
Definition: Pipelining is an implementation technique in which the execution of an instruction is divided into stages and multiple instructions are overlapped, each in a different stage, so that (once the pipeline is full) one instruction completes every clock cycle. It improves throughput (instructions completed per unit time), not the latency of a single instruction.
Mushkil shabd, aasaan matlab:
stage
Kaam ka ek tukda jo ek hardware hissa karta hai. Laundry mein wash / dry / fold / stash; CPU mein IF / ID / EX / MEM / WB.
latency
Ek item ko shuru se khatam hone mein kitna time. Ek load ki latency = 2 ghante, pipelining ke baad bhi 2 ghante.
throughput
Har unit time mein kitne items khatam hote hain. Pipelined laundry mein har 30 min ek load ready.
fill time
Shuru mein pipeline bharne ka time: pehla load akela 4 stages se guzarta hai, tab tak kuch khatam nahi hota.
idle
Khaali baitha hua. Single-cycle mein ALU kaam kare to instruction memory idle.
Kaise kaam karta hai (laundry, 4 loads, 4 stages × 30 min):
  1. Sequential: har load 4 × 30 = 120 min = 2 h. 4 loads × 2 h = 8 h.
  2. Pipelined: 30-min ke "slots" mein socho. Slot 1: A wash. Slot 2: A dry, B wash. Slot 3: A fold, B dry, C wash. Slot 4: A stash, B fold, C dry, D wash (sab machines busy). Slot 5: B stash, C fold, D dry. Slot 6: C stash, D fold. Slot 7: D stash.
  3. Total slots = 7 = (4 stages + 4 loads − 1). Time = 7 × 30 min = 210 min = 3.5 h.
  4. Har load ki latency abhi bhi 2 h (A: slot 1 se 4). Lekin pipeline full hone ke baad har 30 min ek load khatam hota hai.
  5. Speedup = 8 / 3.5 ≈ 2.29. Bahut saare loads ho to speedup → 4 (= number of stages).
  6. CPU pe lagao: single-cycle mein cycle = 800 ps (lw). Datapath ko 5 stages (har ek ≈ 200 ps) mein kaato, beech mein registers lagao. Clock = 200 ps, aur full pipeline mein har 200 ps ek instruction khatam.

Laundry ke rules jo CPU pe bhi lagte hain: (1) sab stages same time lein to best; sabse slow stage speed decide karta hai (dryer 60 min ho to har 60 min ek load). (2) Stages ke beech kaam rakhne ki jagah chahiye (CPU mein pipeline registers). (3) Problem tab aati hai jab ek load ko kuch chahiye jo pichhla load abhi khatam nahi kiya (CPU mein hazards).

Diagram kaise padhein: Upar wala chart sequential hai: 16 rangeen boxes ek ke baad ek, seedhi seedhi (staircase), 8 h tak. Neeche wala pipelined hai: har load ki row ek slot right khiski hui, boxes overlap karte hain, 3.5 h pe khatam. Har rang ek stage (legend: Wash, Dry, Fold, Stash). Kisi bhi ek vertical line (time) pe neeche wale chart mein dekho: zyada se zyada 4 alag rang = 4 machines ek saath busy.

Solved example 1 (easy):

Laundry with 4 stages of 30 min each. How long do 6 loads take (a) sequentially, (b) pipelined? (c) Speedup?

  1. (a) Ek load = 4 × 30 = 120 min = 2 h. 6 loads = 6 × 2 = 12 h.
  2. (b) Slots = stages + loads − 1 = 4 + 6 − 1 = 9. Time = 9 × 30 min = 270 min = 4.5 h.
  3. (c) Speedup = 12 / 4.5 = 2.67.

Answer: 12 h sequential, 4.5 h pipelined, speedup ≈ 2.67.

Solved example 2:

The dryer takes 60 min, the other three stages 30 min. Once the pipeline is full, how often does a load finish?

  1. Washer har 30 min ek load de sakta hai, lekin dryer har load pe 60 min leta hai.
  2. Loads dryer ke aage line mein ruk jaayenge. Pipeline ki speed = sabse slow stage.

Answer: one load every 60 min (slowest stage sets the pace).

Solved example 3 (write the answer like this):

Why is a single-cycle processor inefficient, and how does pipelining help? (3 marks)

  1. In a single-cycle processor the clock period is fixed by the slowest instruction (lw, 800 ps); shorter instructions (R-type 600, beq 500 ps) waste the rest of the cycle.
  2. Each unit is busy only for part of the cycle; e.g. the instruction memory is idle while the ALU works.
  3. Pipelining divides the datapath into stages separated by pipeline registers and overlaps instructions, so all units work at once. The clock period becomes one stage (about 200 ps) and, once full, one instruction completes per cycle.

Answer: wasted time + idle units → split into stages and overlap → shorter clock, CPI ≈ 1, higher throughput.

Galti mat karna: (1) "Pipelining se ek instruction jaldi khatam hota hai" galat hai: latency same rehti hai (ya thodi badhti hai). Throughput badhta hai. (2) Pipelined time = n × stage time mat likho; shuru ka fill time (k − 1) bhoolna common galti hai.

Trick: "Machine kabhi khaali na baithe." Pipelining = har machine ko har slot mein koi na koi kaam.

Ek line mein: Single-cycle mein units idle aur chhote instructions time waste karte hain; pipelining kaam ko stages mein kaat ke instructions overlap karta hai: latency same, throughput zyada.

14.3 The 5-Stage MIPS Pipeline and Pipeline Registers

Pehle socho: Factory assembly line mein har station ke beech ek tray hota hai. Station 1 apna kaam tray mein rakhta hai; bell bajti hai (clock); tray agle station ko milta hai aur station 1 naya kaam shuru karta hai. Bina tray ke, station 1 ka naya kaam purane ko overwrite kar dega. CPU mein ye trays hi pipeline registers hain.
Definition: The classic MIPS pipeline has five stages: IF (instruction fetch), ID (instruction decode and register read), EX (execute or address calculation), MEM (data memory access) and WB (write back). Between consecutive stages are pipeline registers, named IF/ID, ID/EX, EX/MEM, MEM/WB, which hold everything a stage produced (data, register numbers and control signals) for the next stage.
Mushkil shabd, aasaan matlab:
pipeline register
Do stages ke beech ka register (tray). Naam dono stages ka: IF/ID = IF aur ID ke beech. Total 4.
control travels with the instruction
Control signals ID mein bante hain, phir instruction ke saath tray se tray aage jaate hain. EX wale (RegDst, ALUOp, ALUSrc) EX mein use, MEM wale (Branch, MemRead, MemWrite) MEM mein, WB wale (MemtoReg, RegWrite) WB mein.
write first half, read second half
Register file cycle ke pehle aadhe mein likhta hai, doosre aadhe mein padhta hai. Isliye WB mein likha value usi cycle ID wala instruction padh leta hai.
Kaise kaam karta hai (har stage ka kaam):

  1. Har clock edge pe har stage apna result aage wale pipeline register mein daalta hai.
  2. Usi edge pe har stage peeche wale register se naya instruction le leta hai.
  3. Isliye kisi bhi cycle mein 5 alag instructions 5 alag stages mein hote hain.
  4. Destination register number (rd / rt) bhi ID/EX → EX/MEM → MEM/WB mein saath chalta hai, kyunki WB tak IF/ID mein koi aur instruction aa chuka hota hai.
  5. Clock period = sabse slow stage (+ pipeline register ka thoda overhead).

MIPS pipeline ke liye aasaan kyun hai (Lecture 10): (1) saare instructions 32-bit fixed length: IF bina decode kiye agla fetch kar sakta hai; (2) kam formats, rs / rt hamesha same bits mein: decode ke saath hi registers padh lo; (3) memory sirf lw / sw: address EX mein, access MEM mein; (4) memory access aligned.

Diagram kaise padhein: Upar IF, ID, EX, MEM, WB labels batate hain kaunsa hissa kaunsa stage. Neele lambe patle bars pipeline registers hain (IF/ID, ID/EX, EX/MEM, MEM/WB). Left se right: PC + instruction memory (IF) → register file + sign-extend (ID) → ALU (EX) → data memory (MEM) → MUX (WB). Orange wire WB se wapas left register file tak jaata hai: result likhne ke liye (ye ek hi wire right-to-left chalti hai). Trace lw: CC1 IF, CC2 ID (base register padha), CC3 EX (address), CC4 MEM (data), CC5 WB (register mein).

Solved example 1 (MCQ type):

(a) In which stage does lw compute its memory address? (b) How many pipeline registers are there? (c) Why must the destination register number travel to WB?

  1. (a) Address = base + offset ek addition hai → ALU → EX. Memory padhna MEM mein.
  2. (b) Stages ke beech ki jagah: 5 stages → 4 gaps → IF/ID, ID/EX, EX/MEM, MEM/WB = 4.
  3. (c) Jab lw WB mein pahunchta hai, IF/ID mein 3 instructions baad wala instruction hai. Uske rd / rt bits galat honge. Isliye lw ka apna destination number tray-dar-tray saath chalna chahiye.

Answer: (a) EX, (b) 4, (c) because each pipeline register holds a different instruction by then.

Solved example 2 (write the answer like this, 5 marks):

Draw the 5-stage MIPS pipeline with its pipeline registers and explain each stage.

  1. Draw D14.3a: PC/IMem | IF/ID | Reg file + sign-extend | ID/EX | ALU | EX/MEM | Data memory | MEM/WB | write-back MUX, with the write-back wire returning to the register file.
  2. IF: fetch instruction at PC, PC ← PC + 4. ID: decode, read rs and rt, sign-extend, generate control. EX: ALU operation or address calculation, branch compare. MEM: lw reads / sw writes data memory. WB: write the result to rd or rt.
  3. Pipeline registers hold data, register numbers and control for the next stage; control is generated in ID and carried along.
  4. Register file is written in the first half and read in the second half of a cycle.

Answer: 5 stages IF ID EX MEM WB + 4 pipeline registers IF/ID, ID/EX, EX/MEM, MEM/WB.

Galti mat karna: Pipeline register ka naam ek stage pe mat rakho ("ID register" galat), naam hai IF/ID (do stages ke beech). Aur WB ka wire right se left jaata hai, ise diagram mein bhoolna mat.

Trick: "I Do EXercise, MEMorize, Write Back" = IF, ID, EX, MEM, WB.

Ek line mein: IF → ID → EX → MEM → WB, beech mein 4 trays (IF/ID, ID/EX, EX/MEM, MEM/WB) jo data, register number aur control aage le jaate hain.

14.4 Pipeline Diagrams (stages × cycles)

Pehle socho: Railway timetable ek table hai: rows mein trains, columns mein time, aur cell mein station ka naam. Pipeline diagram bilkul yahi hai: rows = instructions, columns = clock cycles, cell = us cycle mein instruction kis stage mein hai. Isse turant dikhta hai kitne cycles lage aur kaun kab kahan tha.
Definition: A multi-cycle pipeline diagram shows instructions as rows and clock cycles (CC1, CC2, CC3) as columns; each cell names the stage the instruction occupies in that cycle. In an ideal pipeline instruction i enters IF in cycle i, and n instructions in a k-stage pipeline take k + (n − 1) cycles.
Mushkil shabd, aasaan matlab:
CC (clock cycle)
CC1 = pehla cycle, CC5 = paanchwa.
staircase / diagonal
Har agli row ek column right khiski: kyunki har cycle ek naya instruction aata hai.
in flight
Abhi pipeline ke andar (shuru ho gaya, khatam nahi hua).
independent instructions
Jo ek doosre ka result use nahi karte, isliye koi rukawat (stall) nahi.
Kaise banayein:
  1. Left mein instructions likho, upar CC1, CC2 likho.
  2. Instruction 1: CC1 IF, CC2 ID, CC3 EX, CC4 MEM, CC5 WB.
  3. Instruction 2: ek column right: CC2 se shuru.
  4. Instruction i: CC i mein IF. Stage s (IF = 1, ID = 2, EX = 3, MEM = 4, WB = 5) cycle i + s − 1 mein.
  5. Last instruction (n) ka WB = cycle n + 5 − 1 = n + 4. Yahi total cycles.
  6. Kisi column ko upar se neeche padho: us cycle mein kaun kis stage mein.

CC5 column dekho: WB, MEM, EX, ID, IF. Paanchon stages busy, paanch instructions in flight. Ye "pipeline full" ka matlab hai.

Diagram kaise padhein: Upar CC1 to CC9. Har row ek instruction, rangeen boxes us cycle ki stage. Har rang ek stage hai (IF ek rang, ID doosra). Rows ek ek column right khiskti hain (staircase). Last box CC9 mein (add $14 ka WB) = total 9 cycles.

Formula: Total cycles (no stalls) = k + (n − 1) · instruction i, stage s → cycle i + s − 1
k = number of stages (5), n = number of instructions. Pehle instruction ko k cycles, phir har naye instruction ke liye +1.
Solved example 1 (easy):

How many cycles do 5 independent instructions take in a 5-stage pipeline? And 100 instructions?

  1. k = 5, n = 5: 5 + (5 − 1) = 5 + 4 = 9 cycles.
  2. k = 5, n = 100: 5 + (100 − 1) = 5 + 99 = 104 cycles.
  3. Check: non-pipelined 5-stage machine pe 100 × 5 = 500 cycles lagte.

Answer: 9 cycles and 104 cycles.

Solved example 2:

In the diagram above, which stage is the third instruction (add $12) in during CC5? Which instruction is in MEM during CC6?

  1. add $12 = instruction 3 → IF in CC3. CC5 − CC3 = 2 stages aage: IF (3) → ID (4) → EX (5). Formula: s = 5 − 3 + 1 = 3 = EX.
  2. CC6 mein MEM (s = 4): i = 6 − 4 + 1 = 3 → instruction 3 = add $12.

Answer: add $12 is in EX during CC5; add $12 is in MEM during CC6.

Galti mat karna: (1) Doosre instruction ko bhi CC1 se shuru karna: har instruction ek cycle baad aata hai. (2) Total = 5 × n likhna: woh non-pipelined hai. Pipelined = 5 + n − 1.
Ek line mein: Rows = instructions, columns = cycles, har row ek column right; n instructions, k stages → k + n − 1 cycles.

14.5 Throughput, Latency and Speedup (numericals)

Pehle socho: Pipelining kitna fayda deta hai? Laundry mein 4 stages the to max 4 guna. Lekin agar ek machine (dryer) slow ho, ya har tray ko shift karne mein thoda time lage, to fayda kam. Exam mein yahi numericals aate hain: non-pipelined time, pipelined time, speedup, aur "speedup exactly k kyun nahi".
Definition: Latency is the time one instruction takes from IF to WB. Throughput is the number of instructions completed per unit time. Speedup = (execution time without pipelining) / (execution time with pipelining). With k perfectly balanced stages, no register overhead and no hazards, speedup approaches k for a large number of instructions (ideal speedup).
Mushkil shabd, aasaan matlab:
balanced stages
Saare stages ka delay barabar (jaise sab 200 ps). Unbalanced = alag alag (250, 350, 150).
register overhead
Har pipeline register ka extra time (setup + clock-to-Q). Jaise 20 ps. Har cycle mein jud jaata hai.
cycle time (tcycle)
Pipelined clock period = sabse slow stage + overhead. Clock sabke liye ek hai, to slowest stage ke hisaab se.
T (non-pipelined time per instruction)
Saare stages ka total delay (bina registers ke). Ek instruction ek baar mein poora.
Kaise solve karein (har numerical mein yahi 6 steps):
  1. T = saare stage delays ka sum (non-pipelined, ek instruction).
  2. Non-pipelined total = n × T.
  3. tcycle = max(stage delays) + register overhead.
  4. Pipelined total = (k + n − 1) × tcycle.
  5. Speedup = non-pipelined / pipelined. Bahut bade n ke liye speedup ≈ T / tcycle.
  6. Latency (pipelined) = k × tcycle; throughput ≈ 1 instruction per tcycle.
Formula:
Non-pipelined time = n × T, where T = sum of stage delays
Pipelined time = (k + n − 1) × tcycle, where tcycle = slowest stage + register overhead
Speedup = n × T / [(k + n − 1) × tcycle] · balanced, no overhead: Speedup = n·k / (k + n − 1) → k
Latency = k × tcycle · Throughput = 1 / tcycle (pipeline full)
n = instructions, k = stages.
Solved example 1 (equal stages, easy):

A 5-stage pipeline has each stage 2 ns (ignore register overhead). For 100 instructions find the non-pipelined time, pipelined time, speedup, latency and throughput.

  1. T = 5 × 2 = 10 ns.
  2. Non-pipelined = n × T = 100 × 10 = 1000 ns.
  3. tcycle = max = 2 ns (sab barabar).
  4. Pipelined = (5 + 100 − 1) × 2 = 104 × 2 = 208 ns.
  5. Speedup = 1000 / 208 = 4.81 (ideal 5; n bada ho to aur 5 ke paas).
  6. Latency = 5 × 2 = 10 ns (same as non-pipelined). Throughput = 1 instruction / 2 ns = 0.5 × 109 instructions/s = 500 million per second.

Answer: 1000 ns vs 208 ns, speedup ≈ 4.81, latency 10 ns, throughput 1 per 2 ns.

Solved example 2 (unequal stages + overhead, exam-level):

Stage delays are 250, 350, 150, 300, 200 ps and each pipeline register adds 20 ps. For 1000 instructions find the non-pipelined time, pipelined time, speedup, the limit of speedup for very many instructions, and the latency of one instruction.

  1. T = 250 + 350 + 150 + 300 + 200 = 1250 ps.
  2. Non-pipelined = 1000 × 1250 = 1,250,000 ps = 1.25 µs.
  3. Slowest stage = 350 ps. tcycle = 350 + 20 = 370 ps.
  4. Pipelined = (5 + 1000 − 1) × 370 = 1004 × 370 = 371,480 ps ≈ 0.371 µs.
  5. Speedup = 1,250,000 / 371,480 = 3.36.
  6. Very many instructions: speedup → T / tcycle = 1250 / 370 = 3.38 (5 nahi, kyunki stages unbalanced + overhead).
  7. Latency = 5 × 370 = 1850 ps: non-pipelined ke 1250 ps se zyada! Har instruction ko har stage mein 370 ps milta hai chahe use 150 chahiye.

Answer: 1.25 µs vs 0.371 µs; speedup ≈ 3.36 (limit 3.38); latency 1850 ps.

Solved example 3 (P&H textbook, single-cycle vs pipelined):

Stage delays 200 (IF), 100 (ID), 200 (EX), 200 (MEM), 100 (WB) ps. Compare 3 lw instructions on the single-cycle (800 ps) and pipelined machine. What is the speedup for a very long program? Why not 5?

  1. Single-cycle clock = 200 + 100 + 200 + 200 + 100 = 800 ps. 3 lw = 3 × 800 = 2400 ps.
  2. Pipelined clock = slowest stage = 200 ps. 3 lw = (5 + 3 − 1) × 200 = 7 × 200 = 1400 ps.
  3. Long program: speedup → 800 / 200 = 4.
  4. Not 5 because the stages are unbalanced (ID and WB need only 100 ps but get 200 ps). Register overhead and hazards reduce it further.
  5. One lw latency = 5 × 200 = 1000 ps (more than 800!), but one lw finishes every 200 ps.

Answer: 2400 ps vs 1400 ps; long-run speedup 4, not 5, because of unbalanced stages.

Galti mat karna: (1) Clock = average stage delay lena: clock = maximum (+ overhead). (2) Overhead sirf ek baar jodna: har cycle mein judta hai. (3) "Latency kam hoti hai" likhna: latency same ya zyada; throughput badhta hai.

Trick: "Slowest + overhead = cycle; k + n − 1 cycles; ideal speedup = k."

Ek line mein: Pipelined time = (k + n − 1) × (slowest stage + overhead); speedup → k sirf balanced, bina overhead, bina hazards; latency nahi ghatti, throughput badhta hai.

14.6 Hazards Preview

Pehle socho: Laundry mein teen tarah ki problem ho sakti hai: (1) washer-dryer combo ek hi machine hai, do loads ek saath nahi (resource ki kami); (2) load B ka "fold" tabhi ho sakta hai jab A ka dupatta bhi aa jaaye jo abhi dryer mein hai (data ka intezaar); (3) pata nahi agla load kaunsa daalna hai jab tak koi decide na kare (decision ka intezaar). CPU mein yahi teen hazards hain.
Definition: A hazard is a situation in which the next instruction cannot execute in its planned clock cycle. Structural hazard: two instructions need the same hardware resource in the same cycle. Data hazard: an instruction needs a result that an earlier instruction has not yet produced. Control hazard: the next instruction to fetch depends on a branch whose outcome is not yet known.
Mushkil shabd, aasaan matlab:
stall / bubble
Pipeline mein ek cycle ka "khaali" slot, instruction rok diya gaya. Detail Unit 15.
forwarding
Result ko register file mein likhe jaane se pehle hi seedha agle instruction ke ALU tak bhej dena. Detail Unit 15.
split I / D memory
Instruction aur data ke liye alag memories (alag L1 caches), isliye IF aur MEM ek saath chal sakte hain.
Teen hazards, ek ek example ke saath:
  1. Structural: agar ek hi memory ho to CC4 mein lw ka MEM aur 4th instruction ka IF dono memory maangenge. MIPS fix: alag instruction aur data memory; register file pehle aadhe mein likhe, doosre mein padhe.
  2. Data: add $s0, $t0, $t1 phir sub $t2, $s0, $t3. sub ko $s0 CC3 mein (ID) chahiye, lekin add use CC5 (WB) mein likhega. Fix: forwarding; load ke baad 1 stall.
  3. Control: beq ke baad kaunsa instruction fetch karein? Branch ka faisla baad mein hota hai, IF tab tak ruk nahi sakta. Fix: stall, predict (not-taken), delayed branch.
  4. RISC ka load/store rule hazards ko pakadna aasaan banata hai: sirf lw / sw memory chhoote hain, aur sab registers ID mein padhte hain, WB mein likhte hain.
Solved example (write the answer like this, 3 marks):

Name and explain the three types of pipeline hazards with one example each.

  1. Structural: two instructions need the same resource in the same cycle, e.g. a single memory needed by lw (MEM) and a later instruction (IF) in CC4. Solved by separate instruction and data memories.
  2. Data: an operand is not ready, e.g. add $s0, $t0, $t1 followed by sub $t2, $s0, $t3. Solved by forwarding (and stalls).
  3. Control: the next PC depends on an unresolved branch, e.g. beq. Solved by stalling, branch prediction or delayed branch.

Answer: structural (resource), data (operand not ready), control (branch decides next PC).

Galti mat karna: Branch ki problem ko data hazard mat bolo, woh control hazard hai. Aur MIPS mein single-memory structural hazard nahi hota, kyunki memories alag hain.

Trick: S-D-C = Seat, Data, Choice: seat (hardware) nahi, data nahi aaya, choice (branch) nahi pata.

Ek line mein: Hazard = agla instruction apne time pe nahi chal sakta; structural (hardware), data (value ready nahi), control (branch).
