Unit 9 · Von Neumann vs Harvard Architecture

Is unit ki kahani: Units 1–8 mein humne saare parts bana liye: gates, ALU, flip-flops, register file, SRAM, DRAM. Ab sawaal hai ki inhe jodein kaise? CPU aur memory ke beech kitne raaste (buses) hon, aur program kahan rakha jaaye? Do classic blueprints hain: Von Neumann (ek memory, ek bus: simple, par bus pe traffic jam = bottleneck) aur Harvard (instructions aur data ke liye alag memory, alag bus). Aaj ke CPUs dono ka mix hain: modified Harvard (andar split L1 cache, bahar ek DRAM). Unit 10 mein dekhenge ki CPU ko kaunsi instructions di jaati hain (CISC vs RISC).

9.1 From Gates to a Complete Machine

Pehle socho: Ek sheher socho. Factories (CPU) saamaan banati hain, godown (memory) saamaan rakhte hain, bandargah / port (I/O) bahar ki duniya se len-den karta hai, aur sadkein (bus) sabko jodti hain. Factory kitni bhi tez ho, agar sadak ek hi hai aur patli hai to sheher dheema chalega. Isliye parts ke saath-saath unka jodne ka tarika (organisation) bhi speed decide karta hai.
Definition: A complete computer consists of a CPU (compute), memory (store programs and data), I/O (communicate with the outside world) and a bus (a set of address, data and control lines that connects them). Computer organisation is the study of how exactly these parts are connected, for example how many buses join the CPU and memory.
Mushkil shabd, aasaan matlab:
CPU
Central Processing Unit: control unit + ALU + registers. Hisaab karta hai aur sabko chalata hai.
I/O
Input/Output: keyboard, screen, disk, network. Computer ka bahar se baat karne ka tarika.
bus
Wires ka group jo parts ko jodta hai. Teen hisse: address lines (kahan: "address 0x40"), data lines (kya: "value 42"), control lines (kya karna hai: "read" ya "write").
computer organisation
Hardware ko kaise joda gaya hai (kitni buses, kitni memories). ISA (instruction set) isse alag hai: woh programmer ko dikhne wala "contract" hai.
Kaise kaam karta hai:
  1. Units 1–8: gates → adder/ALU → flip-flops → registers/register file → SRAM/DRAM. Saare parts tayaar.
  2. CPU ko memory se ek word padhna hai: address lines pe address daalta hai (0x40).
  3. Control line pe "read" signal deta hai.
  4. Memory data lines pe value bhejti hai (0x2A), CPU le leta hai.
  5. I/O devices bhi isi tarah bus se jude hain.
  6. Design ka sawaal: CPU aur memory ke beech ek bus ho ya do? Jawab se do blueprints bante hain: Von Neumann (ek) aur Harvard (do).

Diagram kaise padhein: Upar teen box: CPU (compute), MEMORY (store), I/O (talk to world). Neeche ek lambi patti = BUS (address + data + control). Har box se bus tak do arrows (upar-neeche) = do-taraf ka len-den. Exam mein yahi 4 blocks aur unka kaam likhna hai.

Solved example (write the answer like this):

Draw the block diagram of a basic computer system and explain the role of each component. (3 marks)

  1. Draw D9.1a: CPU, memory and I/O connected to one system bus.
  2. CPU: executes instructions; it contains the control unit, ALU and registers.
  3. Memory: stores the program and the data.
  4. I/O: connects the computer to keyboards, screens, disks and networks.
  5. Bus: carries address, data and control signals between these units.

Answer: diagram + one line for each of CPU, memory, I/O, bus.

Galti mat karna: "Bus sirf data le jaati hai" galat hai: bus mein address + data + control teeno lines hoti hain. Aur "kitni buses" wala sawaal computer organisation ka hai, ISA ka nahi.

Trick: C-M-I-B = "Compute, Memorise, Interact, Bridge". Bus ki lines: "A-D-C": Address (kahan), Data (kya), Control (kaise).

Ek line mein: Computer = CPU + memory + I/O + bus (address, data, control); organisation = in parts ko kaise jodte hain, khaaskar kitni buses.

9.2 Von Neumann Architecture: Structure and History

Pehle socho: 1945 se pehle computer ek hi kaam ke liye wire kiye jaate the. Naya program chalana hai? Plugs aur wires hath se badlo, din lag jaate the. Jaise ek washing machine jo sirf ek tarah ka wash kar sake, doosra wash chahiye to machine kholo. Von Neumann ka idea: program ko bhi numbers bana ke usi memory mein rakh do jahan data hai. Naya program = memory mein naye numbers load karo. Machine wahi, kaam naya. Yahin se "software" paida hua.
Definition: The Von Neumann (stored-program) architecture keeps program instructions and data, both encoded as numbers, in the same memory, and moves both over a single shared bus between the memory and the CPU. Its four classic components are the control unit, the ALU, the memory and I/O. It was described by John von Neumann in the "First Draft of a Report on the EDVAC" (1945).
Mushkil shabd, aasaan matlab:
stored-program concept
Program instructions ko numbers bana ke memory mein data ke saath rakhna. add r3, r1, r2 bhi memory mein bas ek 32-bit number hai.
control unit
CPU ka "manager": memory se instruction laata (fetch) hai, samajhta (decode) hai, aur baaki parts ko signals deta hai. Ye ek FSM hai (Unit 7).
ALU
Arithmetic Logic Unit: add, subtract, compare, AND/OR karta hai.
unified memory
Ek hi memory, ek hi address space: address 0x00 pe instruction ho sakti hai, 0x40 pe data.
PC (program counter)
Register jo batata hai agli instruction kis address pe hai.
IR (instruction register)
Register jisme abhi chal rahi instruction rakhi hai.
EDVAC
Ek early computer jiske liye von Neumann ne 1945 mein ye design likha.
JIT compiler
Just-In-Time: program chalte-chalte naya machine code banata hai (Java, JavaScript). Ye tabhi possible hai jab code = data.

Diagram kaise padhein: Ek hi memory ki table: Address, Contents, Kind. 0x00, 0x04, 0x08 pe teen instructions (lw, add, sw), highlighted. 0x40 aur 0x44 pe data words (0x0000002A = 42 decimal, aur 0). Dhyan do: instructions aur data same memory mein side-by-side hain. Program ka matlab: 0x40 se 42 load karo (r1), r1 + r2 karo (r3), r3 ko 0x44 pe store karo.

Kaise kaam karta hai (ek instruction ka safar):
  1. PC = 0x00. Control unit bus pe address 0x00 bhejta hai: instruction fetch. Memory "lw r1, 0x40" bhejti hai, woh IR mein jaati hai.
  2. Control unit decode karta hai: "memory se load karna hai".
  3. Ab wahi bus pe address 0x40 jaata hai: data access. Memory 0x2A bhejti hai, woh r1 mein.
  4. PC = 0x04. Next instruction "add r3, r1, r2" fetch hoti hai (bus phir use hui). ALU jodta hai.
  5. PC = 0x08. "sw r3, 0x44" fetch, phir wahi bus se r3 ki value 0x44 pe likhi jaati hai.
  6. Har kadam pe instructions aur data ek hi bus pe baari-baari chalte hain. Yahi design ki pehchaan hai (aur limit bhi, 9.3).

Diagram kaise padhein: Left mein CPU box: andar Control unit, ALU, Registers, PC · IR. Right mein ek MEMORY box "(one, unified)" jisme instructions aur data dono hain. Beech mein highlighted do arrows = SINGLE SHARED BUS (address + data + control). Neeche I/O bhi isi bus se juda. Ek hi raasta, isliye ek waqt pe ek hi transfer.

"Programs are data" ka matlab aur asar:
  1. Compiler aur assembler program ko data ki tarah likhte hain (output file = numbers).
  2. OS program ko chalane ke liye bas uske bytes memory mein copy karta hai (loader).
  3. JIT compiler chalte waqt naya code banata hai.
  4. Self-modifying code possible hai, aur yahi kai security attacks (code injection) ki jad hai: attacker data ki jagah code ghusa deta hai.
History aur kyun jeeta: John von Neumann ne 1945 mein "First Draft of a Report on the EDVAC" mein likha (Eckert, Mauchly aur Turing ke kaam pe based). Jeeta kyunki (1) simplicity: ek memory, ek bus, sasta; (2) generality: wahi hardware koi bhi program chala sakta hai. Lagbhag har general-purpose computer isi model pe chalta hai.
Solved example (write the answer like this):

Explain the stored-program concept and draw the Von Neumann architecture, naming its four classic components. (5 marks)

  1. Stored-program concept: instructions are encoded as numbers and stored in the same memory as data; to run a different program, different numbers are loaded, so no rewiring is needed (memory map D9.2b).
  2. Draw D9.2a: CPU (control unit, ALU, registers, PC, IR), one unified memory, one shared bus, I/O on the bus.
  3. Control unit fetches and decodes instructions and directs all other units; ALU performs arithmetic and logic; memory holds program and data with uniform addressing; I/O communicates with the outside world.
  4. Described by John von Neumann in the First Draft of a Report on the EDVAC (1945).
  5. Advantages: simplicity (one memory, one bus) and generality (any program on the same hardware).

Answer: stored-program idea + diagram + four components with roles + 1945 EDVAC + simplicity/generality.

Galti mat karna: (1) "Von Neumann mein instruction aur data ki alag memory hai" galat: woh Harvard hai. Von Neumann = ek memory, ek bus. (2) Stored-program idea ko Harvard Mark I ka bolna galat: Mark I mein program paper tape pe tha, memory mein nahi. (3) Four components mein "bus" ya "registers" likhna: classic chaar = Control unit, ALU, Memory, I/O.

Trick: Von Neumann = "ek ghar, ek darwaza": code aur data ek hi ghar (memory) mein, ek hi darwaze (bus) se aate-jaate hain. Chaar parts: "CAMI" = Control, ALU, Memory, I/O.

Ek line mein: Von Neumann = stored program (code bhi numbers, data ke saath ek memory mein) + ek shared bus; parts: control unit, ALU, memory, I/O; EDVAC report 1945; simple aur general.

9.3 The Von Neumann Bottleneck

Pehle socho: Ek dukaan socho jiska sirf ek darwaza hai, aur woh itna patla ki ek waqt mein ek hi aadmi nikal sake. Andar ka kaarigar (CPU) bahut tez hai. Usko do cheezein chahiye: order slip (instruction: kya banana hai) aur kachcha maal (data). Dono usi ek darwaze se aate hain, baari-baari. Kaarigar kitna bhi tez ho, darwaza hi speed tay karta hai; aadha time woh khaali baitha intezaar karta hai. Yahi Von Neumann bottleneck hai (bottleneck = botal ki patli gardan, jahan se sab dheere nikalta hai).
Definition: The Von Neumann bottleneck (term coined by John Backus in 1977) is the performance limit caused by instructions and data sharing a single bus between CPU and memory: an instruction fetch and a data access cannot happen in the same cycle, and the CPU can compute faster than the bus can supply instructions and data.
Mushkil shabd, aasaan matlab:
bottleneck
Kisi system ka sabse dheema hissa jo poore system ki speed rok deta hai. Botal ki gardan.
bus contention
Do kaam ek hi bus maang rahe hain (fetch aur data); ek ko rukna padega.
IPC
Instructions Per Cycle: ek clock cycle mein kitni instructions poori hoti hain. Bus ek hi transfer de sakti hai to IPC pe cap lag jaata hai.
bandwidth
Bus ek second mein kitna data le ja sakti hai. Unit: bits/s ya bytes/s (GB/s).
GHz
10⁹ cycles per second. 1 GHz = har second 1,000,000,000 cycles.
Gbit/s vs GB/s
1 byte = 8 bits. Gbit/s ko 8 se divide karo to GB/s. 64 Gbit/s = 8 GB/s.

Diagram kaise padhein: Left mein CPU (fast), right mein MEMORY (code + data). Beech ki do lines beech mein patli ho jaati hain = "ONE narrow bus". Neeche likha: "fetch instruction OR load/store data, never both in the same cycle". Wahi patla hissa bottleneck hai.

Kaise kaam karta hai (kyun performance rukti hai):
  1. Bus contention: lw instruction ko pehle fetch (bus use), phir data load (bus phir use). Dono ek saath nahi.
  2. IPC cap: instructions kitni tezi se aati hain, woh bus decide karti hai, ALU nahi.
  3. Idle compute units: data ka intezaar karte hue ALU khaali baitha rehta hai.
  4. Worsens with CPU speed: CPU tez hota gaya, bus utni tez nahi badhi, to gap badhta gaya (Unit 8 ka memory wall bhi isi se juda hai).
  5. Responses: caches (garam code aur data chip pe hi rakho), wider/faster buses, Harvard-style alag raaste.
Solved example 1 (cycle count, single door):

A program has 10 instructions, of which 4 are loads/stores (each needs one data access). Each memory transfer takes 1 bus cycle and there is no cache. How many bus cycles does memory traffic take on a Von Neumann machine and on a Harvard machine?

  1. Har instruction ko fetch karna hai: 10 fetches.
  2. Loads/stores ka data access: 4.
  3. Von Neumann: ek hi bus, sab baari-baari: 10 + 4 = 14 bus cycles.
  4. Harvard: fetch I-bus pe, data D-bus pe, ek saath. 4 data accesses apni instruction ke saath overlap ho jaate hain, to sirf 10 fetch cycles: 10 cycles.
  5. Farak: 14 ÷ 10 = 1.4 guna. Agar har instruction load/store hoti (10 + 10 = 20 vs 10), to 2 guna. Isliye "up to 2×".

Answer: Von Neumann 14 cycles, Harvard 10 cycles (1.4×; best case 2×).

Formula: Bus bandwidth (bytes/s) = bits moved per cycle × clock rate ÷ 8
Von Neumann: one bus carries instruction bits + data bits. Harvard: each bus carries only its own share.
Solved example 2 (class worked, p28):

A 1 GHz CPU must fetch a 32-bit instruction and access a 32-bit data word every cycle. Find the required bandwidth of the single Von Neumann bus, and of each Harvard bus.

  1. Bits per cycle (VN) = 32 + 32 = 64 bits.
  2. Per second: 64 × 10⁹ = 64 Gbit/s.
  3. Bytes: 64 ÷ 8 = 8 GB/s.
  4. Harvard: I-bus 32 × 10⁹ ÷ 8 = 4 GB/s; D-bus bhi 4 GB/s.

Answer: 8 GB/s on the single VN bus; 4 GB/s + 4 GB/s on the Harvard buses.

Solved example 3 (class homework + mock):

(a) 2 GHz, 64-bit instruction + 64-bit data per cycle. (b) 2 GHz, 32-bit instruction + 32-bit data per cycle. Required Von Neumann bus bandwidth?

  1. (a) 64 + 64 = 128 bits per cycle. 128 × 2 × 10⁹ = 256 Gbit/s. 256 ÷ 8 = 32 GB/s. Harvard: 16 GB/s per bus.
  2. (b) 32 + 32 = 64 bits. 64 × 2 × 10⁹ = 128 Gbit/s. 128 ÷ 8 = 16 GB/s.

Answer: (a) 32 GB/s (Harvard 16 + 16); (b) 16 GB/s.

Galti mat karna: (1) ALU ko dosh dena: bottleneck shared raasta (bus) hai, ALU nahi. (2) Bytes/s maanga ho to 8 se divide karna bhoolna. (3) Term ka credit von Neumann ko dena: John Backus, 1977 ne naam diya.

Trick: "Ek darwaza, do mehmaan: instruction aur data ek saath andar nahi aa sakte." Bandwidth: "bits jodo, GHz se guna, 8 se bhaag".

Ek line mein: Bottleneck = ek bus pe instruction fetch aur data access baari-baari (Backus 1977); effects: contention, IPC cap, idle ALU, CPU ke saath badhta; fixes: cache, wider bus, Harvard split; bandwidth = bits × GHz ÷ 8.

9.4 Harvard Architecture: Separate I and D Memories

Pehle socho: Dukaan ka ek darwaza problem tha. Solution: do darwaze bana do: ek sirf order slips (instructions) ke liye, ek sirf kachche maal (data) ke liye. Ab dono ek saath andar aa sakte hain, kaarigar ko intezaar nahi. Kharcha: do darwaze, do raaste, zyada deewar todni padi. Aur ab order slip wale darwaze se maal nahi aa sakta (code aur data alag duniya). Yahi Harvard hai: alag instruction memory + alag data memory + do alag buses.
Definition: The Harvard architecture uses physically separate memories and separate buses for instructions (I-memory, I-bus) and data (D-memory, D-bus), so an instruction fetch and a data access can take place in the same clock cycle. It is named after the Harvard Mark I (1944), which held instructions on punched paper tape and data in relay counters.
Mushkil shabd, aasaan matlab:
I-memory / I-bus
Sirf instructions ki memory aur uska raasta. CPU yahan se sirf fetch karta hai.
D-memory / D-bus
Sirf data ki memory aur uska raasta. Load/store yahan hote hain (do-taraf).
throughput
Ek second mein kitna kaam (yahan: kitne memory transfers) ho sakta hai.
address space
Addresses ki "duniya". Harvard mein do: I-address 0x10 aur D-address 0x10 alag jagah hain.
DSP
Digital Signal Processor: audio/video filter, FFT jaisa lagatar data stream ka kaam karne wala chip.
microcontroller
Chhota computer-on-a-chip (CPU + memory + I/O), jaise Arduino ka ATmega328.
flash
Non-volatile memory: power jaane pe bhi data rehta hai. ATmega328 mein program flash mein, data SRAM mein.
deterministic timing
Har baar kaam bilkul utne hi time mein: real-time systems (airbag, motor control) ke liye zaruri.

Diagram kaise padhein: Upar-left INSTRUCTION MEMORY, upar-right DATA MEMORY, neeche beech mein CPU (Control, ALU). Left ka highlighted arrow = I-bus, sirf instruction memory se CPU ki taraf (ek-taraf, kyunki instructions sirf padhi jaati hain). Right mein do arrows = D-bus, dono taraf (load aur store). Do alag raaste, isliye ek hi cycle mein dono transfer.

Kaise kaam karta hai:
  1. Cycle shuru: CPU I-bus pe PC ka address bhejta hai, instruction memory se instruction aati hai.
  2. Usi cycle mein pichli lw instruction D-bus pe data memory se apna data le aati hai.
  3. Do alag buses, koi takraav (contention) nahi.
  4. Isliye memory throughput Von Neumann se 2 guna tak (jab har cycle mein fetch aur data dono hon).
  5. Kharcha: do memories, do bus systems: zyada wires, pins, silicon. Code aur data alag address spaces mein, to program code ko data ki tarah aasani se nahi padh/likh sakta (kam flexibility).

Diagram kaise padhein: Do rows. Upar "Von Neumann": FETCH instruction (cycle 1), phir ACCESS data (cycle 2), total 2 cycles. Neeche "Harvard": FETCH aur ACCESS ek ke upar ek, dono cycle 1 mein, total 1 cycle. Khadi dashed lines cycle ki seemayein hain. Same kaam, aadha time.

History aur kahan use hota hai:
  1. Harvard Mark I (1944): instructions punched paper tape pe, data electro-mechanical relay counters mein. Alag rakhna majboori thi (alag technology).
  2. Aaj alag rakhna ek design choice hai (on-chip alag memories / caches).
  3. DSPs: filters/FFT mein har cycle instruction + data dono chahiye.
  4. Real-time systems: bus takraav nahi, to timing pakki (deterministic).
  5. Microcontrollers: ATmega328 (Arduino Uno) = true Harvard: code flash mein, data SRAM mein. Embedded / IoT.

Solved example 1 (Harvard bandwidth):

A 1 GHz Harvard CPU fetches a 32-bit instruction and a 32-bit data word per cycle. Bandwidth needed on EACH bus?

  1. Har bus pe sirf apna hissa: 32 bits per cycle.
  2. 32 × 10⁹ = 32 Gbit/s.
  3. 32 ÷ 8 = 4 GB/s.

Answer: 4 GB/s per bus (VN would need 8 GB/s on one bus).

Solved example 2 (write the answer like this):

Draw block diagrams of Von Neumann and Harvard architectures and compare them (six points). Where is each used? (5 marks)

  1. Draw D9.2a (one memory, one shared bus) and D9.4a (instruction memory on the I-bus, data memory on the D-bus).
  2. Write six rows of the table: memory, buses, fetch + data timing, throughput, cost, flexibility.
  3. Add the timeline D9.4b: VN needs 2 cycles, Harvard 1 cycle for a fetch plus a data access.

Galti mat karna: (1) "Harvard = do CPU" galat: CPU ek, memories aur buses do. (2) "Harvard program ko 2 guna tez chalata hai" galat: sirf memory transfer throughput up to 2×. (3) "Harvard ka throughput kam hai" galat: zyada hai; uske nuksaan hain zyada pins/wiring, do memory systems, aur code ko data ki tarah treat na kar paana.

Trick: Harvard = "H" ke do khambe = do memories, do buses. Mark I = paper tape (instructions) + relays (data).

Ek line mein: Harvard = alag instruction memory + alag data memory + do buses → fetch aur data ek cycle mein (up to 2× throughput); kharcha: zyada pins, kam flexibility; Mark I 1944; DSP, ATmega328.

9.5 Modified Harvard in Modern CPUs

Pehle socho: Ek bade restaurant ki rasoi socho. Chef ke bilkul paas do chhoti trolleys hain: ek mein recipe cards (instructions), ek mein masale-sabzi (data), taaki chef dono ek saath utha sake (Harvard speed). Par peeche ek hi bada store room hai jisme sab kuch rakha hai (ek memory, aasaan management). Trolleys khaali hon to store room se bhar lo. Yahi modified Harvard hai: andar se Harvard (split L1), bahar se Von Neumann (ek DRAM).
Definition: A modified Harvard architecture splits only the level-1 cache into a separate instruction cache (L1-I) and data cache (L1-D), so the core can fetch an instruction and access data in the same cycle, while the L2/L3 caches and the main memory (DRAM) are unified and hold both code and data in one address space. Almost all modern CPUs, such as x86-64 desktops and the ARM Cortex-M4, use it.
Mushkil shabd, aasaan matlab:
L1-I / L1-D
Level-1 Instruction cache aur Level-1 Data cache: core ke sabse paas ki do alag chhoti SRAM memories.
unified cache / memory
Ek hi memory jisme code aur data dono (L2, L3, DRAM).
cache coherence
Hardware jo dhyan rakhta hai ki saari copies (L1-I, L1-D, L2, DRAM) ek doosre se match karein, taaki software ko ek hi memory dikhe.
pipeline (preview)
CPU ek saath kai instructions ke alag-alag stage chalata hai (Unit 14). IF stage = instruction fetch, MEM stage = data access.
structural hazard (preview)
Do stages ko ek hi hardware chahiye ek hi cycle mein. Ek hi memory ho to IF aur MEM takrate hain; split L1 ye hata deta hai (Unit 15).

Diagram kaise padhein: Left mein CPU CORE. Uske right mein do chhote box: upar L1-I (instructions, highlighted arrow core ki taraf), neeche L1-D (data, do-taraf arrows). Dono ka raasta ek box L2 / L3 (unified) mein milta hai, phir DRAM (unified code + data). Beech ki khadi dashed line: left = "HARVARD ZONE" (split L1), right = "VON NEUMANN ZONE" (L2 se neeche sab ek).

Kaise kaam karta hai:
  1. Program aur data dono ek hi DRAM mein (ek address space): OS load karta hai, linker jodta hai, sab aasaan (Von Neumann fayda).
  2. Core ke paas L1 do hisson mein: L1-I aur L1-D.
  3. Har cycle pipeline L1-I se instruction aur L1-D se data ek saath le leta hai: koi contention nahi (Harvard fayda).
  4. L1 mein miss hua to unified L2/L3, phir DRAM se block aata hai.
  5. Cache coherence hardware ensure karta hai ki copies match karein, to programmer ko ek hi memory dikhti hai.
  6. Yahi split L1 5-stage pipeline mein IF aur MEM ka structural hazard hatata hai (Unit 15).

Solved example 1 (class activity):

Classify: ATmega328 (Arduino Uno), ARM Cortex-M4, x86-64 desktop.

  1. ATmega328: program flash mein, data SRAM mein, alag buses → true Harvard.
  2. ARM Cortex-M4: alag instruction aur data paths, par ek unified address space → modified Harvard.
  3. x86-64 desktop: split L1-I/L1-D, unified L2/L3 aur DRAM → modified Harvard (pure Von Neumann NAHI).

Answer: true Harvard; modified Harvard; modified Harvard.

Solved example 2 (write the answer like this):

Explain modified Harvard architecture with a diagram. Why do almost all modern CPUs use it? (4 marks)

  1. Draw D9.5a: core → split L1-I and L1-D → unified L2/L3 → unified DRAM; mark the Harvard zone and the Von Neumann zone.
  2. The split L1 lets the pipeline fetch an instruction and access data in the same cycle, avoiding the Von Neumann bottleneck where it matters most.
  3. The unified main memory gives one address space, so loading, linking and programming stay simple and flexible.
  4. Hardware cache coherence keeps the split caches consistent, so software sees a single memory; the design scales to real workloads.

Answer: diagram + "Harvard speed inside, Von Neumann flexibility outside" + coherence.

Galti mat karna: (1) Modern x86 ko "pure Von Neumann" kehna: uska L1 split hai, to modified Harvard. (2) "Modern CPU ke programs ko do address spaces dikhte hain" galat: software ko ek memory dikhti hai. (3) Split ko DRAM ya register file level pe batana: split sirf L1 pe hai.

Trick: "Andar Harvard, bahar Von Neumann" ya "L1 split, baaki sab ek".

Ek line mein: Modified Harvard = split L1-I/L1-D (fetch + data ek cycle mein) + unified L2/L3/DRAM (ek address space), coherence hardware se consistent; x86-64 aur Cortex-M4 isi pe, ATmega328 true Harvard.

MCQ: defining feature of VN / HarvardVN: one memory + one shared bus. Harvard: separate I and D memories + two buses, fetch and data in the same cycle.

Explain the bottleneckOne bus shared → fetch OR data per cycle (D9.3a); four effects: contention, IPC cap, idle ALU, worsens with CPU speed; fixes: caches, wider buses, Harvard split.
Bandwidth numerical1. Add bits per cycle (VN: instr + data; Harvard: each bus separately). 2. × clock (GHz = 10⁹). 3. ÷ 8 for bytes. 1 GHz 32+32 → 8 GB/s (Harvard 4 + 4); 2 GHz 64+64 → 32 GB/s; 2 GHz 32+32 → 16 GB/s.
Cycle count VN vs HarvardVN cycles = fetches + data accesses; Harvard cycles = fetches (data overlaps). Ratio is at most 2.

Harvard disadvantages (MSQ)More pins/wiring, two memory systems, code cannot easily be treated as data. NOT lower throughput.
