Unit 10 · CISC vs RISC

Is unit ki kahani: Unit 9 mein humne dekha CPU memory se kaise juda hai (Von Neumann, Harvard). Ab sawaal hai: CPU kaunsi bhasha samajhta hai? Us bhasha ko ISA kehte hain. ISA design karne ke do tareeke hain: har instruction mein bahut kaam bhar do (CISC, jaise x86) ya har instruction ko chhota aur simple rakho (RISC, jaise MIPS, ARM). Is unit mein dono ka matlab, fayda, nuksaan aur history samjhenge. Unit 11 mein ek RISC (MIPS) ki bhasha bit-by-bit seekhenge, aur Unit 14 mein dekhenge ki RISC pipelining ke liye kyun perfect hai.

10.1 Recap (Von Neumann / Harvard) aur ISA ka matlab

Pehle socho: Tumhare paas ek Android app hai. Wahi app Samsung ke phone pe bhi chalti hai aur Xiaomi pe bhi, jabki dono ke andar chip alag company ne banayi hai. Kaise? Kyunki dono chips ek hi "bhasha" (ARM ISA) samajhti hain. Jaise do alag restaurants ek hi menu card follow karein: customer (software) menu se order deta hai, kitchen (hardware) andar kaise banata hai, customer ko farak nahi padta. Ye "menu card" hi ISA hai.
Definition: The Instruction Set Architecture (ISA) is the part of a processor visible to the programmer: its instructions, registers, data types, addressing modes and memory model. It is the contract between software and hardware: compilers translate programs to the ISA, and the hardware (microarchitecture) executes the ISA.
Mushkil shabd, aasaan matlab:
Von Neumann (recap)
Ek hi memory aur ek hi bus, jisme instructions aur data dono rehte hain. Fetch aur data access baari-baari hote hain (bottleneck).
Harvard (recap)
Instruction memory alag, data memory alag, bus bhi alag. Ek hi cycle mein instruction fetch aur data read dono ho sakte hain.
Modified Harvard (recap)
Aaj ke CPU: L1 cache do hisson mein (L1-I instructions ke liye, L1-D data ke liye), neeche L2/L3 aur RAM ek hi (unified).
ISA
CPU ki "bhasha": kaunse instructions hain (add, lw, beq), kitne registers hain ($0 se $31), memory kaise address hoti hai. Example: x86, ARM, MIPS, RISC-V.
Microarchitecture (organisation)
ISA ko andar se kaise banaya: kitne pipeline stages, cache kitna bada. Intel i3 aur i9 ka ISA same (x86-64), microarchitecture alag.
Memory operand
Instruction ka input/output seedha memory address ho, register nahi. Jaise add [x], eax: x memory mein hai.
Kaise kaam karta hai (recap se ISA tak ka pul):
  1. Unit 9 ne bataya: CPU aur memory ke beech bus hai, aur har memory access mein time lagta hai.
  2. Ab har instruction kitni baar memory chhoota hai, ye ISA decide karta hai.
  3. CISC instruction add [mem1], [mem2]: 1 baar instruction fetch + 2 baar data read + 1 baar result write = ek hi instruction mein bus pe 4 trips.
  4. RISC ka add $t0, $t1, $t2: sirf instruction fetch, data registers mein hai, bus pe koi data trip nahi. Memory sirf lw/sw chhoote hain, aur woh bhi ek baar.
  5. Isliye recap pehle aata hai: ISA ka design seedha memory traffic decide karta hai.
  6. ISA ek contract hai: upar software (compiler, OS, apps) ISA mein compile hota hai, neeche hardware ISA ko execute karta hai. Dono contract maante hain to Intel naya chip banaye, purana program phir bhi chalega.

Diagram kaise padhein: Teen patti upar se neeche: Software, beech mein highlighted ISA, neeche Hardware. Upar wala arrow "compiles TO the ISA" (tumhara C code ISA ke instructions ban jata hai), neeche wala "EXECUTES the ISA" (chip un instructions ko chalata hai). Trace: c = a + b → compiler add instruction banata hai (ISA level) → chip ka ALU usse jodta hai (hardware level).

Solved example (write the answer like this):

Differentiate between architecture (ISA) and organisation. Why is the ISA called a contract? (3 marks)

  1. Architecture (ISA) = the "what": instructions, registers, addressing modes visible to the programmer.
  2. Organisation (microarchitecture) = the "how": pipelines, caches, buses that implement the ISA.
  3. Example: Intel Core i3 and i9 share the x86-64 ISA but have different organisation.
  4. Contract: software is compiled only against the ISA; any hardware that honours the ISA runs it. So hardware and software can be improved independently (old programs run on new chips).

Answer: ISA = what the CPU understands; organisation = how it is built. Same ISA, different chips, same software.

Galti mat karna: "Architecture" aur "organisation" ko same mat likhna. Cache size, pipeline depth = organisation. Instruction list, register count = architecture (ISA).
Ek line mein: ISA = CPU ki bhasha aur software-hardware ka contract; Unit 9 batata hai CPU memory tak kaise pahunchta hai, Unit 10 batata hai CPU kya samajhta hai.

10.2 RISC vs CISC: definitions aur design goals

Pehle socho: Do tarah ke cook socho. Cook A (CISC) ko tum ek hi bada order dete ho: "Paneer butter masala bana do". Ek command, par cook ko andar se 20 kaam khud karne padte hain, aur aisi sainkdon recipes yaad rakhni padti hain. Cook B (RISC) sirf chhote simple steps samajhta hai: "fridge se paneer nikalo", "kaato", "kadhai mein daalo", "milao". Tumhe (compiler ko) zyada lines likhni padti hain, par har step itna simple hai ki cook B bahut tez aur bina confusion ke kaam karta hai, aur ek step khatam hone se pehle agla shuru kar sakta hai (pipelining). CISC = ek complex command; RISC = bahut saare simple steps.
Definition: A CISC (Complex Instruction Set Computer) provides a large number of powerful, variable-length instructions, many of which can operate directly on memory, often implemented with microcode (e.g. x86, VAX, 68000). A RISC (Reduced Instruction Set Computer) provides a small set of simple, fixed-length (32-bit) instructions, each doing one simple operation, in a load/store architecture where only load and store instructions access memory (e.g. MIPS, ARM, RISC-V, SPARC).
Mushkil shabd, aasaan matlab:
Variable length
Instructions alag-alag size ke. x86 mein ek instruction 1 byte ka bhi ho sakta hai aur 15 bytes ka bhi.
Fixed length
Har instruction same size. MIPS mein har instruction 32 bits = 4 bytes. Isliye agla instruction hamesha PC + 4 pe.
Load/store architecture
Sirf do kaam memory chhoo sakte hain: load (memory → register, lw) aur store (register → memory, sw). add, sub sirf registers pe kaam karte hain.
Decoder
CPU ka woh hissa jo instruction ke bits padh ke samajhta hai "ye kaunsa instruction hai, kaunse registers". (Unit 3 wala decoder ka bada roop.)
Microcode
CPU ke andar chhupa ek mini-program. Ek complex CISC instruction aane pe CPU ROM se uska chhota program chalata hai jo usse kai chhote steps mein karta hai.
Pipelining
Assembly line: ek instruction decode ho raha hai tab tak agla fetch ho raha hai. (Unit 14.)
Code density
Kitne bytes mein kitna kaam. Kam bytes mein zyada kaam = high density (CISC ka fayda).
Kaise kaam karta hai (same task, dono styles): Task: C = A + B, teeno variables memory mein hain.
  1. CISC soch: ek instruction memory se operand utha sakta hai. VAX mein ek hi instruction ADDL3 A, B, C (memory A + memory B → memory C) poora kaam kar deta tha. x86 thoda kam flexible hai (ek instruction mein max ek memory operand), to wahan mov eax,[A] ; add eax,[B] ; mov [C],eax.
  2. RISC soch: pehle data ko register mein lao, register pe kaam karo, phir wapas memory mein rakho.
  3. lw $t1, A: A ki value memory se $t1 mein.
  4. lw $t2, B: B ki value $t2 mein.
  5. add $t3, $t1, $t2: registers pe jod (memory ko chhua bhi nahi).
  6. sw $t3, C: result memory ke C mein rakho.
  7. Result: CISC ne kam instructions likhe, RISC ne 4 likhe, par RISC ke chaaron instructions simple, fixed 32-bit, aur ek-ek cycle wale hain.
; Class activity: C = A + B ; D = C * 2

; CISC style (x86-like): 5 instructions, memory operands allowed
mov  ax, [A]      ; ax = A (memory se seedha)
add  ax, [B]      ; ax = A + B  (B memory operand hai)
mov  [C], ax      ; C = A + B, memory mein likh diya
shl  ax, 1        ; ax = C * 2 (left shift 1 = 2 se guna)
mov  [D], ax      ; D = C * 2

# RISC style (MIPS-like): 6 instructions, sirf lw/sw memory chhoote hain
lw   r1, A        # r1 = A (load: memory se register)
lw   r2, B        # r2 = B
add  r3, r1, r2   # r3 = A + B (sirf registers)
sw   r3, C        # C = r3 (store: register se memory)
add  r4, r3, r3   # r4 = C + C = C * 2
sw   r4, D        # D = r4

Diagram kaise padhein: Upar wali line RISC: teen barabar chaudai ke dabbe, har ek 32 bits, fields (opcode, rs, rt, rd, shamt, funct) hamesha same jagah. CPU ko pata hai agla instruction 4 bytes baad shuru hoga, to woh bina padhe agla fetch kar sakta hai. Neeche wali line CISC: dabbe alag lambai ke (prefix, op, modRM, disp, imm), aur dabbe ki boundary tab tak pata nahi jab tak pichla instruction decode na ho jaye. Isliye CISC ko pipeline karna mushkil hai.

Solved example 1 (direct):

Name the two hallmarks of a RISC ISA. (class exit ticket)

  1. RISC ki pehchaan wo cheez hai jo CISC mein nahi hoti.
  2. Pehli: har instruction same size (fixed 32-bit).
  3. Doosri: memory sirf load/store se (load/store architecture).

Answer: (1) fixed-length instructions, (2) load/store-only memory access.

Solved example 2 (exam favourite, 5 marks):

Compare CISC and RISC (six points) with examples, and write C = A + B; D = 2C in both styles.

  1. Definition dono ki ek-ek line mein (upar wali definition).
  2. Upar wali table ki pehli 6 rows likho: number of instructions, length, memory access, decoder, CPI, pipelining (har row ke saath "why" ek chhoti line).
  3. Examples: CISC = x86, VAX, 68000; RISC = MIPS, ARM, RISC-V, SPARC.
  4. Upar wala code likho: CISC 5 instructions (mov, add, mov, shl, mov), RISC 6 (lw, lw, add, sw, add, sw).
  5. Conclusion line: RISC zyada instructions chalata hai, par har ek simple aur pipeline-friendly hai; complexity hardware se compiler mein shift hoti hai.

Answer: 6-point table + code (CISC 5 instructions, RISC 6) + "complexity moves from hardware to compiler".

Galti mat karna: "RISC = kam instructions chalte hain" GALAT hai. RISC mein instruction types kam hain, par ek program chalane mein instructions zyada lagte hain (upar: 6 vs 5). "Reduced" ka matlab har instruction ka kaam reduced (simple) hai.

Trick: RISC ke do hallmarks = "Fixed + Load/Store", jaise railway: fixed time-table (har instruction 4 bytes) aur chadhna-utarna sirf platform pe (memory sirf lw/sw se).

Ek line mein: CISC = kam lekin bhaari, variable-length, memory-operand instructions (complexity hardware mein); RISC = zyada lekin halke, fixed 32-bit, load/store instructions (complexity compiler mein).

10.3 Historical context: VAX, x86, MIPS, ARM, RISC-V

Pehle socho: 1970s mein memory bahut mehengi thi (kuch KB ke liye lakhon rupaye) aur programmer zyada tar assembly haath se likhte the. Aise mein sabse samajhdari kya thi? Program ko chhota rakho aur programmer ka kaam aasaan karo: "ek instruction mein zyada kaam". Isliye pehle CISC aaya. 1980s tak memory sasti ho gayi, compilers smart ho gaye, aur researchers ne dekha ki compiler complex instructions use hi nahi karta. Tab RISC aaya: simple instructions, tez chip, pipelining.
Definition: The ISA family tree shows two lineages: the CISC line (VAX 1977, Motorola 68000 1979, Intel x86 1978 → x86-64 2003) and the RISC line (IBM 801 → MIPS (Stanford, 1984), SPARC, ARM (1985) → RISC-V (Berkeley, 2010)). CISC came first because memory was scarce and expensive; RISC followed when better compilers and the need for pipelining made simple instructions more attractive.
Mushkil shabd, aasaan matlab:
Lineage
Vansh / khaandan. Kaunsa ISA kis se prerit hua.
Backward compatibility
Naya chip purane programs bina badle chala sake. x86 ka sabse bada hathiyaar: 1978 ka code aaj bhi chal sakta hai.
Licensing (ARM model)
ARM khud chip nahi bechta, design ka licence bechta hai. Qualcomm, Apple, Samsung licence leke apni chip banate hain.
Royalty-free
Use karne ke liye koi fees nahi. RISC-V aisa hai.
Compiler
Program jo C jaisi bhasha ko ISA instructions mein badalta hai.
Kaise hua (time-line, step by step):
  1. 1970s, CISC kyun pehle: memory mehengi aur chhoti → program kam bytes mein hona chahiye → ek instruction mein zyada kaam (high code density). Programmer assembly haath se likhte the → powerful instructions unka kaam aasaan karte the. Compilers kamzor the.
  2. CISC family: VAX (DEC, 1977), x86 (Intel 8086, 1978), Motorola 68000 (1979). Baad mein AMD ne x86 ko 64-bit kiya: x86-64 (2003).
  3. 1980, RISC kyun aaya: IBM 801 project ne dekha ki compiler zyada tar simple instructions hi use karta hai. Memory sasti ho rahi thi, compilers achhe ho rahe the. Simple instructions → chhota decoder → tez clock aur pipelining aasaan.
  4. RISC family: IBM 801 → MIPS (Stanford, John Hennessy, 1984), SPARC (Sun, Berkeley RISC se), ARM (1985), aur RISC-V (Berkeley, 2010).
  5. MIPS kahan chala (Lab 11): SGI workstations, original PlayStation (R3000A, 33.8688 MHz), Nintendo 64 (VR4300, 93.75 MHz), PlayStation 2 (R5900). Hennessy aur Patterson ko RISC ke liye 2017 Turing Award mila. 2021 mein MIPS company RISC-V pe shift ho gayi.
  6. 1990s se, do samrajya: ARM ne mobile jeeta (simple design = kam power = lambi battery, aur licence model se sab ARM chip bana sakte hain; ab Apple laptops bhi). x86 ne desktop/server rakha (backward compatibility, dashakon ka software, Intel/AMD ka R&D).
  7. Lesson: "best ISA" jeetta nahi; ecosystem, power budget aur compatibility jeetate hain.

Diagram kaise padhein: Beech mein dashed line dono camps ko alag karti hai. Left (CISC): VAX, 68000, x86, aur x86 se arrow neeche x86-64 (2003). Right (RISC): upar IBM 801, usse teen arrows MIPS, SPARC, ARM ki taraf; MIPS (Berkeley/Stanford lineage) se arrow RISC-V (2010) tak. Neeche ki line: dono family ab mil gayi hain (x86 andar RISC jaise µops chalata hai, 10.5 dekho).

Solved example (write the answer like this, 4 marks):

Trace the history of CISC and RISC. Why did CISC come first, and why did ARM win mobile while x86 kept the desktop?

  1. CISC first (1970s): memory was expensive and small, programs were hand-written in assembly and compilers were weak, so dense, powerful instructions (VAX 1977, x86 1978, 68000 1979) saved memory and programmer effort.
  2. RISC (1980s): IBM 801 showed compilers mainly use simple instructions; cheaper memory and better compilers allowed simple fixed-length instructions that pipeline well (MIPS 1984, SPARC, ARM 1985, RISC-V 2010).
  3. ARM won mobile: simple core → low power → long battery life; licensable design.
  4. x86 kept desktop: backward compatibility with decades of software, huge ecosystem and R&D.
  5. Draw the family tree (D10.3a).

Answer: CISC first because memory was costly; RISC when compilers + pipelining mattered; ARM = power + licensing, x86 = compatibility.

Galti mat karna: RISC-V 1980s ka nahi, 2010 ka hai. ARM RISC hai, CISC nahi. x86 1978 (8086), x86-64 2003 (AMD).

Trick: Saal yaad rakho: "77 VAX, 78 x86, 84 MIPS, 85 ARM, 2003 x86-64, 2010 RISC-V". CISC pehle kyun? "Memory mehengi thi" (bas yahi ek reason exam mein likhna kaafi hai, saath mein compilers kamzor).

Ek line mein: Mehengi memory ke zamane mein CISC aaya (dense code), sasti memory + smart compilers + pipelining ke zamane mein RISC aaya; ARM ne power se mobile jeeta, x86 ne compatibility se desktop rakha.

10.4 Compiler implications aur code density

Pehle socho: Ek SMS mein 160 characters ki limit hai. Agar tum "tomorrow" ki jagah "tmrw" likho, to kam jagah mein zyada baat aa jaati hai, par padhne wale ko thoda dimaag lagana padta hai. CISC "tmrw" jaisa hai: kam bytes mein zyada kaam (dense code), par padhna (decode) mushkil. RISC poore spelling jaisa: zyada jagah, par padhna turant. Ye trade-off kabhi khatam nahi hota, sirf jagah badalta hai.
Definition: Code density is the amount of work a program does per byte of instruction memory. CISC has higher code density (smaller programs, less instruction-cache pressure), while RISC's fixed-length, uniform instructions are easier to decode and pipeline. Performance is given by the iron law: CPU time = Instruction count × CPI × Clock period.
Mushkil shabd, aasaan matlab:
I-cache (instruction cache)
CPU ke paas chhoti fast memory jisme instructions rakhe jaate hain. Program chhota ho to zyada instructions isme fit hote hain.
Instruction count (IC)
Program chalne mein kul kitne instructions execute hue. Jaise 2 million.
CPI (cycles per instruction)
Ek instruction ko average kitne clock cycles lage. CPI = 1.5 matlab average 1.5 cycle.
Clock period (T)
Ek cycle ka time = 1 / frequency. 1 GHz → 1 ns; 2 GHz → 0.5 ns.
ARM Thumb / RISC-V "C"
RISC ke 16-bit chhote instructions (compressed). Inse RISC ki code density CISC ke paas aa jaati hai.
Register allocation
Compiler decide karta hai kaunsa variable kaunse register mein rahe. RISC mein bahut zaroori kyunki maths sirf registers pe hota hai.
Kaise kaam karta hai:
  1. CISC ka fayda (density): kam aur chhote instructions → program kam bytes → fetch kam bytes → I-cache mein zyada fit. Memory kam ho (embedded) to bada fayda.
  2. RISC ka nuksaan: har instruction 4 bytes, chahe kaam chhota ho. Fix: ARM Thumb aur RISC-V C (16-bit instructions).
  3. RISC ka fayda (pipelining), 4 reasons: (a) fixed length = fetch aasaan (agla hamesha PC + 4); (b) uniform format = decode ek stage mein; (c) har instruction ek simple step = flow smooth; (d) load/store = sirf 2 instructions memory chhoote, hazards pakadna aasaan.
  4. Compiler pe asar: RISC compiler ko registers achhe se baantne padte hain aur zyada simple instructions ko sahi order mein lagana padta hai (load ka wait chhupane ke liye reorder bhi kar sakta hai). CISC compiler rich instructions use kar sakta hai, par asal mein instruction set ka bada hissa use hi nahi hota.
  5. Iron law se faisla: CISC IC (instruction count) kam karta hai; RISC CPI aur clock period kam karta hai. Teeno ka product hi asli time hai.
Formula: CPU time = IC × CPI × T  =  IC × CPI / f
IC = instruction count, CPI = average cycles per instruction, T = clock period = 1/f (f = clock frequency). 1 GHz → T = 1 ns; 2 GHz → T = 0.5 ns.

Solved example 1 (easy):

A program runs 2 million instructions with CPI 1.5 on a 1 GHz clock. Find the CPU time in ms.

  1. IC = 2 million = 2 × 10⁶.
  2. T = 1 / 1 GHz = 1 ns = 1 × 10⁻⁹ s.
  3. CPU time = 2 × 10⁶ × 1.5 × 1 ns = 3 × 10⁶ ns.
  4. 3 × 10⁶ ns = 3 × 10⁶ × 10⁻⁹ s = 3 × 10⁻³ s = 3 ms.

Answer: 3 ms.

Solved example 2 (exam-level comparison):

A program on a CISC machine executes 1.0 million instructions at CPI 2.0. Compiled for a RISC machine it executes 1.4 million instructions at CPI 1.1. Both run at 2 GHz. Which is faster?

  1. T = 1 / 2 GHz = 0.5 ns.
  2. CISC: 1.0 × 10⁶ × 2.0 = 2.0 × 10⁶ cycles. × 0.5 ns = 1.0 × 10⁶ ns = 1.0 ms.
  3. RISC: 1.4 × 10⁶ × 1.1 = 1.54 × 10⁶ cycles. × 0.5 ns = 0.77 × 10⁶ ns = 0.77 ms.
  4. Compare: 0.77 ms < 1.0 ms, to RISC tez hai.
  5. Speed-up = 1.0 / 0.77 ≈ 1.30.

Answer: RISC is faster (0.77 ms vs 1.0 ms, about 1.3×) even though it runs 40% more instructions.

Solved example 3 (class homework):

Count the instructions for a straight-line 3-element vector add C[i] = A[i] + B[i] in CISC and RISC style.

  1. CISC (x86) har element: mov eax,[A+4i] ; add eax,[B+4i] ; mov [C+4i],eax = 3 instructions.
  2. 3 elements × 3 = 9 instructions.
  3. RISC har element: lw ; lw ; add ; sw = 4 instructions.
  4. 3 elements × 4 = 12 instructions.

Answer: CISC 9, RISC 12 (RISC has more instructions, but each is simple and pipelines at about one per cycle).

Galti mat karna: (1) "RISC hamesha tez hai" galat; time IC × CPI × T pe depend karta hai. (2) GHz ko ns mein badalte waqt: 2 GHz → 0.5 ns, 2 ns nahi. (3) Answer ms mein maanga ho to ns ko 10⁶ se divide karo.

Trick: "CISC count ghatata hai, RISC cycle ghatata hai." Pipelining ke 4 reasons: "F-U-O-L" = Fixed length, Uniform decode, One cycle, Load/store.

Ek line mein: CISC ka hathiyaar code density, RISC ka hathiyaar pipelining; asli speed = IC × CPI × T.

10.5 Modern reality: x86 ke andar micro-ops

Pehle socho: Ek restaurant ka waiter (front) customer se bada order leta hai: "ek thali". Kitchen (back) mein woh order chhote kaamon mein toota jaata hai: "roti banao", "dal garam karo", "plate lagao", aur kai cooks ek saath assembly line pe kaam karte hain. Customer ko lagta hai ek order diya, par andar simple kaam chal rahe hain. x86 bahar se CISC hai (purane software ke liye), andar se RISC jaisa.
Definition: Micro-operations (µops) are simple, RISC-like internal operations into which the front-end decoder of a modern x86 processor splits each complex CISC instruction. The back end then pipelines, renames and reorders these µops like a RISC machine. µops are internal and not visible to the programmer.
Mushkil shabd, aasaan matlab:
µop (micro-op)
"µ" = micro = chhota. Ek chhota simple kaam: sirf load, ya sirf add, ya sirf store.
Front end
CPU ka woh hissa jo instructions fetch aur decode karta hai (yahan CISC → µops todna hota hai).
Back end (core)
Woh hissa jo asli kaam (ALU, memory) karta hai; ye µops ko RISC ki tarah chalata hai.
Out-of-order execution
Jo µop ready hai woh pehle chal jaye, chahe program mein baad mein likha ho (result phir bhi sahi order mein).
Register renaming
Andar chhupe extra registers use karke false clashes hatana. (Exam mein sirf naam kaafi.)
tmp
CPU ka andar ka temporary register jo programmer ko nahi dikhta.
Kaise kaam karta hai (worked example: add [mem], eax):
  1. Instruction ka matlab: "memory address mem pe jo number hai, usme eax jodo, aur result wapas usi memory address pe likho".
  2. Isme teen alag kaam chhupe hain: memory se padhna, jodna, memory mein likhna.
  3. µop 1 (load): tmp ← Mem[mem]. Maan lo Mem[mem] = 10, to tmp = 10.
  4. µop 2 (add): tmp ← tmp + eax. Maan lo eax = 5, to tmp = 15. (Sirf registers, RISC jaisa.)
  5. µop 3 (store): Mem[mem] ← tmp. Ab memory mein 15.
  6. Dekho: ye bilkul RISC ka lw, add, sw hai. Decoder ne CISC instruction ko RISC jaise 3 µops mein tod diya.
  7. Back end in µops ko pipeline mein, out-of-order, register renaming ke saath chalata hai, jaise ek RISC core.
  8. Kyun? Binary compatibility bani rahe (purane x86 programs chalein) aur saath mein RISC wali pipelining, out-of-order execution aur high clock bhi mile.
x86 instruction (CISC, programmer ko dikhta hai):
    add  [mem], eax        ; Mem[mem] = Mem[mem] + eax

Decoder ke baad 3 micro-ops (andar, chhupe hue):
    uop1: load   tmp  <- Mem[mem]     ; jaise MIPS lw
    uop2: add    tmp  <- tmp + eax    ; jaise MIPS add
    uop3: store  Mem[mem] <- tmp     ; jaise MIPS sw

Values ke saath: Mem[mem] = 10, eax = 5
    uop1: tmp = 10
    uop2: tmp = 10 + 5 = 15
    uop3: Mem[mem] = 15

Diagram kaise padhein: Left se right chalo. Pehla dabba: CISC instruction add [mem], eax. Woh DECODER (splitter) mein jaata hai. Decoder se teen arrows teen chhote dabbon (µop load, µop add, µop store) mein. Teeno µops ek "RISC-like core" mein jaate hain. Neeche ki line: front end tod-ta hai, back end RISC ki tarah chalata hai.

Solved example (write the answer like this, 5 marks):

Explain with a diagram how a modern x86 processor executes CISC instructions using micro-operations. Why is it said that CISC and RISC have merged?

  1. Draw D10.5a: x86 instruction → decoder → µops (load, add, store) → RISC-like core.
  2. The front-end decoder splits each complex x86 instruction into simple RISC-like µops, e.g. add [mem], eax → load, add, store.
  3. The back end pipelines, renames and reorders µops like a RISC core.
  4. Reason: keeps binary compatibility with decades of x86 software while gaining RISC-style pipelining and high clock rates.
  5. Merged: CISC became RISC inside; RISC (ARM, RISC-V) added hundreds of instructions, SIMD/vector and 16-bit compressed instructions (a CISC-style density idea). Microarchitecture now matters more than the label.

Answer: "CISC outside, RISC inside"; both camps borrowed from each other, so the boundary has blurred.

Galti mat karna: (1) µops programmer ko nahi dikhte; tum assembly mein µop nahi likh sakte. (2) "CISC obsolete hai" galat: x86 aaj bhi desktop/server pe raaj karta hai. (3) Class example mein add [mem], eax = 3 µops (load, add, store).

Trick: "Bahar CISC ka kurta, andar RISC ka body." Teen µops = "Utha, Jod, Rakh" (load, add, store).

Ek line mein: Modern x86 ka decoder har CISC instruction ko RISC jaise µops mein todta hai (add [mem], eax → load, add, store), isliye aaj CISC aur RISC ki deewar dhundhli ho gayi hai.

10.6 Trends: RISC-V open ISA aur AI accelerators

Pehle socho: ARM ka design use karne ke liye paise (licence fee) dene padte hain. Socho ek "open recipe" ho jise koi bhi free mein use kare aur apni zaroorat ke hisaab se masale (extensions) jode: ye RISC-V hai. Doosra trend: agar tumhe sirf ek hi kaam baar-baar karna hai (jaise AI mein matrix multiply), to general-purpose CPU ki jagah usi kaam ke liye special chip banao. Jaise roti ke liye alag roti-maker, sab kuch karne wale mixer ki jagah.
Definition: RISC-V is an open, royalty-free, modular RISC ISA created at UC Berkeley in 2010: a small base integer ISA plus optional standard extensions (M, A, F, D, C, V). A domain-specific ISA is an instruction set designed for one class of workload (e.g. graphics or neural networks), trading generality for much higher efficiency, e.g. NVIDIA PTX for GPUs and Google TPU (matrix multiply).
Mushkil shabd, aasaan matlab:
Open / royalty-free
Specification sabke liye free; RISC-V chip banane ke liye kisi ko fees nahi deni.
Modular
Chhota base (RV32I) + jo chahiye woh extension jodo. M = multiply/divide, A = atomic, F = float, D = double, C = compressed 16-bit, V = vector.
Accelerator
Ek kaam ke liye bani special chip jo us kaam mein CPU se kai guna tez aur kam power wali hoti hai.
GPU / PTX
GPU mein hazaaron simple cores jo ek saath (parallel) kaam karte hain. PTX NVIDIA ka GPU ISA hai.
TPU
Google ki Tensor Processing Unit; iska ISA matrix multiplication ke around bana hai, jo neural networks ka main kaam hai.
Kaise kaam karta hai:
  1. RISC-V open hai: koi bhi company ya college bina fees RISC-V chip bana sakta hai.
  2. RISC-V modular hai: microcontroller ko sirf base chahiye (RV32I); laptop chip base + M + A + F + D + C le sakta hai (jaise RV32IMAFDC).
  3. Adoption: teaching se shuru, ab microcontrollers, data-centre aur AI chips tak. (2021 mein MIPS company bhi RISC-V pe aa gayi.)
  4. Domain-specific ISA: workload fixed hai (jaise sirf matrix multiply) → generality hata do → wahi transistors us ek kaam pe lagao → bahut zyada efficiency.
  5. Examples: GPU (NVIDIA PTX, hazaaron simple cores, massive parallelism); Google TPU (matrix multiply ISA).
  6. Direction: multicore + GPU + AI accelerators: architecture ka future specialisation hai (Module 6).
Solved example (write the answer like this, 4 marks):

Write short notes on (a) RISC-V and (b) domain-specific ISAs for AI.

  1. (a) RISC-V: open and royalty-free ISA from UC Berkeley (2010); modular: base RV32I (about 40 instructions) plus extensions M, A, F, D, C, V; clean RISC (fixed 32-bit, load/store, 32 registers); used from teaching to microcontrollers to data-centre/AI chips.
  2. (b) Domain-specific ISAs: designed for one workload; NVIDIA PTX for GPUs (thousands of simple parallel cores); Google TPU centred on matrix multiply (core of neural networks).
  3. Reason for (b): a fixed workload lets designers remove general-purpose features and gain large efficiency.

Answer: RISC-V = open + modular + Berkeley 2010; DSAs = specialise for efficiency (PTX, TPU).

Galti mat karna: RISC-V kisi ek company ki property nahi hai (open hai). Har RISC-V chip mein float nahi hota; float sirf F/D extension ke saath. TPU general-purpose CPU nahi hai.

Trick: RISC-V extension ka letter = uske English naam ka pehla akshar: Multiply, Atomic, Float, Double, Compressed, Vector. Naam padho, ISA samjho: RV32IMAFD = base + M + A + F + D.

Ek line mein: RISC-V = free, open, modular RISC (Berkeley 2010); AI ke liye special ISAs (PTX, TPU) generality chhod ke efficiency jeet-te hain.
