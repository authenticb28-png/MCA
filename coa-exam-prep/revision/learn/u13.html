Unit 13 · The Single-Cycle Datapath

Is unit ki kahani: Units 1–12 mein humne parts banaye (MUX, adder, ALU, register file, memory) aur MIPS ki "language" seekhi (R / I / J formats, lw, sw, beq). Ab in parts ko wires se jod ke ek chalta hua processor banayenge jo har instruction ko ek hi clock cycle mein poora kar de. Exam ka sabse pakka sawaal yahin se aata hai: "Trace <instruction> and fill the control signals". Unit ke end mein dekhenge ki ye design slow kyun hai, aur wahi problem Unit 14 (pipelining) solve karta hai.

13.1 Recap: ISA → Hardware

Pehle socho: Restaurant ka menu batata hai kya order kar sakte ho (paneer tikka, dal, roti). Kitchen batata hai woh dish banti kaise hai (kaunsa chef, kaunsa tawa, kis order mein). Same menu ke liye alag-alag kitchen ho sakte hain: ek chhota dhaba, ek bada hotel. Computer mein ISA = menu (kaunse instructions hain: add, lw, sw, beq) aur microarchitecture = kitchen (hardware jo unhe chalata hai). Is unit mein hum kitchen banayenge.
Definition: The ISA (instruction set architecture) is the programmer-visible contract: the instructions, registers and formats. The microarchitecture is the hardware implementation of the ISA and consists of the datapath (the units that store, move and transform data) and the control unit (which decodes the opcode and tells the datapath what to do). In a single-cycle implementation every instruction completes in exactly one clock cycle (CPI = 1).
Mushkil shabd, aasaan matlab:
datapath
Woh saare hardware blocks jinse data guzarta hai: PC, memories, register file, ALU, MUX, adders. Kitchen ke tawe, chulhe, bartan.
control unit
Chef ka "head". Instruction ka opcode padh ke batata hai: is baar kaunsa MUX kaunsa input le, register mein likhna hai ya nahi, memory padhni hai ya nahi.
clock cycle / clock period (Tc)
Clock ki ek "tick" se agli tick tak ka time. Jaise 800 ps (picosecond, 1 ps = 10−12 s).
CPI
Cycles Per Instruction: ek instruction ko kitne clock cycles lagte hain. Single-cycle mein har instruction = 1 cycle, to CPI = 1.
subset
Hum poora MIPS nahi banate, sirf ye instructions: add, sub, and, or, slt (R-type), lw, sw (memory), beq (branch), aur extension mein addi, j.
Kaise kaam karta hai (ISA se hardware tak ka plan):
  1. ISA ki list dekho: kaunse instructions chalane hain (upar wala subset).
  2. Har instruction ko kya chahiye, likho. Sabko instruction memory se fetch chahiye. Zyada-tar ko registers padhne hain. Sabko ALU chahiye (add, address, compare). Sirf lw / sw ko data memory chahiye. R-type, lw, addi ko register mein likhna hai.
  3. Har zaroorat ke liye ek hardware block rakho (13.3a mein list).
  4. Jahan ek input pe do alag source aa sakte hain, wahan ek MUX lagao (13.3b).
  5. Control unit banao jo opcode dekh ke saare MUX aur enable signals set kare (13.3c).
  6. Single-cycle mein ye sab ek hi lambe clock cycle mein ho jaata hai. Cycle ke end wale clock edge pe PC, register file aur data memory update hote hain.

Teen design possible hain same ISA ke liye: single-cycle (ek lamba cycle per instruction, CPI = 1, slow clock), multicycle (har instruction kai chhote cycles), aur pipelined (kai instructions ek saath alag stages mein, Units 14–15).

Formula (performance): Execution time = Instruction count × CPI × Tc
Single-cycle: CPI = 1, lekin Tc = sabse slow instruction (lw) ka time. Example: 106 instructions × 1 × 800 ps = 800 × 106 ps = 0.8 ms.
Solved example (write the answer like this):

Differentiate ISA and microarchitecture. What are the characteristics of a single-cycle implementation? (3 marks)

  1. ISA is the contract between software and hardware: instruction formats, registers, opcodes (the "what"). Microarchitecture is how a particular processor implements it: datapath + control (the "how"). One ISA (MIPS) can have many microarchitectures.
  2. Single-cycle characteristics: (a) each instruction finishes in one clock cycle, so CPI = 1; (b) the clock period must fit the slowest instruction (lw), so the clock is slow; (c) each hardware unit can be used only once per cycle, so we need separate instruction and data memories and separate adders (PC + 4, branch target) besides the ALU.

Answer: ISA = what (contract); microarchitecture = how (datapath + control). Single-cycle: CPI = 1, period = slowest instruction, units duplicated.

Galti mat karna: "Single-cycle = ek cycle = fast" sochna galat hai. CPI 1 hai, lekin woh ek cycle bahut lamba hai (lw jitna). Speed = CPI × Tc dono se decide hoti hai.
Ek line mein: ISA = menu, microarchitecture = kitchen (datapath + control); single-cycle mein har instruction ek lambe cycle mein, CPI = 1.

13.2 Fetch–Decode–Execute Cycle

Pehle socho: Tum recipe book se khana bana rahe ho. Har step ke liye: (1) bookmark wale page se agla step padho, bookmark aage khiskao; (2) samjho kya karna hai, kaunsa masala chahiye; (3) karo; (4) zaroorat ho to fridge (storage) se cheez lo ya rakho; (5) result plate mein rakh do. Phir agla step. CPU bhi har instruction ke saath yahi 5 kaam karta hai, forever. Bookmark ka naam hai PC.
Definition: The instruction cycle is the sequence a CPU repeats for every instruction: Fetch the instruction from memory at address PC and set PC ← PC + 4; Decode it and read the source registers; Execute the operation in the ALU; access data Memory if the instruction is a load or store; and Write back the result to a register.
Mushkil shabd, aasaan matlab:
PC (Program Counter)
32-bit register jisme agle instruction ka address hota hai. Bookmark. Jaise PC = 0x00400000 matlab agla instruction memory address 0x00400000 pe pada hai.
IR (Instruction Register)
Fetch kiya hua 32-bit instruction yahan rakha jaata hai (single-cycle mein ye seedha instruction memory ka output hai).
PC + 4
Har MIPS instruction 32 bit = 4 bytes ka hai, aur memory ka har address ek byte ko point karta hai. Isliye agla instruction 4 address aage hai. PC = 0x0040000C → PC + 4 = 0x00400010 (hex: C + 4 = 12 + 4 = 16 = 0x10, to 0C → 10).
decode
Instruction ke bits ko todna: opcode [31-26] dekh ke pata chalta hai kaunsa instruction hai, rs / rt fields se registers padhe jaate hain.
write-back
Result ko destination register mein likhna.
Kaise kaam karta hai (ek instruction ke 5 steps):
  1. F (Fetch): PC jo address bata raha hai, instruction memory se us address ka 32-bit word padho. Saath hi PC ← PC + 4 (agle instruction pe bookmark).
  2. D (Decode): Opcode control unit ko jaata hai. rs aur rt registers register file se padhe jaate hain.
  3. E (Execute): ALU kaam karta hai: R-type ke liye operation (add, sub), lw / sw ke liye address = base + offset, beq ke liye compare (subtract karke dekho zero aaya ya nahi).
  4. M (Memory): Sirf lw (memory se padho) aur sw (memory mein likho). Baaki instructions ye step skip karte hain.
  5. WB (Write-back): R-type, lw, addi apna result register mein likhte hain. sw aur beq kuch nahi likhte.
  6. Phir PC naya instruction point kar raha hai → wapas step 1. Single-cycle mein ye paanchon steps ek hi clock cycle ke andar ho jaate hain.

Solved example 1 (Lab question type):

Which steps does add $t2, $t0, $t1 use? Which instruction skips the write-back step?

  1. add ko instruction chahiye → Fetch haan.
  2. $t0, $t1 padhne hain → Decode haan.
  3. ALU mein jodna hai → Execute haan.
  4. add memory ko chhoota hi nahi (MIPS mein sirf lw / sw memory use karte hain) → Memory nahi.
  5. Result $t2 mein jaata hai → Write-back haan.
  6. sw memory mein likhta hai, kisi register mein nahi → sw write-back skip karta hai.

Answer: add uses F, D, E, WB (skips M). sw skips WB.

Solved example 2:

An instruction is fetched from address 0x0040001C. What is the PC after the fetch step?

  1. PC + 4 karna hai. Last hex digit: C = 12. 12 + 4 = 16.
  2. 16 hex mein = 0x10: last digit 0, aur 1 ka carry agle digit mein jaata hai.
  3. Agla digit 1 tha → 1 + 1 = 2.
  4. Baaki digits same: 0x00400020.

Answer: PC = 0x00400020 (PC is incremented by 4 bytes).

Galti mat karna: (1) PC + 1 mat likho, MIPS mein PC + 4 hai (byte address, 4-byte instruction). (2) "add memory step use karta hai" galat hai. (3) "sw register mein likhta hai" galat hai: sw ka $t0 sirf padha jaata hai.

Trick: add M skip, sw WB skip, beq dono skip. Sirf lw paanchon steps use karta hai, isliye wahi sabse lamba hai (13.5).

Ek line mein: Har instruction: Fetch (IR ← Mem[PC], PC ← PC + 4) → Decode (registers padho) → Execute (ALU) → Memory (sirf lw / sw) → Write-back (R-type, lw, addi).

13.3a The Datapath Components (what each part does and why it is there)

Pehle socho: Kitchen setup karne se pehle list banate ho: fridge (ingredients), recipe stand, chopping board, gas, plates. Har cheez kisi zaroorat ki wajah se hai. Datapath ka bhi aisa hi ek "shopping list" hai. Har block ko "ye kya karta hai" aur "iske bina kaunsa instruction nahi chalega" ke saath yaad karo, to diagram khud ban jaayega.
Definition: The single-cycle datapath consists of state elements (PC, register file, instruction memory, data memory), which hold values, and combinational elements (ALU, adders, sign-extend unit, shift-left-2, multiplexers), which compute outputs from inputs. Each element is used at most once per clock cycle.
Mushkil shabd, aasaan matlab:
state element
Jo value yaad rakhta hai (clock edge pe likhta hai). PC, register file, data memory.
combinational element
Jiska output sirf abhi ke inputs pe depend karta hai, kuch yaad nahi rakhta. ALU, adder, MUX.
sign-extend
16-bit number ko 32-bit banana, sign bit (bit 15) ko upar copy karke. 0x0004 (+4) → 0x00000004. 0xFFFC (−4) → 0xFFFFFFFC (abhi bhi −4). Upar zero bhar dete to −4 galti se +65532 ban jaata.
shift-left-2
Bits ko 2 jagah left khiskao, right mein do 0 daalo = × 4. 3 = 0011 → 1100 = 12. Branch offset "kitne instructions" mein hota hai, address "bytes" mein chahiye, isliye × 4.
MUX (multiplexer)
Railway points: do (ya zyada) tracks mein se ek ko aage jaane deta hai. Select = 0 → input 0 pass, select = 1 → input 1 pass.
Zero flag
ALU ka 1-bit output: result 0 hai to Zero = 1. beq ise use karta hai: $t1 − $t2 = 0 matlab dono barabar.
read port / write port
Register file ek saath 2 registers padh sakta hai (Read data 1, Read data 2) aur 1 register likh sakta hai (Write register + Write data, tabhi jab RegWrite = 1).
Kaise kaam karta hai (har component, ek ek karke):
  1. PC: 32-bit register, agle instruction ka address. Har clock edge pe naya value leta hai (PC + 4, ya branch / jump target). Kyun: bina PC ke pata hi nahi kahan se instruction lena hai.
  2. Instruction memory: Input = address (PC), output = 32-bit instruction. Sirf padhi jaati hai. Kyun: program yahin rakha hai.
  3. PC + 4 adder: Ek alag adder jiska ek input PC aur doosra constant 4. Kyun alag: ALU us cycle mein instruction ka kaam kar raha hai (single-cycle mein ek unit ek hi baar use ho sakti hai).
  4. Register file: 32 registers. Read register 1 ← bits [25-21] (rs), Read register 2 ← bits [20-16] (rt), Write register ← rt ya rd (RegDst MUX se). Outputs Read data 1, Read data 2. Kyun: MIPS ke saare operands registers mein hote hain.
  5. Sign-extend: bits [15-0] (immediate / offset) ko 32 bit banata hai. Kyun: ALU 32-bit hai; lw / sw ka offset, addi ka constant, beq ka offset 16-bit hote hain.
  6. ALU: do 32-bit inputs, ek 4-bit "ALU control" input (kaunsa operation), outputs = result + Zero. Kyun: add / sub / and / or / slt, address calculation, beq ka compare, sab yahin.
  7. Data memory: Address (ALU result se), Write data (Read data 2 se), Read data output; MemRead aur MemWrite signals. Kyun: lw / sw ke liye.
  8. Shift-left-2 + branch adder: sign-extended offset × 4, phir PC + 4 mein jodo → branch target. Kyun alag adder: ALU us waqt compare kar raha hai.
  9. MUXes (4 basic + 1 for jump): RegDst, ALUSrc, MemtoReg, PCSrc (+ Jump). Har MUX wahan hai jahan ek input ke do possible source hain (13.3b mein detail).
  10. Control unit + ALU control: opcode [31-26] → main control (saare signals); ALUOp + funct [5-0] → ALU control (4 bits).

Solved example 1 (MCQ type):

Which instruction bits drive Read register 1, and which drive Read register 2?

  1. R-format: op [31-26] | rs [25-21] | rt [20-16] | rd [15-11] | shamt [10-6] | funct [5-0].
  2. rs hamesha padha jaata hai → Read register 1 ← [25-21].
  3. rt bhi padha jaata hai (R-type ka doosra operand, sw ka data, beq ka doosra register) → Read register 2 ← [20-16].
  4. rd sirf likhne ke liye hai, isliye woh RegDst MUX mein jaata hai, read port pe nahi.

Answer: Read register 1 ← [25-21] (rs); Read register 2 ← [20-16] (rt).

Solved example 2 (write the answer like this):

Why does the single-cycle datapath need separate instruction and data memories and extra adders?

  1. In a single-cycle design, every instruction finishes in one clock cycle, so each hardware unit can be used only once per cycle.
  2. lw and sw need to fetch the instruction and access data in the same cycle, so one memory is not enough → separate instruction memory and data memory.
  3. In the same cycle the ALU is busy with the instruction's own operation, so PC + 4 and the branch target (PC + 4 + offset × 4) need their own adders.

Answer: one use per unit per cycle → two memories + PC + 4 adder + branch adder.

Galti mat karna: (1) rd ko Read register 2 pe mat jodo, woh rt [20-16] hai. (2) Branch offset pe shift-left-2 bhoolna: offset instructions mein hai, × 4 karke bytes banao. (3) Sign-extend ko zero-extend mat samjho: upar sign bit copy hota hai.
Ek line mein: PC → instruction memory → (rs, rt) register file + sign-extend → ALU → data memory → wapas register file; saath mein PC + 4 adder aur branch adder (shift-left-2), aur jahan do source milte hain wahan MUX.

13.3b Building the Datapath Step by Step (why each MUX is added)

Pehle socho: Ek gaon mein pehle ek hi sadak hai. Jab doosre gaon se bhi sadak aa ke usi pul pe milni hai, to pul pe ek signal / gate lagana padta hai jo batata hai abhi kis taraf ki gaadi jaayegi. Datapath mein bhi: pehle sirf R-type ke liye wires banao. Jab lw aata hai aur kisi input pe doosra source chahiye hota hai, wahan ek MUX lagao. Har MUX ek "do raaste, ek pul" ki kahani hai.
Definition: The datapath is built incrementally: start with the fetch unit, add the parts needed for R-type, then extend it for lw, sw, beq and j. Whenever two different sources must drive the same input, a multiplexer is inserted and its select line becomes a control signal.
Mushkil shabd, aasaan matlab:
select line
MUX ka control input. 2:1 MUX mein 1 bit: 0 → upar wala (input 0), 1 → neeche wala (input 1).
branch target
Jahan beq jump karega: PC + 4 + (offset × 4). Offset 16-bit signed hai (−32768 se +32767 instructions), isliye peeche (loop) aur aage dono ja sakte ho.
PCSrc
PC ke aage wale MUX ka select. PCSrc = Branch AND Zero.
jump target
j ke liye: (PC + 4) ke upar ke 4 bits [31:28] + 26-bit address × 4. Total 4 + 26 + 2 = 32 bits.
Kaise kaam karta hai (6 building steps):
  1. Fetch: PC → instruction memory; PC → adder (+4) → wapas PC. (Diagram D13.3b.)
  2. R-type (add $t1, $t2, $t3): rs, rt register file mein → Read data 1 aur Read data 2 → ALU ke dono inputs → ALU result → register file ka Write data; Write register = rd [15-11]. Abhi koi MUX nahi chahiye.
  3. lw ($t2 ← Mem[$t1 + 4]): teen nayi problems aati hain.
    (a) ALU ka doosra input ab register nahi, offset hai → sign-extend jodo, aur ALU ke doosre input pe ab do source (Read data 2 ya immediate) → ALUSrc MUX.
    (b) Data memory jodo (address = ALU result). Register mein ab likhna hai memory ka data, R-type mein ALU result → Write data pe do source → MemtoReg MUX.
    (c) lw ka destination rt [20-16] hai (I-format mein rd field hai hi nahi), R-type ka rd [15-11] → Write register pe do source → RegDst MUX.
  4. sw (Mem[$t1 + 4] ← $t2): address lw jaisa hi. Store karne wala data $t2 = rt, jo already Read data 2 pe aa raha hai → bas ek wire Read data 2 → data memory "Write data". Koi naya MUX nahi.
  5. beq ($t1 == $t2 ? jump): ALU subtract karta hai, Zero flag nikalta hai. Target banane ke liye sign-extend → shift-left-2 → branch adder (PC + 4 + offset × 4). Ab agla PC do jagah se aa sakta hai (PC + 4 ya target) → PCSrc MUX, jiska select = Branch AND Zero (ek AND gate).
  6. j (extension): target = PC+4[31:28] joined with (instr[25-0] × 4). Agla PC ka teesra source → Jump MUX (PCSrc MUX ke baad), select = Jump.

Solved example 1 (exam favourite):

State the function of each multiplexer in the single-cycle datapath.

  1. RegDst: chooses the destination register number: rt [20-16] (0) for lw / addi, rd [15-11] (1) for R-type.
  2. ALUSrc: chooses the ALU's second operand: Read data 2 (0) for R-type / beq, sign-extended immediate (1) for lw / sw / addi.
  3. MemtoReg: chooses the value written to the register: ALU result (0) or data read from memory (1, lw).
  4. PCSrc: chooses the next PC: PC + 4 (0) or branch target (1); select = Branch AND Zero.

Answer: RegDst = which register, ALUSrc = which ALU operand, MemtoReg = which data to write back, PCSrc = which next PC. (Basic datapath has 4 MUXes; with jump, 5.)

Solved example 2:

A j instruction is at address 0x00400018 and its 26-bit address field is 0x0100008. Find the jump target.

  1. PC + 4 = 0x0040001C. Iske upar ke 4 bits [31:28] = hex ka pehla digit = 0 → 0000.
  2. Address field × 4 (shift-left-2): 0x0100008 × 4 = 0x0400020 (8 × 4 = 32 = 0x20, 1 × 4 = 4 at the 0x100000 place).
  3. Jodo: 0000 (4 bits) + 0x0400020 ka 28-bit roop = 0x00400020.

Answer: jump target = 0x00400020.

Galti mat karna: PCSrc ko control unit ka seedha output mat bolo. Control sirf Branch deta hai; PCSrc = Branch AND Zero (ALU se). Branch = 1 lekin registers unequal → Zero = 0 → PCSrc = 0 → PC + 4.

Trick: Har MUX ka naam batata hai woh kya chunta hai: Reg-Dst = register destination, ALU-Src = ALU source, Mem-to-Reg = memory to register (1 matlab haan, memory ka data). Input 1 hamesha "naya / special" wala hai (rd, immediate, memory data, branch target).

Ek line mein: R-type se shuru, lw ne 3 MUX joda (ALUSrc, MemtoReg, RegDst), sw ne sirf ek wire, beq ne branch adder + PCSrc MUX, j ne Jump MUX.

13.3c Control Signals and the Main Control Table

Pehle socho: Railway station pe tracks (datapath) hamesha wahi rehte hain. Station master (control unit) har train (instruction) ke liye decide karta hai: kaunse points kis taraf karne hain (MUX selects) aur kaunse signal green karne hain (write enables). Train ka number (opcode) dekh ke woh ek fixed chart se settings uthata hai. Woh chart hi control table hai, aur exam mein yahi bharna hota hai.
Definition: The main control unit is a combinational circuit that takes the 6-bit opcode and produces the control signals RegDst, ALUSrc, MemtoReg, RegWrite, MemRead, MemWrite, Branch, ALUOp (2 bits) and Jump. The ALU control unit uses ALUOp and the funct field to produce the 4-bit ALU operation (two-level decoding). A value X (don't care) means the signal may be 0 or 1 because its effect is not used by that instruction.
Mushkil shabd, aasaan matlab:
control signal
Ek wire jiska 0 / 1 datapath ko ek decision batata hai. Jaise MemWrite = 1 → "is cycle memory mein likho".
asserted / deasserted
Asserted = 1 (ON), deasserted = 0 (OFF).
write enable
RegWrite, MemWrite. Ye 1 ho tabhi clock edge pe likhai hoti hai. 0 → kuch nahi badlega, chahe input pe kuch bhi ho.
X (don't care)
"Farak nahi padta". Jaise RegWrite = 0 hai to Write register kaunsa chuna (RegDst) koi farak nahi, kyunki likhna hi nahi hai. Designer X ko 0 ya 1 jo sasta ho rakh sakta hai.
ALUOp
2-bit signal main control se: 00 = "add karo", 01 = "subtract karo", 10 = "funct field dekho".
funct
R-type ke bits [5-0]: add 100000, sub 100010, and 100100, or 100101, slt 101010. Saare R-type ka opcode 000000 hai, funct batata hai asli operation.
two-level decoding
Pehle main control opcode se ALUOp banata hai, phir ALU control (ALUOp + funct) se 4-bit operation. Main control chhota rehta hai.

Har value ka WHY (row by row):

  1. R-type: destination rd → RegDst 1. Dono operands registers → ALUSrc 0. Result ALU se → MemtoReg 0. Register likhna hai → RegWrite 1. Memory nahi → MemRead 0, MemWrite 0. Branch nahi → 0. Operation funct batayega → ALUOp 10.
  2. lw: destination rt → RegDst 0. Address = rs + offset → ALUSrc 1. Register mein memory data → MemtoReg 1. RegWrite 1. Memory padhni hai → MemRead 1, MemWrite 0. Branch 0. Address ke liye add → ALUOp 00.
  3. sw: koi register nahi likhna → RegWrite 0, isliye RegDst aur MemtoReg ka chunav bekaar → X. Address = rs + offset → ALUSrc 1. Memory mein likhna → MemWrite 1, MemRead 0. Branch 0. ALUOp 00 (add).
  4. beq: register nahi likhna → RegWrite 0 → RegDst, MemtoReg = X. Compare do registers ka → ALUSrc 0. Memory nahi → 0, 0. Branch 1. Compare = subtract → ALUOp 01.
  5. addi: destination rt → RegDst 0. Constant → ALUSrc 1. Result ALU se → MemtoReg 0. RegWrite 1. Memory 0, 0. Branch 0. Add → ALUOp 00.
  6. j: sirf PC badalna hai. Jump MUX PCSrc wale raaste ko ignore karta hai, isliye Branch bhi X; ALU ka output kahin use nahi → ALUSrc, ALUOp X. Lekin RegWrite, MemRead, MemWrite = 0 pakka.

X ka rule: X sirf un signals pe jinka asar is instruction mein kahin nahi pahunchta. Write enables (RegWrite, MemWrite) kabhi X nahi: agar galti se 1 ho gaya to koi register ya memory word kharab ho jaayega. MemRead bhi 0 rakhte hain (bekaar read na ho). Branch sirf j mein X.

Solved example 1 (mock question):

Fill the control signals (Branch, MemtoReg, MemRead, MemWrite, ALUOp, ALUSrc, RegWrite, RegDst) for addi $t0, $t1, −4.

  1. addi I-format hai: rs = $t1 padho, constant −4 jodo, result rt = $t0 mein.
  2. Branch? Nahi → Branch = 0.
  3. Register mein ALU ka result jaata hai, memory ka nahi → MemtoReg = 0.

Answer: Branch 0, MemtoReg 0, MemRead 0, MemWrite 0, ALUOp 00, ALUSrc 1, RegWrite 1, RegDst 0.

Solved example 2:

sub $s0, $s1, $s2: give the ALUOp and the 4-bit ALU control input. Why does the main control not output the ALU operation directly?

  1. sub R-type hai → main control ALUOp = 10 ("funct dekho").
  2. funct of sub = 100010 → table se ALU control = 0110 (subtract).
  3. Saare R-type ka opcode same (000000) hai, isliye opcode se operation pata hi nahi chal sakta; funct chahiye. Two-level decoding se main control sirf opcode dekhta hai aur chhota rehta hai.

Answer: ALUOp = 10, ALU control = 0110; R-type operation is in funct, not opcode.

Galti mat karna: (1) ALUOp khaali chhodna (class ki har sample sheet mein chhoda gaya tha; free marks gaye). (2) lw ke liye RegDst = 1 likhna: lw ka destination rt hai → 0. (3) R-type mein MemRead = X likhna: 0 likho. (4) RegWrite ya MemWrite pe X likhna: kabhi nahi.

Trick: Columns RegDst ALUSrc MemtoReg RegWrite MemRead MemWrite Branch ALUOp ke order mein: R = 1001 000 10, lw = 0111 100 00, sw = X1X0 010 00, beq = X0X0 001 01. ALUOp: "lw/sw add, beq sub, R funct" = 00, 01, 10.

Ek line mein: Opcode → control signals; MUX selects batate hain kaunsa raasta, RegWrite / MemWrite batate hain likhna hai ya nahi; X sirf RegDst / MemtoReg pe jab RegWrite = 0 (aur j mein unused signals pe).

13.4 Tracing Different Instruction Types (add, lw, sw, beq)

Pehle socho: Courier ka parcel track karte ho: "Delhi hub → Jaipur hub → local office → ghar". Trace karna matlab yahi: instruction ka data kis block se kis block tak jaata hai, aur raaste mein har MUX pe kaunsa gate khula tha. Class ki chaaron worksheets yahi poochti hain: "Trace <instruction> and Fill the Control Signals".
Definition: Tracing an instruction on the datapath means highlighting the path its data takes from the PC to its destination (register, memory or PC), stating which MUX input is selected at each multiplexer, and writing the value of every control signal for that instruction.
Mushkil shabd, aasaan matlab:
active path
Woh wires jinpe is instruction ka kaam ka data chal raha hai (diagram mein orange). Baaki wires pe bhi kuch value hoti hai, par use nahi hoti.
Zero flag (reminder)
ALU result 0 → Zero = 1. beq mein $t1 − $t2 = 0 → barabar.
offset (beq)
"PC + 4 se kitne instructions aage". 3 → 3 × 4 = 12 bytes aage.
base + offset
lw / sw ka address: register (base) + constant (offset). 4($t1) = $t1 + 4.
Kaise trace karein (4 steps, har baar):
  1. Fetch path darken karo: PC → instruction memory; PC → +4 adder.
  2. Fields follow karo: [25-21] → Read reg 1, [20-16] → Read reg 2 (aur RegDst input 0), [15-11] → RegDst input 1, [15-0] → sign-extend, [5-0] → ALU control.
  3. Har MUX pe jo input use hua usse darken karo aur uska 0 / 1 likho.
  4. Destination pe khatam karo (register, memory ya PC) aur control row bharo; jis MUX ka output use nahi hua wahan X.

Trace 1 (actual numbers): add $t1, $t2, $t3 at PC = 0x00400000, with $t2 = 7, $t3 = 5.

  1. Fetch: instruction memory[0x00400000] = 0x014B4820 = 000000 01010 01011 01001 00000 100000. Adder: PC + 4 = 0x00400004.
  2. Fields: op = 000000 (R-type), rs = 01010 = 10 = $t2, rt = 01011 = 11 = $t3, rd = 01001 = 9 = $t1, funct = 100000 (add).
  3. Register file: Read data 1 = $t2 = 7, Read data 2 = $t3 = 5.
  4. ALUSrc = 0 → ALU ko 5 milta hai (immediate nahi). ALUOp = 10 + funct 100000 → ALU control 0010 (add). ALU result = 7 + 5 = 12, Zero = 0.
  5. Data memory use nahi (MemRead 0, MemWrite 0). MemtoReg = 0 → Write data = 12.
  6. RegDst = 1 → Write register = rd = 9 ($t1). RegWrite = 1.
  7. Branch = 0 → PCSrc = 0 → next PC = 0x00400004. Clock edge pe: $t1 = 12, PC = 0x00400004.

Diagram kaise padhein: Orange = active path. Upar se: PC → instruction memory, PC → +4 → PCSrc MUX ka input 0 → wapas PC. Instruction se rs, rt register file mein; rd neeche se RegDst MUX ke input 1 mein. Read data 1 seedha ALU, Read data 2 ALUSrc MUX ke input 0 se ALU. ALU result data memory ko bypass karke MemtoReg MUX ke input 0 se neeche wale lambe wire se wapas Write data pe. Funct [5-0] wire neeche ALU control tak jaata hai. Control oval se nikalti har dashed line pe uski value likhi hai (Branch = 0, MemRead = 0, MemtoReg = 0, ALUOp = 10, MemWrite = 0, ALUSrc = 0, RegWrite = 1, RegDst = 1). Dhyan do: MemtoReg MUX mein 1 upar (memory data) aur 0 neeche (ALU result) hai.

Trace 2: lw $t2, 4($t1) (0x8D2A0004) with $t1 = 0x10010000 and Mem[0x10010004] = 99.

  1. Fetch + PC + 4 (same as before).
  2. Fields: op 100011 (lw), rs = 01001 = $t1, rt = 01010 = $t2, imm = 0x0004.
  3. Read data 1 = $t1 = 0x10010000. (Read data 2 = $t2 ka purana value bhi niklega, par use nahi hoga.)
  4. Sign-extend: 0x0004 → 0x00000004. ALUSrc = 1 → ALU ka 2nd input = 4.
  5. ALUOp = 00 → add. ALU result = 0x10010000 + 4 = 0x10010004 → data memory Address.
  6. MemRead = 1 → Read data = 99.
  7. MemtoReg = 1 → Write data = 99. RegDst = 0 → Write register = rt = $t2. RegWrite = 1. Edge pe $t2 = 99.

Diagram kaise padhein: Ye sabse lamba raasta hai: instruction memory → register file → (immediate sign-extend → ALUSrc input 1) → ALU → data memory → MemtoReg input 1 → register file. rt wala wire RegDst MUX ke input 0 pe orange hai. Isi lambai ki wajah se lw clock period decide karta hai (13.5).

Trace 3: sw $t2, 4($t1) (0xAD2A0004) with $t1 = 0x10010000 and $t2 = 42.

  1. Fetch + PC + 4.
  2. rs = $t1 → Read data 1 = 0x10010000; rt = $t2 → Read data 2 = 42.
  3. Sign-extend 4, ALUSrc = 1, ALUOp = 00 → Address = 0x10010004.
  4. Read data 2 (42) seedha data memory ke "Write data" pe. MemWrite = 1 → edge pe Mem[0x10010004] = 42.
  5. RegWrite = 0: koi register nahi badla, isliye RegDst = X, MemtoReg = X.

Diagram kaise padhein: lw jaisa address path, lekin data memory pe raasta khatam: neeche se Read data 2 ka wire memory ke Write data mein jaata hai. Register file ki taraf wapas koi orange wire nahi.

Trace 4: beq $t1, $t2, L1 at PC = 0x00400010, offset = 3 (0x112A0003).

  1. Fetch; PC + 4 = 0x00400014.
  2. Read data 1 = $t1, Read data 2 = $t2. ALUSrc = 0 → ALU ko dono registers. ALUOp = 01 → subtract.
  3. Saath mein: offset 3 → sign-extend → shift-left-2 = 12 = 0xC → branch adder: 0x00400014 + 0xC = 0x00400020.
  4. Case A: $t1 = 5, $t2 = 5 → 5 − 5 = 0 → Zero = 1. Branch = 1 → PCSrc = 1 AND 1 = 1 → PC = 0x00400020 (branch taken).
  5. Case B: $t1 = 5, $t2 = 7 → 5 − 7 = −2 ≠ 0 → Zero = 0 → PCSrc = 0 → PC = 0x00400014 (not taken).
  6. RegWrite = 0, MemRead = 0, MemWrite = 0; RegDst = X, MemtoReg = X.

Diagram kaise padhein: Orange = taken path: offset → sign-extend → shift-left-2 → branch adder → PCSrc input 1 → PC. Blue = not-taken path (PC + 4 → PCSrc input 0). ALU se Zero wire upar AND gate tak jaata hai, AND ka doosra input Branch (dashed, control se).

Solved example 1 (mock passage, exam-level):

lw $s0, 8($sp) runs on the single-cycle datapath. $sp = 0x7FFFEFF8 and the word at 0x7FFFF000 is 25. (a) What address does the ALU compute? (b) What is written into $s0 and with which MemtoReg? (c) Machine code? (d) Control row.

  1. (a) Address = $sp + 8. Last digits: 0xF8 + 0x08 = 248 + 8 = 256 = 0x100 → last two digits 00, carry 1. Carry chain: 0xEF + 1 = 0xF0. So 0x7FFFEFF8 + 8 = 0x7FFFF000.
  2. (b) MemRead = 1 → memory gives 25. MemtoReg = 1 → 25 goes to $s0 (not the address).
  3. (c) op = 100011, rs = $sp = 29 = 11101, rt = $s0 = 16 = 10000, imm = 0000 0000 0000 1000. Group in 4s: 1000 1111 1011 0000 0000 0000 0000 1000 = 0x8FB00008.
  4. (d) Branch 0, MemtoReg 1, MemRead 1, MemWrite 0, ALUOp 00, ALUSrc 1, RegWrite 1, RegDst 0.

Answer: address 0x7FFFF000; $s0 = 25 via MemtoReg = 1; code 0x8FB00008; row 0 1 1 0 00 1 1 0.

Solved example 2 (write the answer like this, 5 marks):

Trace sw $t2, 4($t1) and fill the control signals.

  1. Fetch: PC → instruction memory gives the instruction; PC + 4 computed by the adder.
  2. Register read: rs = $t1 (Read data 1, base address) and rt = $t2 (Read data 2, data to store).
  3. Address: offset 4 is sign-extended, ALUSrc = 1 selects it, ALUOp = 00 → ALU adds: address = $t1 + 4.
  4. Memory: Read data 2 goes to Write data; MemWrite = 1 → Mem[$t1 + 4] ← $t2.
  5. No write-back: RegWrite = 0, so RegDst and MemtoReg are don't care. PCSrc = 0 → PC = PC + 4.

Answer: Branch 0, MemtoReg X, MemRead 0, MemWrite 1, ALUOp 00, ALUSrc 1, RegWrite 0, RegDst X.

Galti mat karna: (1) lw mein MemtoReg = 0 likhna → register mein address chala jaayega, data nahi. (2) beq mein ALUSrc = 1 likhna: beq do registers compare karta hai, offset ALU mein nahi jaata (woh branch adder mein jaata hai). (3) beq target = PC + offset likhna: sahi = PC + 4 + offset × 4.
Ek line mein: Trace = fetch path + fields + har MUX ka chuna hua input + destination; R-type rd mein ALU result, lw rt mein memory data, sw memory mein Read data 2, beq PC mein target (sirf Zero = 1 pe).

13.5 Critical Path and Clock Period

Pehle socho: School trip ki bus har stop pe utna rukti hai jitna sabse slow bachche ko time lagta hai, kyunki sab ek hi bus mein hain. Single-cycle CPU mein har instruction ko ek hi size ka clock cycle milta hai. To cycle itna lamba hona chahiye ki sabse slow instruction (lw) bhi khatam ho jaaye. Baaki instructions (add, beq) jaldi khatam ho ke bas khaali baithe intezaar karte hain. Yahi waste pipelining ki wajah hai.
Definition: The critical path is the longest combinational delay path between two state elements; it sets the minimum clock period. In the single-cycle MIPS datapath the critical path is that of lw: instruction memory → register read → ALU → data memory → register write (setup). Clock period Tc = delay of the slowest instruction, and clock frequency f = 1 / Tc.
Mushkil shabd, aasaan matlab:
propagation delay
Input badalne ke baad output sahi hone mein lagne wala time. Jaise ALU = 200 ps.
critical path
Sabse lamba raasta (delay ka total sabse zyada). Chain ki sabse kamzor kadi jaisa: poora system usi ki speed se chalega.
ps, ns, GHz
1 ps = 10−12 s, 1 ns = 1000 ps. f = 1 / T. 1 / 1 ns = 1 GHz. 1 / 800 ps = 1 / 0.8 ns = 1.25 GHz.
instruction class
Same raasta lene wale instructions ka group: R-type, lw, sw, beq, j.
Kaise calculate karein:
  1. Har instruction class ke liye likho kaunse units use hote hain (13.4 wali table): R-type = IMem + Reg read + ALU + Reg write; lw = IMem + Reg read + ALU + DMem + Reg write; sw = IMem + Reg read + ALU + DMem; beq = IMem + Reg read + ALU; j = IMem.
  2. Diye hue delays jodo, har class ka total.
  3. Sabse bada total = clock period (ye hamesha lw aayega).
  4. Frequency = 1 / period.
  5. Waste = period − us instruction ka apna time.

Diagram kaise padhein: Har row ek instruction class hai, rangeen tukde uske units (Instr mem, Reg read, ALU, Data mem, Reg write) ki lambai = delay. Right mein total. Formula: Tc = max(total delay of each instruction class) = tIMem + tRegRead + tALU + tDMem + tRegWrite (lw)
f = 1 / Tc · Program time = N × 1 × Tc
Harris & Harris version (more detailed): Tc = tpcq,PC + tmem + tRFread + tALU + tmem + tmux + tRFsetup; tpcq = PC ka clock-to-Q delay, tRFsetup = register file setup time.
Solved example 1 (easy):

Delays: instruction memory 200, register read 100, ALU 200, data memory 200, register write 100 ps. Find the single-cycle clock period, frequency, and the time wasted by beq in each cycle.

  1. lw = 200 + 100 + 200 + 200 + 100 = 800 ps (sabse lamba).
  2. Tc = 800 ps.
  3. f = 1 / 800 ps = 1 / (0.8 × 10−9 s) = 1.25 × 109 Hz = 1.25 GHz.
  4. beq = 200 + 100 + 200 = 500 ps. Waste = 800 − 500 = 300 ps.

Answer: Tc = 800 ps, f = 1.25 GHz, beq wastes 300 ps per cycle.

Solved example 2 (mock exam-level):

Single-cycle delays: instruction memory 250, register read 150, ALU 200, data memory 250, register write 150 ps. Find the delay of each instruction class, the clock period, the clock frequency, and the time to run 106 instructions.

  1. R-type = 250 + 150 + 200 + 150 = 750 ps.
  2. lw = 250 + 150 + 200 + 250 + 150 = 1000 ps.
  3. sw = 250 + 150 + 200 + 250 = 850 ps.
  4. beq = 250 + 150 + 200 = 600 ps. j = 250 ps.
  5. Sabse bada = lw = 1000 ps → Tc = 1000 ps = 1 ns.
  6. f = 1 / 1 ns = 1 GHz.
  7. Time = 106 × 1 (CPI) × 1 ns = 106 ns = 1 ms.

Answer: R 750, lw 1000, sw 850, beq 600, j 250 ps; Tc = 1000 ps; f = 1 GHz; 106 instructions take 1 ms.

Solved example 3 (Harris & Harris formula):

tpcq = 30, tmem = 250, tRFread = 150, tALU = 200, tmux = 25, tRFsetup = 20 ps. Find Tc.

  1. Memory do baar aata hai (instruction memory aur data memory).
  2. Tc = 30 + 250 + 150 + 200 + 250 + 25 + 20.
  3. 30 + 250 = 280; + 150 = 430; + 200 = 630; + 250 = 880; + 25 = 905; + 20 = 925.

Answer: Tc = 925 ps (f = 1 / 925 ps ≈ 1.08 GHz).

Solved example 4 (why single-cycle is inefficient, write like this):

Why is the single-cycle design inefficient? How much faster would an ideal variable-length clock be for a mix of 25 % lw, 10 % sw, 45 % R-type, 15 % beq, 5 % j (P&H delays)?

  1. Every instruction gets the full 800 ps, although R-type needs only 600, beq 500, j 200. Also each unit is busy only for a part of the cycle (when the ALU works, the instruction memory sits idle).
  2. Average needed time = 0.25 × 800 + 0.10 × 700 + 0.45 × 600 + 0.15 × 500 + 0.05 × 200.
  3. = 200 + 70 + 270 + 75 + 10 = 625 ps.
  4. Speedup = 800 / 625 = 1.28.
  5. Better fix: cut the datapath into 5 stages of about 200 ps and overlap instructions (pipelining, Unit 14): one instruction can finish every 200 ps → up to 800 / 200 = 4 times faster.

Answer: time wasted on short instructions and idle units; variable clock would be 1.28× faster; pipelining fixes it better.

Galti mat karna: (1) R-type ka delay clock period le lena: period = max = lw. (2) beq ya R-type mein data memory ka delay jod dena. (3) Average delay ko clock period bolna: single-cycle mein har cycle same length ka hota hai, average sirf "ideal variable clock" ke comparison ke liye hai.

Trick: P&H numbers yaad: 8-7-6-5-2 (×100 ps) = lw, sw, R, beq, j.

Ek line mein: Single-cycle clock = lw ka poora raasta (IMem + Reg + ALU + DMem + Reg); CPI 1 hai par clock slow, chhote instructions time waste karte hain, isliye pipelining.
