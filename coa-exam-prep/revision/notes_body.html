1. Boolean Algebra & Gates

Big picture

Abstraction stack (top to bottom): AI/ML models → applications & languages → OS → ISA → datapath & control → logic gates → transistors. The ISA is the contract between software and hardware.

Architecture = the “what” (programmer-visible: instructions, registers). Organisation = the “how” (hidden implementation: pipelines, caches, how ADD is built).

1 = TRUE = HIGH (about 3.3 V / 5 V); 0 = FALSE = LOW (0 V).

De Morgan in words: “break the bar, change the sign”.

“+” means OR, not addition: A + 1 = 1 (not 2). The distributive law A + BC = (A + B)(A + C) has no equivalent in ordinary algebra — students forget it exists.

Derivations of the laws you must be able to prove

Absorption: A + AB = A
  1. Take A out as a common factor: A + AB = A·1 + A·B = A(1 + B)
  2. Null law: 1 + B = 1
  3. So A(1 + B) = A · 1 = A
Absorption (AND form): A(A + B) = A
  1. Multiply out: A·A + A·B
  2. Idempotent: A·A = A, so we get A + AB
  3. By the previous result, A + AB = A
Redundancy: A + A'B = A + B
  1. Use the distributive law X + YZ = (X + Y)(X + Z) with X = A, Y = A', Z = B
  2. A + A'B = (A + A')(A + B)
  3. Complement: A + A' = 1
  4. So it is 1 · (A + B) = A + B
Combining: AB + AB' = A
  1. Take A out: A(B + B')
  2. B + B' = 1
  3. A · 1 = A
Consensus: XY + X'Z + YZ = XY + X'Z
  1. Multiply the extra term YZ by 1 = (X + X'): YZ = YZ(X + X') = XYZ + X'YZ
  2. Whole expression = XY + X'Z + XYZ + X'YZ
  3. Group: (XY + XYZ) + (X'Z + X'YZ)
  4. Absorption on each group: XY(1 + Z) = XY and X'Z(1 + Y) = X'Z
  5. Result = XY + X'Z (the YZ term was redundant)

Worked simplifications

Simplify A'B'C + A'BC + AB'C + ABC + A'B
  1. Look at the first four terms: they all contain C. Take C out: C(A'B' + A'B + AB' + AB)
  2. A'B' + A'B + AB' + AB is every combination of A and B, so it equals 1. (Check: A'(B' + B) + A(B' + B) = A' + A = 1)
  3. So the first four terms = C · 1 = C
  4. Expression = C + A'B
Complement of (A + B)(A' + C)
  1. First simplify: (A + B)(A' + C) = AA' + AC + A'B + BC = 0 + AC + A'B + BC
  2. BC is the consensus of AC and A'B, so it disappears → AC + A'B
  3. Complement: (AC + A'B)' = (AC)' · (A'B)' (De Morgan)
  4. = (A' + C')(A + B') (De Morgan again on each bracket)
  5. Multiply out: A'A + A'B' + AC' + B'C' = 0 + A'B' + AC' + B'C'
  6. B'C' is the consensus of A'B' and AC' → drops. Answer A'B' + AC'
Nested De Morgan: ((A + B)'C)' + (AB)'
  1. ((A + B)'C)' = ((A + B)')' + C' = (A + B) + C'
  2. (AB)' = A' + B'
  3. Sum = A + B + C' + A' + B'
  4. A + A' = 1, and 1 + anything = 1. Answer 1

2. K-maps & Universal Gates

Why minimise: fewer gates → less area, less power, faster, cheaper (“16 gates → 2 gates”).

Canonical forms

Minterm (for SOP): a row where F = 1. Variable 1 → write X, variable 0 → write X'. Example row 101 → m5 = AB'C.
Maxterm (for POS): a row where F = 0. Variable 0 → write X, variable 1 → write X'. Example row 011 → M3 = (A + B' + C').
F = Σm(rows where F = 1) = ΠM(all the other rows). The two index lists together are 0 to 2ⁿ − 1.

The POS rule is the OPPOSITE of the SOP rule (0 → plain variable). This flip is the number-one trap.

F = Σm(1, 3, 5, 7) for A, B, C
  1. Rows 001, 011, 101, 111 → SOP = A'B'C + A'BC + AB'C + ABC
  2. POS uses the other rows 0, 2, 4, 6 → (A + B + C)(A + B' + C)(A' + B + C)(A' + B' + C)
  3. Simplify the SOP: A'C(B' + B) + AC(B' + B) = A'C + AC
  4. = C(A' + A) = C. (Every listed row has C = 1 and the others have C = 0.)

Karnaugh maps

Rows/columns are in Gray code: 00, 01, 11, 10 (neighbours differ in ONE bit).
Group only 1s (and don't-cares) in rectangles of size 1, 2, 4, 8, 16 (powers of 2). The map wraps around: left edge touches right edge, top touches bottom, the four corners form one group.
A group of 2ᵏ cells removes k variables. Keep only the variables that do not change inside the group.
Make groups as LARGE as possible and as FEW as possible; overlap is allowed; diagonal groups are not.
Why grouping works
  1. Two cells side by side differ in exactly one variable, say B: e.g. A'BC' and A'B'C'.
  2. Add them: A'C'(B + B') = A'C'. The changing variable B disappears.
  3. A group of 4 = two such pairs differing in another variable → that one disappears too. So each doubling removes one variable.
F(A,B,C,D) = Σm(0, 2, 5, 7, 8, 10, 13, 15)
  1. Corners m0 (0000), m2 (0010), m8 (1000), m10 (1010): in all four, B = 0 and D = 0; A and C change → group = B'D'
  2. Centre m5 (0101), m7 (0111), m13 (1101), m15 (1111): B = 1 and D = 1 everywhere; A and C change → BD
  3. F = B'D' + BD = (B ⊙ D), the XNOR of B and D.
F(A,B,C,D) = Σm(0, 1, 2, 5, 8, 9, 10)
  1. Corners 0, 2, 8, 10 → B'D'
  2. m0, m1, m8, m9 (B = 0, C = 0; A and D change) → B'C'
  3. m5 (0101) is still uncovered. Pair it with m1 (0001): A = 0, C = 0, D = 1 stay fixed → A'C'D
  4. F = B'D' + B'C' + A'C'D

Don't-cares (X): input combinations that never happen (e.g. BCD 10–15). Treat an X as 1 if it makes a group bigger, otherwise as 0; never group Xs alone.

Prime implicant (PI) = a group that cannot be made larger. Essential PI (EPI) = a PI that is the only one covering some 1. The minimal SOP = all EPIs + the fewest extra PIs to cover the remaining 1s. A cyclic map (e.g. Σm(0,1,2,5,6,7)) has no EPI: answer A'B' + BC' + AC.

De Morgan & bubble pushing

NAND = OR with inverted inputs: (AB)' = A' + B'.   NOR = AND with inverted inputs: (A + B)' = A'B'.
Two bubbles on the same wire cancel (double inversion).

SOP (AND–OR) → NAND–NAND. POS (OR–AND) → NOR–NOR. (A + B)(C + D) with only 2-input NANDs needs 6.
CMOS: NAND = 4 transistors, AND = 6 (AND is NAND + inverter) → fabs prefer NAND.
Building each gate from NAND
  1. NOT: NAND(A, A) = (A·A)' = A'
  2. AND: NAND then NOT: ((AB)')' = AB → 2 gates
  3. OR: NAND(A', B') = (A'B')' = A + B (De Morgan). A' and B' each cost one NAND → 3 gates
XOR from 4 NANDs
  1. Gate 1: X = (AB)' = A' + B'
  2. Gate 2: P = (A·X)'. Inside: A·X = A(A' + B') = AA' + AB' = AB'. So P = (AB')'
  3. Gate 3: Q = (B·X)'. Inside: B(A' + B') = A'B. So Q = (A'B)'
  4. Gate 4: (P·Q)' = P' + Q' = AB' + A'B = A ⊕ B
Why SOP becomes NAND–NAND: F = AB + CD
  1. Double complement changes nothing: F = ((AB + CD)')'
  2. De Morgan on the inner bar: (AB + CD)' = (AB)'·(CD)'
  3. So F = ((AB)'·(CD)')' → a NAND of two NANDs. Three 2-input NANDs.
  4. Same idea for POS: F = (A + B)(C + D) = ((A + B)' + (C + D)')' → NOR of two NORs.

3. MUX, Decoders, Adders, ALU

Multiplexer (data selector)

2:1 MUX: Y = S'·I0 + S·I1
4:1 MUX: Y = S1'S0'·I0 + S1'S0·I1 + S1S0'·I2 + S1S0·I3
n select lines → 2ⁿ inputs (8:1 needs 3 selects). A 2ⁿ:1 MUX built from 2:1 MUXes needs 2ⁿ − 1 of them (4:1 → 3; 8:1 → 7).
A 2ⁿ:1 MUX can implement ANY function of n variables; a 2ⁿ:1 MUX can also do n + 1 variables using the “residue” trick (inputs 0, 1, X or X').
Implement F(A,B,C) = Σm(1, 3, 5, 6) with a 4:1 MUX (S1 = A, S0 = B)
  1. For each value of AB, see what F does as C changes.
  2. AB = 00: rows 000 (m0, F = 0) and 001 (m1, F = 1) → F = C → I0 = C
  3. AB = 01: rows 010 (m2, 0) and 011 (m3, 1) → F = C → I1 = C
  4. AB = 10: rows 100 (m4, 0) and 101 (m5, 1) → F = C → I2 = C
  5. AB = 11: rows 110 (m6, 1) and 111 (m7, 0) → F = C' → I3 = C'

XOR on a 4:1 MUX with S1 = A, S0 = B: I0 = 0, I1 = 1, I2 = 1, I3 = 0.

A decoder is a DEMUX whose data input is tied to 1 (the enable).

Full adder from a 3-to-8 decoder: Sum = D1 + D2 + D4 + D7; Cout = D3 + D5 + D6 + D7.

Half adder

From the truth table
  1. A B → Sum Carry: 00 → 0 0; 01 → 1 0; 10 → 1 0; 11 → 0 1 (1 + 1 = 10 in binary)
  2. Sum is 1 when the inputs differ → Sum = A'B + AB' = A ⊕ B
  3. Carry is 1 only for 11 → Carry = A·B
  4. Limitation: no carry-in, so it cannot be chained.

Full adder

Sum = A ⊕ B ⊕ Cin (odd parity)    Cout = AB + Cin(A ⊕ B) = AB + BCin + ACin (majority)
Sum derivation
  1. Sum = 1 on rows 001, 010, 100, 111 → Σm(1, 2, 4, 7) = A'B'C + A'BC' + AB'C' + ABC (C = Cin)
  2. Group by A: A'(B'C + BC') + A(B'C' + BC)
  3. B'C + BC' = B ⊕ C, and B'C' + BC = (B ⊕ C)'
  4. So Sum = A'(B ⊕ C) + A(B ⊕ C)' — this is the XOR pattern X'Y + XY' with X = A, Y = B ⊕ C
  5. Sum = A ⊕ B ⊕ C
Cout derivation
  1. Cout = 1 on rows 011, 101, 110, 111 → A'BC + AB'C + ABC' + ABC
  2. Group the last two: ABC' + ABC = AB(C' + C) = AB
  3. Group the first two: A'BC + AB'C = C(A'B + AB') = C(A ⊕ B)
  4. Cout = AB + C(A ⊕ B)

Full adder from two half adders + OR: HA1(A, B) → S1 = A ⊕ B, C1 = AB. HA2(S1, Cin) → Sum = S1 ⊕ Cin, C2 = S1·Cin. Cout = C1 + C2. The OR is safe because C1 and C2 can never both be 1 (if A = B = 1 then S1 = 0 so C2 = 0).

Ripple-carry adder and carry-lookahead

n-bit RCA = n full adders, Cout of stage i → Cin of stage i + 1, Cin0 = 0 (or 1 for subtraction).
Delay grows linearly: about 2 gate delays per bit → 4-bit ≈ 8, 64-bit ≈ 128 gate delays.
Carry-lookahead: Generate Gi = Ai·Bi, Propagate Pi = Ai ⊕ Bi, C(i+1) = Gi + Pi·Ci.
Expanding the lookahead carries (no waiting for ripple)
  1. C1 = G0 + P0·C0
  2. C2 = G1 + P1·C1 = G1 + P1(G0 + P0C0) = G1 + P1G0 + P1P0C0
  3. C3 = G2 + P2·C2 = G2 + P2G1 + P2P1G0 + P2P1P0C0
  4. Every carry is now a 2-level AND-OR of the inputs → roughly constant delay per block, at the cost of more area.

ALU (preview, researched)

1-bit ALU slice = AND gate + OR gate + full adder + MUX selecting the operation. Subtract with Binvert = 1 and carry-in = 1 (A + B' + 1).
ALU control: 0000 AND, 0001 OR, 0010 add, 0110 subtract, 0111 slt. Zero flag = NOR of all result bits (1 when the result is 0).

4. Number Systems & Two's Complement

Conversions

Value = Σ (digit × baseposition), positions counted from 0 on the right.
Powers of 2: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024.  1 hex digit = 4 bits; 1 octal digit = 3 bits.
Hex digits: A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.
Binary → decimal: 101101
  1. Write the weights under the bits: 1×32, 0×16, 1×8, 1×4, 0×2, 1×1
  2. Add the weights where the bit is 1: 32 + 8 + 4 + 1 = 45
Decimal → binary: 42
  1. 42 ÷ 2 = 21 remainder 0
  2. 21 ÷ 2 = 10 remainder 1
  3. 10 ÷ 2 = 5 remainder 0
  4. 5 ÷ 2 = 2 remainder 1
  5. 2 ÷ 2 = 1 remainder 0
  6. 1 ÷ 2 = 0 remainder 1
  7. Read the remainders from the BOTTOM up: 101010. Check: 32 + 8 + 2 = 42 ✓
Binary ↔ hex: 10110101
  1. Split into groups of 4 from the right: 1011 | 0101
  2. 1011 = 8 + 2 + 1 = 11 = B; 0101 = 4 + 1 = 5 → 0xB5
  3. To decimal: B × 16 + 5 = 11 × 16 + 5 = 176 + 5 = 181
Also: 0x2A = 0010 1010 = 2 × 16 + 10 = 42.   0xFF = 255.

Two's complement

Negate: invert every bit, then add 1 (−x = x' + 1).
Shortcut: from the right, copy bits up to and including the first 1, then invert everything to its left.
Why “invert and add 1” gives −x
  1. In n bits, x + x' = 111…1 (every column is 0 + 1 or 1 + 0) = 2ⁿ − 1
  2. So x' + 1 = 2ⁿ − x
  3. An n-bit register throws away the 2ⁿ carry (works modulo 2ⁿ), so 2ⁿ − x behaves exactly like −x
−18 in 8 bits
  1. +18 = 16 + 2 = 00010010
  2. Invert: 11101101
  3. Add 1: 11101110 → −18 = 11101110
  4. Check with the MSB weight: −128 + 64 + 32 + 8 + 4 + 2 = −128 + 110 = −18 ✓
−45 in 8 bits
  1. 45 = 32 + 8 + 4 + 1 = 00101101
  2. Invert: 11010010
  3. Add 1: 11010011

  2. Unsigned: 128 + 32 + 16 + 4 + 2 + 1 = 183
  3. Signed: −128 + 32 + 16 + 4 + 2 + 1 = −128 + 55 = −73
Same bits, different meaning: 11111111 = 255 unsigned = −1 signed. 10000000 = −128 (the most negative 8-bit value).

Sign extension

To widen a two's-complement number, copy the MSB (sign bit) into every new bit. +5 = 0101 → 0000 0101; −5 = 1011 → 1111 1011. Zero-padding −5 would give +11 (wrong).
MIPS: 16-bit 0xFFFB → 0xFFFFFFFB = −5. Unsigned values (lbu, andi/ori/xori) are zero-extended.
Why copying the sign bit keeps the value (negative case)
  1. Old MSB of an n-bit number has weight −2ⁿ⁻¹
  2. After adding one more 1 on top: the new top bit has weight −2ⁿ and the old top bit becomes +2ⁿ⁻¹
  3. Their sum: −2ⁿ + 2ⁿ⁻¹ = −2·2ⁿ⁻¹ + 2ⁿ⁻¹ = −2ⁿ⁻¹ — the same as before, so the value does not change

Addition, subtraction, overflow

A − B = A + B' + 1. Adder–subtractor: each Bi goes through XOR with M, and M is also the carry-in. M = 0 → A + B; M = 1 → A + B' + 1 = A − B.
Signed overflow V = C(into MSB) ⊕ C(out of MSB) = C3 ⊕ C4 for 4 bits.
Rule: overflow only when two numbers of the same sign give a result of the opposite sign. Adding numbers of opposite signs never overflows.
Unsigned overflow (carry flag CF) = C4, the carry out of the MSB. In subtraction (A + B' + 1), carry = 1 means NO borrow.
Why V = C3 ⊕ C4 (look only at the MSB column: a3, b3, carry-in c3)
  1. Case a3 = b3 = 0 (both positive): sum bit = c3, carry out c4 = 0. Overflow when c3 = 1 (result looks negative) → c3 = 1, c4 = 0 → they differ.
  2. Case a3 = b3 = 1 (both negative): c4 = 1 always; sum bit = c3. Overflow when c3 = 0 (result looks positive) → c3 = 0, c4 = 1 → they differ.
  3. Case a3 ≠ b3 (mixed signs): c4 = c3, never overflow → they are equal.
  4. So overflow ⇔ c3 ≠ c4 ⇔ V = c3 ⊕ c4

  2. 0101 + 1100 + 1: 0101 + 1101 = 1 0010
  3. Drop the carry → 0010 = 2 ✓ (carry = 1 → no borrow)

5. Latches, Flip-Flops & Timing

Combinational: output depends only on present inputs (adder, MUX). Sequential: output depends on inputs + stored state (counter, register). The difference is a feedback loop. Two inverters in a loop = bistable = 1-bit memory with no way to change it.

SR latch

NOR SR latch (active-HIGH): Q = (R + Q')', Q' = (S + Q)'.
S R: 00 hold · 10 set (Q = 1) · 01 reset (Q = 0) · 11 forbidden (Q = Q' = 0; releasing both together → race, unpredictable).
NAND SR latch (active-LOW S', R'): 11 hold · 01 set · 10 reset · 00 forbidden (Q = Q' = 1).
Characteristic equation: Q⁺ = S + R'Q, with SR = 0.
Deriving Q⁺ = S + R'Q
  1. Table of (S, R, Q) → Q⁺: hold rows 000 → 0, 001 → 1; reset rows 010 → 0, 011 → 0; set rows 100 → 1, 101 → 1; forbidden rows 110, 111 → X
  2. Q⁺ = 1 on 001, 100, 101; X on 110, 111
  3. Group 100, 101, 110, 111 (S = 1) → S. Group 001 and 101 (R = 0, Q = 1) → R'Q
  4. Q⁺ = S + R'Q

D latch (level-triggered)

S = D·EN, R = D'·EN → S and R can never both be 1 → no forbidden state.
EN = 1: transparent (Q follows D, glitches pass). EN = 0: holds. Q⁺ = EN·D + EN'·Q.

D flip-flop (edge-triggered)

At each active (rising) edge: Q⁺ = D; between edges Q is frozen. Triangle on the clock pin = edge-triggered.
Master–slave: two D latches on opposite clock phases. Master transparent while CLK = 0, slave while CLK = 1 → value just before the rising edge reaches Q (positive-edge). The class slide enables the master on CLK = 1 → output changes on the FALLING edge. The two latches are never transparent together.
Verilog: always @(posedge clk) q <= d; (non-blocking <=, q declared reg).

Timing

t_setup: D stable this long BEFORE the edge. t_hold: stable this long AFTER the edge. t_pcq (clock-to-Q): edge → Q valid.
Setup (max-delay) check: T_c ≥ t_pcq + t_pd(logic) + t_setup → f_max = 1 / T_c
Hold (min-delay) check: t_ccq + t_cd(logic) ≥ t_hold — independent of the clock, so slowing the clock never fixes it; add delay to the short path.
Unit help: 1 / (1 ns) = 1 GHz; 1 / (1 ps) = 1000 GHz; 1 ns = 1000 ps.
Why T_c ≥ t_pcq + t_pd + t_setup
  1. At a clock edge, flip-flop 1 launches new data. It appears at its Q after t_pcq.
  2. The data travels through the logic, taking t_pd.
  3. It must arrive at flip-flop 2 at least t_setup before the NEXT edge.
  4. So the gap between edges (T_c) must cover all three: T_c ≥ t_pcq + t_pd + t_setup.

Ring oscillator: an ODD number N of inverters in a loop → T = 2 · N · t_pd, f = 1/T.

6. Registers, Counters, Shift Registers

Registers

n-bit register = n D flip-flops sharing one clock. PC, IR, general registers and pipeline registers are all registers.
Load enable = a 2:1 MUX before each D: Q⁺ = LOAD·D + LOAD'·Q (LOAD = 0 feeds Q back → hold). Never AND the clock with LOAD (skew, glitches).
Synchronous reset: acts only at the clock edge (always @(posedge clk) if (rst)). Asynchronous reset: acts immediately (always @(posedge clk or posedge rst)), used for power-on.
Lab priority: reset > load > hold.

Counters

Counting rule: a bit toggles exactly when ALL lower bits are 1 (0111 → 1000).
Bit k runs at f_clk / 2^(k+1): Q0 = f/2, Q1 = f/4, Q2 = f/8.
Flip-flops for a mod-N counter = ⌈log₂ N⌉ = smallest k with 2ᵏ ≥ N.
Ripple counter: settle time = n × t_pd, f_max = 1 / (n × t_pd).
Synchronous up counter with T FFs: T0 = 1, T1 = Q0, T2 = Q0·Q1, T3 = Q0·Q1·Q2.
With D FFs: D0 = Q0', D1 = Q1 ⊕ Q0, D2 = Q2 ⊕ (Q1·Q0). Down counter: T1 = Q0', T2 = Q0'·Q1' (toggle when all lower bits are 0).
How many flip-flops? (powers: 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024)
  1. mod-6: 4 < 6 ≤ 8 = 2³ → 3 FFs
  2. mod-12: 8 < 12 ≤ 16 = 2⁴ → 4 FFs
  3. mod-20: 16 < 20 ≤ 32 = 2⁵ → 5 FFs
  4. mod-1000 (1 MHz → 1 kHz): 512 < 1000 ≤ 1024 = 2¹⁰ → 10 FFs
  5. 32,768 Hz → 1 Hz: 32,768 = 2¹⁵ → 15 divide-by-2 stages
Ripple counter speed
  1. 4-bit, t_pd = 10 ns: settle = 4 × 10 = 40 ns → f = 1 / 40 ns = 1000 / 40 MHz = 25 MHz
  2. 16-bit, 10 ns: 160 ns → 1000 / 160 = 6.25 MHz
  3. 12-bit, 0.6 ns: 12 × 0.6 = 7.2 ns → 1000 / 7.2 MHz ≈ 138.9 MHz (≈ 139 MHz)
(1 / ns = 1000 MHz.)
Deriving T0 = 1, T1 = Q0, T2 = Q0Q1 (3-bit up counter)

7. Register Files & FSMs

Register file

MIPS / RISC-V: 32 registers × 32 bits, 2 read ports + 1 write port (an R-type reads 2 and writes 1 per cycle).
Address bits per port = log₂(number of registers) (32 → 5; 64 → 6; 16 → 4). Total flip-flops = registers × width (16 × 8 = 128; 32 × 32 = 1024).
Write port (synchronous): write address → n-to-2ⁿ decoder → each output AND RegWrite → load enable of one register; write data goes to all; only the enabled one captures it at the edge. “Decoder picks WHERE, WE picks WHETHER.”
Read ports (combinational): every register feeds TWO 32:1 MUXes; Read register 1/2 are the 5-bit selects. No clock → operands ready in the same cycle.
Register 0 ($zero / x0) always reads 0; writes to it are ignored.

Finite state machines

FSM = (S, I, O, δ, λ): δ = transition (next-state) function, λ = output function.
Hardware: next-state logic (combinational) → state register (the only flip-flops) → output logic, with the present state fed back.
Moore: output = λ(state) — written INSIDE the circle; changes only with the state; glitch-free; output one cycle later; often one more state.
Mealy: output = λ(state, input) — written ON the arrow (in/out); same-cycle output; fewer states; can glitch.
Flip-flops: binary encoding ⌈log₂ N⌉; one-hot N.

Design flow: understand the spec → state diagram → state table → encode states → next-state and output equations (K-maps) → build/simulate.

8. SRAM, DRAM & Memory Hierarchy

Flip-flops cost 20+ transistors per bit → too expensive for gigabytes. Core tension: fast memory is small and expensive; big memory is slow and cheap.

SRAM — 6T cell

6T = 4 transistors (two cross-coupled inverters, store Q and Q') + 2 access transistors (M5, M6). Word line (WL) = select the cell; bit lines BL and BL' = data and its complement.
Static: the feedback loop holds the bit (actively) while powered — no refresh.
Read: (1) precharge both bit lines high; (2) raise WL; (3) the side storing 0 pulls its bit line slightly low; (4) sense amplifier detects which side dropped. Non-destructive.
Write: (1) drive BL/BL' to the new value; (2) raise WL; (3) strong drivers overpower the latch; (4) latch flips and holds.
A few ns, low density, expensive, static power → caches, register files, buffers.

DRAM — 1T1C cell

1 access transistor + 1 storage capacitor (charged = 1, empty = 0) → about 6× denser than SRAM.
Dynamic: the charge leaks (full → lost in about 64 ms), so the controller reads and rewrites every row about every 64 ms.
Destructive read: (1) the capacitor shares its charge with the bit line; (2) a tiny signal; (3) sense amplifier swings it to 0/1; (4) write-back. Every read = read + rewrite.
50–100 ns, cheap per bit → main memory, GPU memory (GDDR).
Per-row refresh interval = retention time ÷ number of rows. Fraction of time busy = row refresh time ÷ interval.

9. Von Neumann vs Harvard

A computer = CPU + memory + I/O + bus (bus = address + data + control lines).
Stored-program concept (von Neumann, “First Draft of a Report on the EDVAC”, 1945): the program lives in the SAME memory as data, as numbers. Change the program by loading new numbers.
Von Neumann: one memory, one shared bus; four classic components: control unit, memory, ALU, I/O.
Von Neumann bottleneck (term by John Backus, 1977): fetch and data access must take turns on one bus → contention, IPC capped, idle ALU, worse as CPUs get faster. Fixes: caches, wider buses, Harvard split.
Harvard: separate instruction and data memories + two buses → fetch AND data access in ONE cycle (up to 2× throughput). Name from the Harvard Mark I (1944): instructions on punched tape, data in relays. Used in DSPs, real-time systems, microcontrollers (ATmega328 / Arduino Uno = true Harvard).
Modified Harvard (every modern CPU): split L1-I / L1-D caches (Harvard inside) over unified L2/L3 and DRAM (Von Neumann outside). ARM Cortex-M4 and x86-64 are modified Harvard.
Bandwidth = bits moved per cycle × clock frequency ÷ 8 (bytes per second).
1 GHz, 32-bit instruction + 32-bit data every cycle
  1. Bits per cycle = 32 + 32 = 64
  2. Per second = 64 × 10⁹ bits = 64 Gbit/s
  3. Bytes: 64 ÷ 8 = 8 GB/s on the single Von Neumann bus
  4. Harvard: each bus carries 32 bits × 10⁹ ÷ 8 = 4 GB/s

10. CISC vs RISC

ISA = the hardware/software contract (software compiles TO it, hardware EXECUTES it).
CISC: hundreds of instructions, variable length (x86: 1–15 bytes), memory operands (add [mem1], [mem2]), complex decoder, often microcode, denser code. x86, VAX, 68000.
RISC: few simple instructions, fixed 32-bit length, load/store only (only lw/sw touch memory), simple decoder, easy to pipeline, more instructions per task. MIPS, ARM, RISC-V, SPARC.
RISC hallmarks = fixed length + load/store. Complexity moves: CISC → hardware, RISC → compiler.
Iron law: CPU time = instruction count × CPI × clock period (= IC × CPI ÷ f).

Why RISC pipelines well: fixed length (next instruction is always 4 bytes on); uniform format (decode in one stage); one simple step each; only lw/sw access memory (predictable hazards). Code density is CISC's edge; ARM Thumb and RISC-V “C” (16-bit) close the gap.

History: CISC — VAX (1977), 68000 (1979), x86 (1978) → x86-64 (2003). RISC — IBM 801 → MIPS (Stanford, Hennessy, 1984), SPARC, ARM (1985), RISC-V (Berkeley, 2010). ARM won mobile (low power, licensing); x86 kept the desktop (compatibility). MIPS: PlayStation 1 (R3000A), N64, PS2. Hennessy & Patterson: 2017 Turing Award.

Modern reality: x86 decodes each CISC instruction into RISC-like micro-ops (µops) (e.g. add [mem], eax → load, add, store) and pipelines/reorders them — CISC outside, RISC inside, for compatibility plus speed. RISC-V: open, royalty-free, modular. Domain-specific ISAs: NVIDIA PTX (GPUs), Google TPU (matrix multiply).

“RISC runs fewer instructions” is false — fewer instruction TYPES, usually MORE instructions executed. The ISA alone does not decide speed.

13. Single-Cycle Datapath

Single-cycle: every instruction finishes in ONE clock cycle → CPI = 1, but the clock period = the SLOWEST instruction (lw). Each unit used once per cycle → separate instruction and data memories, extra adders.
Steps: Fetch (IR ← Mem[PC], PC ← PC + 4) → Decode (read registers, control from opcode) → Execute (ALU) → Memory (lw/sw only) → Write-back (R-type, lw, addi).
Field → hardware: [31-26] opcode → Control; [25-21] rs → Read reg 1; [20-16] rt → Read reg 2 and RegDst input 0; [15-11] rd → RegDst input 1; [15-0] → sign-extend; [5-0] funct → ALU control.

  1. Highlight the fetch path: PC → instruction memory, PC → +4 adder.
  2. Follow the fields: rs → Read reg 1; rt → Read reg 2 (or destination for lw/addi); rd for R-type; immediate → sign-extend.

14. Pipelining (bonus — researched)

Five stages: IF (fetch, PC + 4) · ID (decode, read registers) · EX (ALU / address) · MEM (lw/sw) · WB (write register). Pipeline registers between them: IF/ID, ID/EX, EX/MEM, MEM/WB (data, destination register number and control travel along). Register file: written in the first half, read in the second half of a cycle.
Cycles for n instructions in a k-stage pipeline = k + (n − 1).
Speedup = n·k ÷ (k + n − 1) → k for large n (balanced stages, no hazards).
Pipelined clock = slowest stage + pipeline-register overhead. Pipelining improves THROUGHPUT, not latency.
Why k + n − 1
  1. The first instruction needs all k cycles to come out of the last stage.
  2. After that, one more instruction finishes every cycle.
  3. The remaining n − 1 instructions add n − 1 cycles → total k + n − 1.
  4. Non-pipelined: n·k cycles. Ratio n·k ÷ (k + n − 1); as n grows, the k − 1 becomes tiny next to n, so the ratio → k.
P&H stages 200, 100, 200, 200, 100 ps
  1. Single-cycle clock = 200 + 100 + 200 + 200 + 100 = 800 ps
  2. Pipelined clock = slowest stage = 200 ps
  3. 3 lw instructions: single-cycle 3 × 800 = 2400 ps; pipelined (5 + 2) × 200 = 1400 ps
  4. Long program speedup = 800 ÷ 200 = 4 (not 5, because stages are unbalanced)
  5. Latency of one instruction = 5 × 200 = 1000 ps (longer than 800!)
With overhead: stages 250, 350, 150, 300, 200 ps + 20 ps register overhead → non-pipelined 1250 ps; clock = 350 + 20 = 370 ps; speedup = 1250 ÷ 370 ≈ 3.38. Laundry (4 stages × 30 min, 4 loads): sequential 16 × 30 = 8 h; pipelined (4 + 3) × 30 = 210 min = 3.5 h.

15. Hazards (bonus — researched)

Structural: two instructions need the same hardware (one memory for IF and MEM) → fix with split I/D memory. Data: operand not ready yet → forwarding / stall. Control: next PC unknown until a branch resolves → stall, predict, delayed branch.
RAW (read after write, true dependence) is the ONLY data hazard in the in-order 5-stage pipeline, because every instruction reads in ID (stage 2) and writes in WB (stage 5) in program order. WAR and WAW appear only in out-of-order machines (fixed by register renaming).
No forwarding: back-to-back dependent instructions → 2 stalls. With forwarding: ALU → ALU → 0 stalls; load-use → 1 stall.
Forwarding paths: EX/MEM → EX (producer 1 ahead) and MEM/WB → EX (producer 2 ahead). ForwardA/B: 00 register file, 10 EX/MEM, 01 MEM/WB.
Why 2 stalls without forwarding (add $s0, … then sub …, $s0, …)
  1. add: IF in cycle 1, ID 2, EX 3, MEM 4, WB 5 — $s0 written in the first half of cycle 5.
  2. sub normally reads registers in ID in cycle 3.
  3. It may read only in the second half of cycle 5 (after the write), so its ID must move from cycle 3 to cycle 5.
  4. 5 − 3 = 2 stall cycles.
Why load-use needs 1 stall even with forwarding
  1. lw: EX in cycle 3, data comes out of memory at the END of MEM (cycle 4).
  2. The next instruction wants it at the START of its EX, normally cycle 4.
  3. Data from the end of cycle 4 cannot be used at the start of cycle 4 (that would be backwards in time).
  4. Delay the user's EX to cycle 5 (1 stall), then forward MEM/WB → EX.
Forwarding conditions (same for Rt):
EX hazard: if EX/MEM.RegWrite and EX/MEM.Rd ≠ 0 and EX/MEM.Rd = ID/EX.Rs → ForwardA = 10
MEM hazard: if MEM/WB.RegWrite and MEM/WB.Rd ≠ 0 and NOT the EX hazard and MEM/WB.Rd = ID/EX.Rs → ForwardA = 01
Load-use detection (in ID): if ID/EX.MemRead and (ID/EX.Rt = IF/ID.Rs or ID/EX.Rt = IF/ID.Rt) → stall (hold PC and IF/ID, zero the control into ID/EX).
Stall cost: CPI = 1 + stall cycles per instruction.
Compiler scheduling (a = b + e; c = b + f): original order lw, lw, add, sw, lw, add, sw has two load-use stalls → 5 + 6 + 2 = 13 cycles. Move the third lw up (lw, lw, lw, add, sw, add, sw) → no stalls → 5 + 6 = 11 cycles. Never move an instruction past one it depends on.

Control hazards: branch decided in MEM → 3 wrong-path instructions; decide in ID → 1-cycle penalty; predict not-taken (flush if taken); 2-bit dynamic predictors; MIPS delayed branch (the instruction after a branch always runs).
