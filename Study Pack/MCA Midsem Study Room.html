Boolean Algebra, Gates & the Abstraction Stack

Lecture L01 (11 Aug)Lab 1 Verilog gatesStudy-pack quiz L01
1

Intuition first

A computer is a tower of layers. Each layer hides the one below it, so a Python programmer never thinks about transistors, and a chip designer never thinks about Python. This course climbs the middle of that tower: gates → datapath → ISA.

At the very bottom, a transistor is just a switch: ON or OFF. We call ON “1” (voltage present, ~3.3 V/5 V) and OFF “0” (≈0 V). Everything (numbers, text, images, instructions) is a pattern of these two values. Reliability comes from only having to tell “voltage” from “no voltage”.

Mental picture: AND = two switches in series (both must close for current to flow). OR = two switches in parallel (either one is enough). NOT = a switch that is closed when you are not pressing it.

Architecture vs Organisation (asked often): Architecture is the what, the programmer-visible interface (which instructions exist, how registers/memory look). Organisation is the how, the hidden implementation (how ADD is built, pipelines, caches, clock).

Absorption: A + AB = A

  2. AB + A′C + ABC + A′BC = AB(1 + C) + A′C(1 + B)

Exam traps & one-line memory hooks

  • “+” is OR, not addition: A + 1 = 1 (not 2).
  • OR vs XOR: they differ only in the last row (1,1): OR = 1, XOR = 0.
  • NAND ≠ AND: the bubble inverts the output.
  • OR distributes over AND in Boolean algebra: A + BC = (A+B)(A+C). Ordinary algebra has no such rule, so students forget it.
  • Always verify a simplification with a truth table until the laws are automatic.
  • Hook: “Break the bar, flip the sign” for De Morgan.

QGATE CSE 2019
Which one of the following is NOT a valid identity?
  • A. (x⊕y)⊕z = x⊕(y⊕z)
  • B. (x + y)⊕z = x⊕(y + z)
  • C. x⊕y = x + y, if xy = 0
  • D. x⊕y = (xy + x′y′)′
Show answer

B. One counter-example is enough: x = 1, y = 1, z = 0 gives LHS = (1+1)⊕0 = 1 but RHS = 1⊕(1+0) = 0 ✗. A is associativity (true). C: if xy = 0 the (1,1) row never happens, so XOR = OR (true). D: xy + x′y′ is XNOR; its complement is XOR (true).

QExam-style
Simplify A + A′B + AB′ and name each law.
Show answer

A + A′B = A + B (redundancy). Then A + B + AB′ = A + AB′ + B = A + B (absorption). Answer: A + B.

QExam-style
How many distinct Boolean functions of n variables exist? Evaluate for n = 2.
Show answer

A truth table has 2ⁿ rows; each row’s output can be 0 or 1 independently → 2^(2ⁿ) functions. For n = 2: 2⁴ = 16 (AND, OR, XOR, NAND … are 6 of them).

QExit ticket
Where does the ISA sit relative to logic gates and Python in the abstraction stack?
Show answer

Python (applications) → OS → ISA → datapath & control → logic gates → transistors. The ISA is above gates/datapath and below the OS/languages: it is the hardware/software contract.

QExam-style
Prove (A + B)(A + C) = A + BC algebraically.
Show answer

(A+B)(A+C) = AA + AC + AB + BC = A + AC + AB + BC = A(1 + C + B) + BC = A + BC. ✓

QExam-style
Simplify F = XY + X′Z + YZ. Is YZ needed?
Show answer

No. YZ is the consensus of XY and X′Z (the variable X appears true in one, complemented in the other; the leftover literals Y and Z form the consensus term). F = XY + X′Z.

Logic Minimisation, K-Maps & Universal Gates

Lecture L02 (13 Aug)Lecture L03 (18 Aug)Lab 2: 35-question minimisation setAdded: PI/EPI, POS from K-map, NAND–NAND / NOR–NOR
1

Intuition first

A truth table tells you what a circuit must do. Many different circuits do the same thing; minimisation finds the cheapest one. Fewer gates means smaller silicon area (more chips per wafer), less switching power, shorter gate chains (faster clock) and lower cost. A 4-variable function can collapse from 16 gates to 2.

K-map idea: re-draw the truth table so that cells that touch differ in exactly one variable (Gray code 00, 01, 11, 10). When two adjacent cells are both 1, that one variable is both 0 and 1 inside the group, so it cancels: AB′C + ABC = AC(B′ + B) = AC. Every doubling of a group cancels one more variable. Your eye does the algebra.

Universal gates: NAND alone (or NOR alone) can build NOT, AND and OR, so it can build anything. Fabs like NAND because a CMOS NAND needs 4 transistors while an AND needs 6.

Formal definitions, examples & stepwise numericals

A. Canonical forms

Minterm (mᵢ)A product (AND) term containing every variable once, true for exactly one input row. Variable = 1 → write it plain; = 0 → complement it. Row A=1,B=0,C=1 → 101₂ = 5 → m₅ = AB′C.

B. K-map rules

  1. Order rows/columns in Gray code 00, 01, 11, 10.
  2. Groups must be rectangles of size 1, 2, 4, 8, 16 (powers of 2). No diagonals, no groups of 3 or 6.
  3. Make every group as large as possible and use as few groups as possible. Overlap is allowed.
  4. The map wraps like a donut: left↔right edges, top↔bottom edges, and all four corners are adjacent.
  5. Inside a group, a variable that changes is dropped; a variable that stays 1 is written plain; one that stays 0 is complemented.
  6. Don't-cares (X) may be taken as 1 when they make a group bigger, otherwise as 0. Never form a group of only X's.
Prime implicant (PI)A group that cannot be made any bigger. Essential PI (EPI): a PI that is the only one covering some 1. Minimal SOP = all EPIs + the fewest extra PIs to cover the remaining 1s.

Exam traps & one-line memory hooks

  • SOP: 1 → X, 0 → X′. POS: 0 → X, 1 → X′. Say the rule out loud every time.
  • K-map columns are Gray code (00, 01, 11, 10), not binary.
  • Diagonal cells are never adjacent. Groups of 3 or 6 are illegal.
  • Always check edge wrap-around and the 4-corner group before finalising.
  • Don't-cares are optional: use only those that enlarge a group.
  • Stopping De Morgan after one bar is the most common slip.
  • NAND is not “more powerful” than AND+OR+NOT; it is self-sufficient.

Minimum number of 2-input NAND gates to implement F = (A + B)(C + D)?
  • A. 3
  • B. 4
  • C. 5
  • D. 6
Show answer

D. 6. Rewrite F = C(A+B) + D(A+B) and share A+B:

G1 = NAND(A,A) = A′, G2 = NAND(B,B) = B′, G3 = NAND(G1,G2) = A+B, G4 = NAND(C,G3), G5 = NAND(D,G3), G6 = NAND(G4,G5) = C(A+B) + D(A+B) = (A+B)(C+D).

The obvious method (build A+B and C+D, then AND them) costs 8. An exhaustive computer search done for this page confirms 6 is the minimum. With 2-input NOR gates the answer is just 3: NOR(NOR(A,B), NOR(C,D)).

Intuition first

Nobody designs a CPU one gate at a time. Engineers use a small parts catalogue (MUX, decoder, adder, register) and repeat those parts millions of times. Test one block once; trust every copy.

Mental pictures. MUX = railway switch: many tracks in, the lever (select) decides which train reaches the single output. DEMUX = the reverse: one track fans out to one of many destinations. Decoder = a hotel key-card reader: an n-bit room number lights exactly one of 2ⁿ room lamps (one-hot). Adder = grade-school column addition with “carry the 1”.

B. MUX as a universal function generator (FPGA LUT idea)

Connect the input variables to the select lines and tie each data input to the constant the truth table needs. A 2ⁿ:1 MUX implements any n-variable function. XOR(A,B) with a 4:1 MUX: S1=A, S0=B, I0=0, I1=1, I2=1, I3=0.

Why Cout = AB + Cin(A⊕B) equals the majority form
  1. Cin(A⊕B) = Cin(A′B + AB′) = A′B·Cin + AB′·Cin
  2. AB + A′BCin + AB′Cin: add the redundant ABCin twice (idempotent)
  3. = (AB + ABCin) + (A′BCin + ABCin) + (AB′Cin + ABCin) = AB + BCin + ACin ✓
  4. Also: HA1 carry (AB) and HA2 carry (S1·Cin) are never both 1 (if A=B=1 then S1=0), so a plain OR (or even XOR) merges them.

F. Ripple-carry adder and its delay

Chain n full adders; Cout of stage i → Cin of stage i+1. Each stage must wait for the carry from the previous one, so worst-case delay grows linearly: ≈ 2 gate delays per stage (Cin→Cout path) → 4-bit ≈ 8, 64-bit ≈ 128 gate delays.

Worked: 0111 + 0001 on a 4-bit ripple adder (Lab 4 vectors)
  1. bit0: 1+1+0 = 0 carry 1
  2. bit1: 1+0+1 = 0 carry 1
  3. bit2: 1+0+1 = 0 carry 1
  4. bit3: 0+0+1 = 1 carry 0
  5. Result 1000 (= 8), Cout = 0. The carry rippled through bits 0→1→2→3.

Other Lab 4 vectors: 0001+0001 = 0010 (Cout 0); 1111+0001 = 0000 Cout 1 (ripples through all 4 stages); 1000+1000 = 0000 Cout 1 (immediate carry out of bit 3).

G. Carry-lookahead (the fix, from Lab 4)

Generate Gᵢ = AᵢBᵢ Propagate Pᵢ = Aᵢ ⊕ Bᵢ Cᵢ₊₁ = Gᵢ + PᵢCᵢ, Sᵢ = Pᵢ ⊕ Cᵢ C1 = G0 + P0C0 C2 = G1 + P1G0 + P1P0C0 C3 = G2 + P2G1 + P2P1G0 + P2P1P0C0 C4 = G3 + P3G2 + P3P2G1 + P3P2P1G0 + P3P2P1P0C0

Every carry is a 2-level SOP of the inputs, so all carries are ready after ≈3 gate delays (1 for G/P, 2 for the AND-OR) regardless of position, at the cost of more and wider gates (area vs speed). With fan-in-2 gates and a tree structure, an n-bit lookahead adder takes Θ(log n) time.

H. Adder–subtractor and the CPU preview (ALU + register file)

A − B = A + B′ + 1. Put an XOR on each B input controlled by K: K = 0 passes B (add), K = 1 inverts B and also feeds Cin = 1 (subtract). One adder does both jobs. An ALU computes AND, OR, ADD (and SUB via Binvert) in parallel and a MUX chooses the result using the operation code; a Zero flag (NOR of all result bits) supports beq. The register file (Topic 7) is built from these same blocks: a decoder picks the register to write, MUXes pick the registers to read.

Intuition first

An adder only moves bits by rules; it has no idea what they mean. Meaning is a convention we choose. The same byte 11111111 is 255 if you read it unsigned and −1 if you read it as two’s complement. The CPU only knows which you meant from the instruction you use.

Odometer picture: a 4-bit register is a car odometer with 16 positions arranged in a circle. Count up from 1111 and it rolls to 0000. Two’s complement simply relabels the top half of the circle as negative numbers, so “one step back from 0000” (1111) means −1. Adding still just walks around the circle, which is why one adder handles signed and unsigned numbers alike.

Why hex? One hex digit = exactly 4 bits (a nibble), two hex digits = one byte. It is binary written compactly for humans (colours #FF8800, addresses, MAC addresses).

D. Sign extension

To widen a two’s-complement number, copy the sign bit into the new upper bits. +5: 0101 → 0000 0101. −5: 1011 → 1111 1011 (still −5). Zero-padding −5 would give 0000 1011 = +11 (wrong). MIPS uses sign extension for lb, addi, lw offsets and branch offsets; zero extension for lbu, andi, ori. Verilog (Lab 5): assign y = { {4{a[3]}}, a };

Rules: 0+0 = 0, 0+1 = 1, 1+1 = 10, 1+1+1 = 11. Subtraction A − B = A + (B′ + 1): negate B and add, discard the carry out of the MSB for signed results.

Intuition first

Everything so far forgets instantly: output = f(inputs now). A CPU must remember (the PC, registers, state). The trick is feedback: route an output back into an input and the circuit can hold itself up.

Pictures. Two inverters in a ring are a seesaw that rests on either side (bistable): a 1-bit memory you can’t change. A latch adds handles to push the seesaw (Set/Reset). A D latch is a window: while EN is high you see through it (Q follows D); when EN drops, the picture freezes. A flip-flop is a camera: it takes one photo exactly at the clock edge. Setup/hold is “keep still just before and just after the shutter”, otherwise the photo blurs (metastability).

With S = R = 1 both NOR outputs are 0, so Q = Q′ = 0 (breaks Q′ = NOT Q). If S and R then drop to 0 together the gates race and the final state is unpredictable (simulation shows oscillation or X). Characteristic equation: Q⁺ = S + R′Q with the constraint SR = 0.

NAND SR latch (S′R′ latch): inputs are active-low. S′ = 0 sets, R′ = 0 resets, S′ = R′ = 1 holds, and S′ = R′ = 0 is forbidden (both outputs go to 1).

Gated SR latch: AND each input with an enable E; when E = 0 the latch holds regardless of S and R.

C. D latch (level-triggered)

Feed S = D·EN and R = D′·EN. S and R can never both be 1, so the forbidden state is engineered away. EN = 1 → transparent (Q = D); EN = 0 → hold. Problem: any glitch on D while EN is high passes straight to Q.

D. D flip-flop (edge-triggered) and master–slave

Q takes the value of D at the clock edge and holds for the whole cycle: Q⁺ = D. Built as two D latches in series on opposite clock phases (master EN = CLK, slave EN = CLK′); they are never transparent together, so data advances one step per cycle. With this wiring Q changes on the falling edge; swap the phases for a rising-edge FF. The small triangle (▷) on the clock pin marks edge triggering.

Intuition first

One flip-flop stores one bit. Put n of them side by side on one shared clock and you store an n-bit word that updates atomically: that is literally what a CPU register is. Chain them output-to-input and bits march along like a conveyor belt (shift register). Feed a register its own value + 1 and it counts (counter). The program counter is just a counter that can also be loaded.

Rule that makes counters easy: watch binary counting 000, 001, 010, 011, 100… A bit flips exactly when all bits below it are 1. Q0 flips every clock, Q1 when Q0 = 1, Q2 when Q1Q0 = 1. That is the whole design of a binary up-counter.

Formal definitions, examples & stepwise numericals

A. Registers: load enable, reset, CPU preview

Registern D flip-flops sharing a clock. A plain FF captures D on every edge, so a useful register adds a load enable: a 2:1 MUX in front of each D chooses new data (LOAD = 1) or the FF’s own output (LOAD = 0 → hold). Reset forces all bits to 0, synchronously (on the edge) or asynchronously (immediately). Priority in Lab 7 Q2: rst > load > hold.

CPU registers: PC (address of next instruction), IR (current instruction), general-purpose registers (32 × 32-bit in MIPS/RISC-V), pipeline registers. They are the fastest storage, sitting right beside the ALU.

Register Files & Finite State Machines (1011 detector)

Lecture L09 (8 Sep) MCA_Lecture_7Lecture L10 (10 Sep)Lab 8 sequence-detector FSMs (Lab8 PDF)Lab: register-file Verilog assignmentAdded: next-state equations, encodings
1

Intuition first

An instruction like add $t0, $t1, $t2 must read two registers and write one in a single cycle. A register file is a tiny, ultra-fast memory inside the CPU built for exactly that: 2 read ports + 1 write port. A decoder chooses where to write, the write-enable chooses whether, and a big MUX per read port chooses what to read.

FSM picture: a board game. You are always on exactly one square (state). The dice (input) and the square you are on decide where you move next (transition). Moore = each square has a prize printed on it (output depends on state only). Mealy = the prize is printed on the arrow you take (state + input), so it can react in the same cycle and usually needs fewer squares.
2

Formal definitions, examples & stepwise numericals

A. Register file

DefinitionA bank of N registers of W bits with addressed access. MIPS/RISC-V: 32 × 32-bit, 2 read ports, 1 write port. Address width = log₂N bits (5 for 32 registers). Storage = N × W flip-flops.
  • Write port: write address → log₂N-to-N decoder → AND with WE → that register’s load enable; it captures WD on the clock edge (synchronous).
  • Read ports: each read address is the select of an N:1 MUX (W bits wide) over all register outputs; data appears after gate delay, no clock (combinational).
  • Reads instant, writes wait for the edge → read old operands early in the cycle, compute, write the result at the edge (read-before-write). The new value is readable next cycle.
  • $zero / x0 is hard-wired to 0: reads give 0, writes are ignored (lab assignment “R0 always reads zero even under repeated writes”).
  • Alternative read design: tri-state buffers on a bus. Enabling two at once = bus contention (a hardware fault).
Sizing (study-pack quiz)
  1. 64 registers → write address = log₂64 = 6 bits
  2. 16 registers × 8 bits → 16 × 8 = 128 flip-flops; read address 4 bits
  3. 8 × 16 register file (homework) → 3-to-8 write decoder, 128 FFs, two 8:1 16-bit MUXes

B. Finite state machines

Formal definitionAn FSM is a tuple (S, I, O, δ, λ, s₀): finite set of states S, inputs I, outputs O, transition function δ: S × I → S, output function λ, and reset state s₀. Moore: λ: S → O. Mealy: λ: S × I → O.

Anatomy: next-state combinational logic → state register (flip-flops on the clock) → output logic. In a Mealy machine the input also feeds the output logic directly.

Six-step design flow: 1 understand the problem → 2 state diagram → 3 state table → 4 encode states (binary needs ⌈log₂N⌉ FFs; one-hot needs N FFs but simpler logic) → 5 K-map next-state and output bits → 6 build with FFs + gates. Every FSM needs a reset state; route unused encodings back to reset.

Why is the register-file read combinational but the write synchronous?
Show answer

SRAM vs DRAM & the Memory Stack

Lecture L10 (10 Sep) MCA_Lecture_8 SRAM vs DRAMLab L12 notesAdded: hierarchy numbers, locality, memory wall, AMAT, refresh numericals
1

Intuition first

The register file is blazing fast but tiny (32 words, and flip-flops cost 20+ transistors per bit). Programs need gigabytes. No single memory is fast, big and cheap, so computers layer them: small-fast on top, big-slow below.

Picture: SRAM stores a bit actively — two inverters holding each other up, like two people leaning back-to-back; as long as power is on, they never fall. DRAM stores a bit passively — water in a leaky bucket (capacitor). Tiny and cheap, but it leaks within milliseconds, so someone must keep refilling the buckets (refresh), and looking inside empties it (destructive read).

The hierarchy works because programs show locality: temporal (what you used recently you’ll use again: loop variables) and spatial (you’ll use neighbours of what you just used: array elements). So a small cache catches most accesses.

2

Formal definitions, examples & stepwise numericals

A. SRAM: 6T cell

Static RAMEach bit is a bistable latch of two cross-coupled inverters (4 transistors) plus two access transistors (M5, M6) connecting the cell to the bit lines BL and BL′ when the word line is high. “Static”: holds its value with no refresh as long as power is on.
  • Read: precharge both bit lines high → raise WL → the side storing 0 pulls its bit line slightly low → a sense amplifier detects which line dropped. Non-destructive.
  • Write: drive BL/BL′ to the new value → raise WL → the strong bit-line drivers overpower the cell → the latch flips and holds.
  • Self-reinforcing: if Q = 1, inverter 1 drives Q′ = 0, inverter 2 drives Q back to 1. Leakage is corrected instantly.

B. DRAM: 1T1C cell

Dynamic RAMEach bit is charge on a capacitor (charged = 1) behind one access transistor. “Dynamic”: the charge leaks, so every row must be read and rewritten periodically (typically every 64 ms).
  • Read: WL opens the transistor; the capacitor shares its tiny charge with the long bit line, nudging its voltage slightly; a sense amplifier amplifies to a full 0/1 and then writes the value back because the read drained the cell (destructive read). Row activation + precharge give ~50–100 ns latency.
  • Refresh: a refresh controller cycles through all rows; during refresh that part of memory is briefly unavailable (performance and power cost).

Von Neumann vs Harvard Architectures

Lecture L11 (15 Sep) MCA_Lecture_9MCA_Lecture_8_Architecture_Intro.pdfLab L13 notes
1

Intuition first

We now own every part: ALU (compute), registers and memory (store). The organisation question is how CPU, memory and I/O are wired together, and especially how many paths to memory there are.

Picture: Von Neumann is a single-lane bridge between a city (CPU) and a warehouse (memory): recipe cards (instructions) and ingredients (data) share the lane and must take turns. Harvard builds two bridges: one for recipe cards, one for ingredients, so both cross at once. Modern laptops have one warehouse (DRAM) but two private side-roads right next to the city (split L1-I and L1-D caches).
2

Formal definitions, examples & stepwise numericals

A. Von Neumann architecture (stored-program concept)

DefinitionA single memory holds both instructions and data, encoded as numbers in one address space, reached over a single shared bus. Described by John von Neumann in the First Draft of a Report on the EDVAC (1945), drawing on Eckert, Mauchly and Turing. Four classic components: control unit (fetches/decodes, an FSM), ALU, memory, I/O.

Before it, machines were rewired by hand for each task. After it, running a new program means loading different numbers. Because programs are data: compilers/assemblers write programs as data, the OS loads a program by copying bytes and jumping to them, JIT compilers generate code at run time, and self-modifying code is possible (powerful, and a source of security exploits).

B. The Von Neumann bottleneck

DefinitionInstruction fetches and data accesses share one bus, so they cannot happen in the same cycle; the CPU computes faster than the bus can feed it. Term coined by John Backus (1977 Turing lecture).

Effects: bus contention, capped IPC, idle ALUs, and it gets worse as CPUs speed up faster than memory. Responses: caches, wider/faster buses, and Harvard-style splits.

C. Harvard architecture

DefinitionSeparate instruction and data memories with independent buses, so an instruction fetch and a data access occur in the same cycle (up to 2× memory throughput). Name from the Harvard Mark I (1944): instructions on punched tape, data in relay counters.

D. Modified Harvard (what your laptop really is)

Outside the chip: one unified DRAM (Von Neumann: simple, flexible). Inside: the L1 cache is split into L1-I and L1-D (Harvard: parallel fetch + data every cycle). L2/L3 are unified. Hardware keeps the split caches coherent so software sees one memory. Examples: x86-64 desktops and ARM Cortex-M4 = modified Harvard; ATmega328 (Arduino Uno) = true Harvard; pure Von Neumann is now rare.

CISC vs RISC: Design Philosophies

Lecture L12 (17 Sep) MCA_Lecture_10Lab 11 MIPS history slideAdded: ISA timeline details, iron law of performance
1

Intuition first

The ISA (instruction set architecture) is the contract between software and hardware: compilers produce it, chips execute it. As long as both honour it, either side can change independently (Intel redesigns a chip and your old programs still run).

Picture: CISC is a Swiss-army knife: one complex tool does a whole job (“add memory to memory”) but is bulky to make. RISC is a set of simple, identical screwdrivers: each does one small thing quickly, and the compiler combines them. The complexity never disappears; it moves between the hardware (CISC) and the compiler (RISC).

C. Compiler implications and code density

  • CISC: denser code → fewer bytes fetched, less pressure on the instruction cache; but compilers struggle to use the complex instructions (most programs use a small subset), and the decoder is large and power-hungry.
  • RISC: the compiler does more work (register allocation over 32 registers, instruction scheduling to avoid pipeline stalls); fixed 32-bit encoding wastes some space. Compressed encodings (ARM Thumb, RISC-V “C”, 16-bit) recover much of the density.
  • Why RISC pipelines well: fixed length (easy fetch), uniform formats (one-stage decode), mostly 1-cycle ops (smooth flow), load/store only (predictable memory hazards).

D. Modern reality and trends

Modern x86 is CISC outside, RISC inside: the front-end decoder splits each x86 instruction into simple micro-ops (µops) (e.g. add [mem], eax → load µop, add µop, store µop) which the back-end pipelines, renames and reorders like a RISC machine. Meanwhile RISC ISAs grew (hundreds of instructions, SIMD/vector extensions). Today the microarchitecture (caches, pipelines, predictors) matters more than the label. Success depends on ecosystems, power budgets and compatibility: ARM won mobile (power, licensing), x86 held desktops/servers (software base).

RISC-V: open and royalty-free, a small base (RV32I) plus optional extensions (M, A, F, D, C, V), used from classrooms to microcontrollers to data-centre/AI chips. Domain-specific ISAs: GPU ISAs (NVIDIA PTX) for massive parallelism; Google TPU’s ISA centred on matrix multiply for neural networks.

Intuition first

A 32-bit instruction is not magic: it is a handful of labelled bit-fields. The first 6 bits (opcode) tell the CPU which of three layouts to use for the remaining 26 bits. Once you know the three layouts you can decode raw hex into assembly by hand.

Picture: three envelope templates of the same size. R = “two senders, one receiver, which-operation note” (register ops). I = “one register, one register, one 16-bit number” (immediates, loads/stores, branches). J = “just a big address” (jumps). The R-format fields rs, rt (read) and rd (write) are exactly the two read ports and one write port of the register file.

Why MIPS for teaching: clean, fixed 32-bit, only three formats, 32 registers, load/store, MARS simulator, decades of textbooks (Patterson & Hennessy); and RISC-V shares its DNA.

D. Details students get wrong

  • Sign-extended immediates: addi, addiu, lw, sw, lb, slti, branches. Zero-extended: andi, ori, xori. addi $t0,$t0,−1 → imm 0xFFFF → 0xFFFFFFFF.
  • lb of byte 0xF0 → 0xFFFFFFF0; lbu → 0x000000F0.
  • addu/addiu do the same arithmetic as add/addi; they just don’t trap on overflow.
  • $zero gives free instructions: move = addu rd,$zero,rs; nop = sll $zero,$zero,0; li small = addiu rt,$zero,imm.
  • Pseudo-instructions: li (32-bit) = lui + ori; la = lui + ori; blt = slt + bne; bge = slt + beq; ble $a,$b = slt $at,$b,$a + beq.

C-to-MIPS Translation: Control Flow, Loops & Functions

Lecture L14 (24 Sep) MCA_Lecture_12Lab 11 + lab assignments (even/odd, arrays, factorial, Fibonacci)Added: leaf-function example, array indexing, corrected while-loop exit
1

Intuition first

High-level code is structured (if, while, functions). Assembly is flat: a list of instructions plus labels. A compiler “flattens” each C construct with a fixed idiom of compares, branches and jumps. Learn a handful of idioms and you can translate anything.

Key trick: reverse the condition. C says “if (a == b) do X”. MIPS says “if (a != b) skip X” (bne Skip). You branch away on the opposite test. Functions are a relay race: the caller hands the baton in $a0–$a3, jumps with jal (which remembers the way back in $ra), the callee returns the result in $v0 and jumps back with jr $ra.

B. if, if/else, and the slt idiom

# if (a == b) c = a + b; $t0=a, $t1=b, $t2=c bne $t0, $t1, Skip # reversed condition add $t2, $t0, $t1 Skip: # if (a == b) c = 1; else c = 0; bne $t0, $t1, Else li $t2, 1 j Done # essential: don't fall into the else Else: li $t2, 0 Done: # if (a > b) c = a; else c = b; (a > b is b < a) slt $t3, $t1, $t0 # t3 = (b < a) beq $t3, $zero, Else # flag 0 -> a <= b move $t2, $t0 j Done Else: move $t2, $t1 Done:

Conditions with slt: a < b → slt t,a,b; bne t,$zero (true). a ≥ b → same slt, beq t,$zero. a > b → slt t,b,a. a ≤ b → slt t,b,a then beq t,$zero.

C. Loops

# while (i < n) { sum += i; i++; } $t0=i, $t1=n, $s0=sum Loop: slt $t2, $t0, $t1 # test at the top beq $t2, $zero, End # exit when !(i < n) i.e. i >= n add $s0, $s0, $t0 addi $t0, $t0, 1 j Loop End: # for (i = 0; i < 10; i++) sum += i; li $t0, 0 # init Loop: slti $t2, $t0, 10 # condition beq $t2, $zero, End add $s0, $s0, $t0 # body addi $t0, $t0, 1 # increment j Loop End:

The lecture slide writes the while-loop exit as blt $t1, $t0, End (exit when n < i). That runs one extra iteration when i == n. The correct exit test is i ≥ n: bge $t0, $t1, End, or the slt/beq pair above.

D. Calling convention

  • Arguments in $a0–$a3 (more go on the stack); results in $v0 (and $v1).
  • jal Label: $ra ← PC + 4, then jump. jr $ra: jump back to the instruction after the jal.
  • Caller-saved $t0–$t9: the callee may destroy them; the caller saves them if needed after the call. Callee-saved $s0–$s7, $sp, $ra (if it calls others): the callee must restore them.
  • The stack grows down: push = addi $sp,$sp,−N then sw; pop = lw then addi $sp,$sp,+N. Every −N must be matched.

E. Leaf vs non-leaf functions

Fetch–Decode–Execute & the Single-Cycle MIPS Datapath

Lab 11 fetch-decode-execute slideStudy-pack syllabus L16 (1 Oct)Added: full datapath, control table, critical-path numericals (Patterson &amp; Hennessy ch. 4)
1

Intuition first

We now build the CPU that runs the instructions from Topics 11–12, out of parts we already know: a register (PC), memories, the register file, adders, the ALU and MUXes. “Single-cycle” means every instruction does all its work in one long clock cycle.

Picture: a factory line where each instruction walks through the same rooms: fetch (read the recipe at address PC), decode (read two registers, look at the opcode), execute (ALU), memory (only loads/stores), write back (save the answer). MUXes are railway switches that the control unit (an FSM-like decoder of the opcode) sets differently for each instruction type. Since the clock must fit the slowest instruction (lw uses every room), every instruction pays for the longest one: that’s the problem pipelining solves next.

E. Critical path and clock period

In a single-cycle CPU, CPI = 1 but the clock period = delay of the slowest instruction’s path (the critical path).

Classic numbers: IMem 200 ps, register read 100, ALU 200, DMem 200, register write 100 (MUX/adders ignored)
  1. R-type: IMem + Reg read + ALU + Reg write = 200 + 100 + 200 + 100 = 600 ps
  2. lw: 200 + 100 + 200 + 200 + 100 = 800 ps (critical path)
  3. sw: 200 + 100 + 200 + 200 = 700 ps
  4. beq: 200 + 100 + 200 = 500 ps
  5. j: 200 ps (fetch only)
  6. Clock period = 800 ps → f = 1.25 GHz
Is a variable-length clock worth it? Mix: 25% lw, 10% sw, 45% R, 15% beq, 5% j
  1. average = 0.25·800 + 0.10·700 + 0.45·600 + 0.15·500 + 0.05·200
  2. = 200 + 70 + 270 + 75 + 10 = 625 ps
  3. single-cycle is 800 / 625 = 1.28× slower than an ideal per-instruction clock
  4. Real clocks cannot vary per instruction → this waste motivates multicycle and pipelined designs

Introduction to Pipelining: the 5-Stage MIPS Pipeline

Intuition first

The single-cycle CPU wastes time: the clock must fit lw (800 ps) even for a 500 ps beq, and while the ALU works, the instruction memory sits idle. Pipelining overlaps instructions: as soon as instruction 1 leaves the fetch stage, instruction 2 enters it.

Laundry analogy (Patterson & Hennessy): four loads, each needs Wash, Dry, Fold, Put-away, 30 min each. Sequential: 4 × 4 × 30 min = 8 h. Pipelined: start the next wash as soon as the washer is free → 7 slots × 30 min = 3.5 h. Each load still takes 2 h (latency unchanged), but a load finishes every 30 min (throughput 4× for many loads). The slowest stage sets the pace.

Pipeline Hazards: Data Hazards & Forwarding

Not in your folder: taught from Patterson &amp; Hennessy ch. 4.7–4.8 + GATE PYQs
1

Intuition first

An assembly line jams when a worker needs a part that the previous worker hasn’t finished. In add $s0,… followed by sub …,$s0,…, the sub wants $s0 in its EX stage (cycle 4) but add only writes it to the register file in WB (cycle 5).

Forwarding idea: the value actually exists at the end of add’s EX stage (cycle 3), sitting in the EX/MEM pipeline register. Instead of waiting for it to be “filed” in the register file, run a wire straight from there to the ALU input (a bypass). Like handing a colleague the page straight off the printer rather than waiting for it to be archived. Loads are the exception: their data only exists after MEM, which is one cycle too late, so one bubble is unavoidable.

A bubble is a nop: control signals in ID/EX are zeroed, PC and IF/ID are not updated.

F. Compiler scheduling

a = b + e; c = b + f; (P&H)

  2. 7 instructions: 5 + 7 − 1 = 11 cycles + 2 stalls = 13 cycles
  3. Reorder: move lw $t4,8($t0) up to third place → lw, lw, lw, add, sw, add, sw
  4. now each add is ≥ 2 instructions after its load → no stalls → 11 cycles

G. Stall counting recipe

  1. Write the pipeline diagram row by row.
  2. For each source register, find the producer and when its value is available (end of EX for ALU ops, end of MEM for loads) and when it’s needed (start of EX; start of ID if no forwarding, read in 2nd half of the producer’s WB).
  3. Insert bubbles until available ≤ needed; later instructions slide right too.
  4. Total cycles = last WB cycle.
